vii. 3

Write the intent code needed to open a specific location on a map using a geo: URI (uniform link).

Show solution

A geo: URI opens a location in a maps app. It is an implicit Intent with ACTION_VIEW.

Uri uri = Uri.parse("geo:30.1978,71.4697?q=Multan");

Intent intent = new Intent(Intent.ACTION_VIEW, uri);

try {
    startActivity(intent);
} catch (ActivityNotFoundException e) {
    Toast.makeText(this, "No maps app found", Toast.LENGTH_SHORT).show();
}

30.1978,71.4697 are the latitude and longitude, and ?q=Multan adds a label for the marker.

Topic: Displaying Maps


viii. 3

Explain what happens to an Activity during a configuration change such as screen rotation and how a ViewModel helps preserve data through it.

Show solution

During a configuration change (such as rotation) Android destroys the Activity (onPause(), onStop(), onDestroy()) and creates a new one (onCreate()), loading the layout for the new orientation. Data kept in the old Activity is lost unless it is saved.

How ViewModel helps: a ViewModel stores UI data outside the Activity, and it survives the recreation. The new Activity gets the same ViewModel and shows the old data again.

public class StudentViewModel extends ViewModel {
    private String studentName = "";

    public void setStudentName(String name) { studentName = name; }
    public String getStudentName() { return studentName; }
}

// In the Activity
StudentViewModel model =
    new ViewModelProvider(this).get(StudentViewModel.class);

model.setStudentName("Muhammad");
String name = model.getStudentName();

Topic: Managing Changes to Screen Orientation

Question 4 10 marks

Write and explain the code required to perform an HTTP GET request from an Android app and process the response of a background thread. Explain why this operation cannot be performed directly on the main thread.

Show solution

Why not on the main thread? The main (UI) thread draws the screen and handles touches. A network call can take seconds, so running it there would freeze the app and can cause an ANR (Application Not Responding). Android also blocks it and throws NetworkOnMainThreadException. So the request runs on a background thread and the result is posted back to the main thread.

ExecutorService executor = Executors.newSingleThreadExecutor();
Handler handler = new Handler(Looper.getMainLooper());

executor.execute(() -> {
    String response;
    try {
        URL url = new URL("https://jsonplaceholder.typicode.com/users/1");
        HttpURLConnection conn = (HttpURLConnection) url.openConnection();
        conn.setRequestMethod("GET");
        conn.setConnectTimeout(10000);
        conn.setReadTimeout(10000);

        BufferedReader reader = new BufferedReader(
            new InputStreamReader(conn.getInputStream()));
        StringBuilder sb = new StringBuilder();
        String line;
        while ((line = reader.readLine()) != null) {
            sb.append(line);
        }
        reader.close();
        response = sb.toString();

    } catch (Exception e) {
        response = "Error: " + e.getMessage();
    }

    String finalResponse = response;

    // Process the response back on the main thread
    handler.post(() -> txtResult.setText(finalResponse));
});

Add <uses-permission android:name="android.permission.INTERNET" /> to the manifest. The request is sent with HttpURLConnection, the response is read line by line, and handler.post() updates the TextView safely.
