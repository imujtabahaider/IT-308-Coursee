Data and storage

User Preferences in Android

Saving and reading small settings with SharedPreferences

15.1 Introduction

Every Android application needs to remember some information about its users. For example, imagine you use a mobile application and make these settings:

  • Select Dark Mode
  • Choose English as the language
  • Turn notifications ON
  • Set the font size to Large
  • Save your login preference

Now, suppose you close the application and open it again. You would expect the application to remember your previous settings instead of asking you to select everything again. Android provides a feature called SharedPreferences to store small amounts of information, such as user settings and preferences.

15.2 Definition of User Preferences

User Preferences are settings or choices selected by users that an application stores so that it can remember them for future use.

In simple words, user preferences allow an application to remember how a user wants the application to work.

Example: suppose you open a student application and select Dark Mode. The application saves this choice. When you open the application again, it remembers your selection and displays Dark Mode.

15.3 Why Are User Preferences Important?

User preferences are important because they make applications more convenient and personalized.

15.3.1 Remember User Settings

An application can remember the settings selected by the user. For example, if a user selects Dark Mode, the application can remember that choice.

15.3.2 Improve User Experience

Users do not need to configure the application every time they open it. For example, a user can select a preferred language once, and the application can remember it.

15.3.3 Personalization

Applications can provide different experiences based on user preferences:

  • Light Mode or Dark Mode
  • English or Urdu
  • Small or large text
  • Notifications ON or OFF
15.3.4 Save Time

User preferences reduce repeated work. For example, a student application can remember the selected semester instead of asking the student to select it every time.

15.3.5 Maintain Application Settings

When the application closes and opens again, saved preferences can remain available. This is useful because users expect their settings to remain the same.

15.4 What Is SharedPreferences?

SharedPreferences is an Android storage mechanism used to save small amounts of data in key-value pairs.

Let's understand the term key-value. A key-value pair contains two parts:

  • Key: the name used to identify stored information.
  • Value: the actual information stored under that name.
KeyValue
usernameMuhammad
dark_modetrue
languageEnglish
notificationsfalse
font_sizeLarge

Here, dark_mode is the key and true is its value; language is the key and English is its value. The application uses the key to find the corresponding value.

How does it work? Suppose a user selects Dark Mode.

  1. The user turns on the Dark Mode switch.
  2. The application receives the selection.
  3. The application saves dark_mode = true.
  4. The user closes the application.
  5. The user opens it again.
  6. The application reads the saved value.
  7. The application enables Dark Mode.
User selects Dark Mode

          ↓

          ↓

15.5 Types of Data Stored in SharedPreferences

SharedPreferences is designed for small amounts of simple data. It supports these main data types:

Data typePurposeExample
StringStores text"Muhammad"
IntegerStores whole numbers25
FloatStores decimal numbers5.5
LongStores large whole numbers123456789
BooleanStores true or falsetrue
String SetStores a set of stringsSubjects list

For example, a username can be stored as a String, age as an Integer, Dark Mode as a Boolean and font size as an Integer.

Important: SharedPreferences is not suitable for storing large files, images, videos, or complex database records.

15.6 How to Use SharedPreferences in Java

Let's understand how to save and retrieve user preferences. There are three basic operations: create or access SharedPreferences, save data, and retrieve data.

Step 1: Create or Access SharedPreferences
SharedPreferences preferences =
    getSharedPreferences(
        "MyPreferences",
        MODE_PRIVATE
    );

Explanation:

  • SharedPreferences is the Android class used to access stored preferences.
  • getSharedPreferences() opens a preferences file.
  • "MyPreferences" is the name of the file.
  • MODE_PRIVATE means the preferences are private to the application.

The application can use this preferences file to save different settings.

Step 2: Save Data

To save information, Android provides SharedPreferences.Editor.

SharedPreferences.Editor editor =
    preferences.edit();

editor.putString("username", "Muhammad");

editor.putBoolean("dark_mode", true);

editor.putInt("age", 22);

editor.apply();

Understand each method:

MethodPurpose
edit()Opens an editor to make changes
putString()Saves text
putBoolean()Saves true or false
putInt()Saves a whole number
apply()Saves changes asynchronously

Here, the application saves three values: Username = Muhammad, Dark Mode = true and Age = 22.

What is the purpose of apply()? After adding or changing values, we must save those changes. apply() saves the changes asynchronously, meaning it does not make the application wait for the disk write to finish. Another method is commit(), which saves synchronously and returns a Boolean indicating success or failure. For normal preference saving, apply() is generally preferred.

Step 3: Retrieve Saved Data

When the application opens again, it can retrieve the saved information.

String username =
    preferences.getString("username", "Guest");

boolean darkMode =
    preferences.getBoolean("dark_mode", false);

int age =
    preferences.getInt("age", 0);

Explanation: getString() retrieves a text value, getBoolean() retrieves a true or false value, and getInt() retrieves an integer value. The second argument is the default value. For example:

preferences.getString("username", "Guest");

This means: if the username exists, return the saved username; if it does not exist, return "Guest".

15.7 Updating and Removing Preferences

SharedPreferences also allows applications to update and remove stored values.

15.7.1 Updating Data

Suppose the username changes from Muhammad to Ali.

SharedPreferences.Editor editor =
    preferences.edit();

editor.putString("username", "Ali");

editor.apply();

The old value is replaced with the new value under the same key.

15.7.2 Removing One Preference

If you want to remove only the username:

SharedPreferences.Editor editor =
    preferences.edit();

editor.remove("username");

editor.apply();

This removes the value associated with the username key.

15.7.3 Clearing All Preferences

If you want to remove all stored preferences from that file:

SharedPreferences.Editor editor =
    preferences.edit();

editor.clear();

editor.apply();

This clears all entries in the selected preferences file.

15.8 Practical Example: Remembering Dark Mode

Let's create a simple application that remembers whether Dark Mode is enabled.

Step 1: XML Layout

Create activity_main.xml.

<?xml version="1.0" encoding="utf-8"?>

<LinearLayout
    xmlns:android="http://schemas.android.com/apk/res/android"
    android:id="@+id/mainLayout"
    android:layout_width="match_parent"
    android:layout_height="match_parent"
    android:orientation="vertical"
    android:gravity="center"
    android:padding="20dp">

    <TextView
        android:layout_width="wrap_content"
        android:layout_height="wrap_content"
        android:text="Application Settings"
        android:textSize="24sp" />

    <Switch
        android:id="@+id/darkModeSwitch"
        android:layout_width="wrap_content"
        android:layout_height="wrap_content"
        android:text="Dark Mode" />

</LinearLayout>

This creates a main layout, a heading and a Dark Mode switch.

Step 2: Java Code

Create MainActivity.java.

package com.example.studentapp;

import android.os.Bundle;
import android.content.SharedPreferences;
import android.graphics.Color;
import android.widget.Switch;
import android.widget.LinearLayout;

import androidx.appcompat.app.AppCompatActivity;

public class MainActivity extends AppCompatActivity {

    Switch darkModeSwitch;
    LinearLayout mainLayout;

    SharedPreferences preferences;

    @Override
    protected void onCreate(Bundle savedInstanceState) {

        super.onCreate(savedInstanceState);

        setContentView(R.layout.activity_main);

        darkModeSwitch = findViewById(R.id.darkModeSwitch);

        mainLayout = findViewById(R.id.mainLayout);

        preferences = getSharedPreferences(
            "MyPreferences",
            MODE_PRIVATE
        );

        boolean isDarkMode =
            preferences.getBoolean("dark_mode", false);

        darkModeSwitch.setChecked(isDarkMode);

        updateTheme(isDarkMode);

        darkModeSwitch.setOnCheckedChangeListener(
            (buttonView, isChecked) -> {

                SharedPreferences.Editor editor =
                    preferences.edit();

                editor.putBoolean("dark_mode", isChecked);

                editor.apply();

                updateTheme(isChecked);
            }
        );
    }

    private void updateTheme(boolean darkMode) {

        if (darkMode) {

            mainLayout.setBackgroundColor(Color.BLACK);

        } else {

            mainLayout.setBackgroundColor(Color.WHITE);
        }
    }
}
Step 3: Understand the Complete Working

When the application opens:

  1. Android loads the XML layout.
  2. Java connects to the Dark Mode switch.
  3. The application opens the MyPreferences file.
  4. It retrieves the saved dark_mode value.
  5. If the value is true, the switch is enabled and the background becomes black.
  6. If the value is false, the switch is disabled and the background becomes white.

When the user changes the switch:

  1. Android detects the switch change.
  2. The event listener runs.
  3. The new value is saved using SharedPreferences.
  4. The background changes.
  5. The setting remains saved when the application is closed.
Important concept: this example demonstrates the basic idea of saving and retrieving user preferences. A production application should also manage its overall application theme, including text and other UI components, rather than changing only the background color.

15.9 SharedPreferences vs Database

Both SharedPreferences and databases store information, but they are designed for different purposes.

SharedPreferencesDatabase
Stores small amounts of simple dataStores structured and larger amounts of data
Uses key-value pairsUses tables and records
Suitable for application settingsSuitable for student, employee, and product records
Simple to useProvides querying and relationships
Not designed for complex searchesSupports complex searches and queries
Example: a student application may use SharedPreferences to remember Dark Mode, and a database to store student names, registration numbers, marks, and attendance records.

15.10 Advantages and 15.11 Limitations of SharedPreferences

Advantages
  1. Easy to use: developers can save and retrieve data with simple methods.
  2. Persistent storage: saved values remain available after the application closes or the device restarts.
  3. Fast access: suitable for reading and writing small settings.
  4. Simple structure: data is organized using keys and values.
  5. No database required: developers do not need to create tables for simple preferences.
  6. Private storage: preferences are normally private to the application.
Limitations
  1. It is not designed for large amounts of data.
  2. It does not provide advanced database queries.
  3. It is not suitable for storing images, videos, or large files.
  4. It does not provide database-style relationships between records.
  5. Sensitive information should not be stored as ordinary unencrypted preferences.
For modern Android development, DataStore is often recommended instead of SharedPreferences for new preference-storage implementations. DataStore provides asynchronous data operations and is available in Preferences and Proto forms.

Persisting Data in Android

Files, SQLite, Room, DataStore and cloud storage

16.1 Introduction

Every Android application works with different types of information. For example, a Student Management System may contain:

  • Student names
  • Registration numbers
  • Examination marks
  • Attendance records
  • Profile pictures
  • Login information
  • Assignment files

Now imagine that a student enters their name and marks into an application. The application closes unexpectedly. When the student opens the application again, the information should still be available. How can Android applications remember information even after they are closed? The answer is Data Persistence. Data persistence is an important part of Android development because applications often need to store information for future use.

16.2 Definition of Data Persistence

Data Persistence is the process of storing information in a way that allows it to remain available even after an application is closed or the device is restarted.

In simple words, data persistence means saving information so that it is not lost when an application stops running.

Example: suppose you use a Notes application.
  1. You write a note.
  2. You press the Save button.
  3. The application stores the note.
  4. You close the application.
  5. You open it again.
  6. Your note is still available.
This is called data persistence.

16.3 Why Is Data Persistence Important?

Data persistence is necessary because most applications need to remember information.

16.3.1 Prevents Data Loss

If information is stored properly, it remains available even after the application closes. For example, a student does not lose saved examination marks when closing the application.

16.3.2 Stores Important Information

Applications can store important records:

  • Student details
  • Employee information
  • Customer records
  • Product information
  • Payment history
16.3.3 Supports Offline Applications

Some applications allow users to access saved information without an internet connection. For example, a Notes application can display previously saved notes even when the phone is offline.

16.3.4 Improves User Experience

Users do not need to enter the same information repeatedly. For example, a shopping application can save a user's cart information for later use.

16.3.5 Maintains Application History

Applications can store previous activities: search history, download history, previous transactions and recently opened documents.

16.4 Different Methods of Data Persistence in Android

Android provides several methods for storing information. Each method is designed for a different type of data. The main methods include:

  1. SharedPreferences
  2. DataStore
  3. Internal Storage
  4. External Storage
  5. SQLite Database
  6. Room Database
  7. Cloud Storage

Let's understand each method in detail.

16.5 SharedPreferences

SharedPreferences is used to store small amounts of information in key-value pairs. It is useful for saving simple application settings, for example the username, Dark Mode setting, language selection, notification preference and selected application theme.

How does SharedPreferences work? Suppose a user enables Dark Mode. The application saves dark_mode = true. When the application opens again, it reads the saved value and enables Dark Mode.

SharedPreferences preferences =
    getSharedPreferences("MySettings", MODE_PRIVATE);

SharedPreferences.Editor editor = preferences.edit();

editor.putBoolean("dark_mode", true);

editor.apply();

To retrieve the value:

boolean darkMode =
    preferences.getBoolean("dark_mode", false);
Important: SharedPreferences was covered in the previous topic. Here, remember that it is one of the methods used for data persistence.

16.6 DataStore

DataStore is a modern Android storage solution that can be used instead of SharedPreferences for storing small amounts of application data. It provides asynchronous data operations and uses Kotlin Coroutines and Flow in its common implementation. There are two main types:

16.6.1 Preferences DataStore

Stores information using key-value pairs, for example Dark Mode, language, notification settings and user preferences. It is conceptually similar to SharedPreferences but provides a more modern asynchronous approach.

16.6.2 Proto DataStore

Stores structured data using Protocol Buffers. For example, an application can store a structured user settings object containing username, language, theme and notification settings.

Remember: DataStore is a modern option for small settings and structured preference data. It is not intended to replace a relational database for large collections of records.

16.7 Internal Storage

Internal Storage is used to save files privately inside an application's dedicated storage area.

Each Android application normally has its own private internal storage directory. Other ordinary applications cannot directly access these private files. Examples include private text files, application configuration files, downloaded private documents and temporary application files.

How does Internal Storage work? Suppose a Notes application allows users to save notes. When a user saves a note:

  1. The application receives the text.
  2. It creates or opens a file in internal storage.
  3. It writes the note into the file.
  4. The file remains available after the application closes.
  5. The application reads the file when the user opens the note again.
Advantages of Internal Storage
  1. Private to the application by default.
  2. No general storage permission is required to access the application's own internal files.
  3. Useful for sensitive application-specific files.
  4. Files remain available after restarting the device.
Disadvantages of Internal Storage
  1. Storage space is limited.
  2. Files are normally removed when the application is uninstalled.
  3. Files are not automatically accessible to other applications.
  4. Large files may consume valuable application storage.

Java example: saving a file. Suppose we want to save a student's name in a text file.

String fileName = "student.txt";

String studentName = "Muhammad";

try (
    FileOutputStream fos =
        openFileOutput(fileName, MODE_PRIVATE)
) {

    fos.write(studentName.getBytes());

} catch (IOException e) {

    e.printStackTrace();
}

Explanation:

  • fileName defines the file's name.
  • studentName contains the information to save.
  • openFileOutput() opens a file in the application's internal storage.
  • MODE_PRIVATE creates or replaces the file privately.
  • write() writes the information into the file.
  • close() is handled automatically by the try-with-resources statement.

Java example: reading a file. Now suppose we want to retrieve the saved student name.

try (
    FileInputStream fis =
        openFileInput("student.txt")
) {

    ByteArrayOutputStream buffer =
        new ByteArrayOutputStream();

    byte[] data = new byte[1024];

    int length;

    while ((length = fis.read(data)) != -1) {

        buffer.write(data, 0, length);
    }

    String studentName =
        buffer.toString("UTF-8");

} catch (IOException e) {

    e.printStackTrace();
}

Explanation:

  • openFileInput() opens the saved file.
  • read() reads the file's content.
  • The loop continues until the end of the file.
  • buffer.toString() converts the saved bytes into text.
  • The final String contains the student's name.

This demonstrates how an application can save information and retrieve it later.

16.8 External Storage

External Storage is used for files that may need to be accessed outside an application's private internal storage area.

Examples include photos, videos, documents, music and downloaded files. External storage can include shared device storage and removable storage, such as an SD card on supported devices.

Important: modern Android uses scoped storage, which limits how applications access shared files. External storage does not automatically mean that every application can access every file.

Types of external storage access

16.8.1 App-Specific External Storage

Storage reserved for files belonging to a particular application. For example, a photo-editing application may save edited images in its own application-specific external directory. Other applications generally cannot access these files directly unless access is shared through an appropriate mechanism.

16.8.2 Shared Storage

Contains files that users may want to access through different applications: pictures, videos, music and documents. Android provides tools such as MediaStore for managing shared media and the Storage Access Framework for allowing users to select documents and files.

Advantages of External Storage
  1. Useful for large files.
  2. Supports user-accessible documents and media.
  3. Allows files to be shared with other applications through supported mechanisms.
  4. Can provide more available space than internal storage.
Disadvantages of External Storage
  1. Storage availability may change.
  2. Files may become unavailable if removable storage is removed.
  3. Shared files require appropriate access management.
  4. Developers must follow Android's storage restrictions.

Example: saving a file in app-specific external storage

File file = new File(
    getExternalFilesDir(null),
    "student.txt"
);

try (
    FileOutputStream fos =
        new FileOutputStream(file)
) {

    fos.write("Muhammad".getBytes());

} catch (IOException e) {

    e.printStackTrace();
}

Here:

  • getExternalFilesDir(null) gets the application's external files directory.
  • File represents the file to create.
  • FileOutputStream writes information into the file.
This example saves a file in app-specific external storage. It does not save a document into the public Downloads folder.

16.9 SQLite Database

SQLite is a lightweight relational database management system included in Android. It is used to store structured information in tables.

Unlike SharedPreferences, which stores key-value pairs, SQLite organizes data using rows and columns. For example, a student management application may store student records in a table:

IDNameSemesterMarks
1Ali485
2Muhammad490
3Ahmed378

Here, each row represents one student, each column represents a particular type of information, and the table stores multiple student records.

Why is SQLite used? SQLite is useful when an application needs to store many records, search for specific information, update existing records, delete records, organize information into tables and work with data offline.

Important SQL operations. SQLite uses SQL (Structured Query Language) to manage information. The four basic operations are:

INSERT – used to add new records.

INSERT INTO Students
(name, semester, marks)
VALUES
('Muhammad', 4, 90);

SELECT – used to retrieve records. This retrieves all records from the Students table.

SELECT * FROM Students;

UPDATE – used to modify existing records. This changes the marks of the student whose ID is 1.

UPDATE Students
SET marks = 95
WHERE id = 1;

DELETE – used to remove records. This removes the student record whose ID is 1.

DELETE FROM Students
WHERE id = 1;
Advantages of SQLite
  1. Built into Android.
  2. Does not require a separate database server.
  3. Supports SQL queries.
  4. Stores structured information.
  5. Works offline.
  6. Suitable for local application databases.
Disadvantages of SQLite
  1. Not designed for direct synchronization between multiple devices.
  2. Complex database operations require proper SQL knowledge.
  3. It is not a complete replacement for a centralized server database in large online systems.

16.10 Room Database

Room is an Android persistence library that provides an easier and safer way to work with SQLite databases. It is part of Android Jetpack.

Instead of writing all database operations manually, developers can use Room components to manage database records. Room has three main components.

16.10.1 Entity

An Entity represents a database table. For example, a Student Entity defines the structure of a Students table.

@Entity
public class Student {

    @PrimaryKey(autoGenerate = true)
    public int id;

    public String name;

    public int marks;
}

Here:

  • @Entity identifies the class as a database table.
  • @PrimaryKey identifies the primary key.
  • autoGenerate = true allows IDs to be generated automatically.
  • name and marks are table columns.
16.10.2 DAO (Data Access Object)

DAO defines methods for performing database operations. For example:

@Dao
public interface StudentDao {

    @Insert
    void insertStudent(Student student);

    @Query("SELECT * FROM Student")
    List<Student> getAllStudents();

    @Delete
    void deleteStudent(Student student);
}

Here, @Insert inserts a student, @Query retrieves student records using SQL, and @Delete deletes a student.

16.10.3 Database Class

The Database class connects the entities and DAOs and provides access to the database.

@Database(
    entities = {Student.class},
    version = 1
)
public abstract class AppDatabase extends RoomDatabase {

    public abstract StudentDao studentDao();
}

This defines a Room database containing the Student entity and providing access to StudentDao.

How Room works

Application
Requests database operations
        ↓
DAO
Defines insert, update, delete and query methods
        ↓
Room Database
Manages database access
        ↓
SQLite Database
Stores structured records
Remember: Entity defines the table. DAO defines database operations. The Database class provides database access. SQLite stores the actual records. Room is generally preferred over directly using SQLite APIs in modern Android applications.

16.11 Cloud Storage

Cloud Storage means storing application information on remote servers accessed through the internet.

Instead of keeping all information only on the mobile device, an application can send data to an online server. Examples of cloud-based services include Firebase, Amazon Web Services (AWS), Microsoft Azure and Google Cloud.

How does Cloud Storage work? Imagine a student uses an application on two different mobile phones. If student information is stored only in the first phone's internal storage, the second phone will not automatically have that information. But if the information is stored on a cloud server:

  1. The student enters information into the application.
  2. The application sends the information to the server through an API.
  3. The server stores the information.
  4. The student opens the application on another phone.
  5. The application requests the information from the server.
  6. The server sends the saved information back.

This allows data to be accessed from different devices, subject to authentication and permissions.

Advantages of Cloud Storage
  1. Data can be accessed from multiple devices.
  2. Supports online synchronization.
  3. Can provide large storage capacity.
  4. Makes centralized data management possible.
  5. Supports online collaboration.
Disadvantages of Cloud Storage
  1. Usually requires an internet connection.
  2. Server usage may involve costs.
  3. Security and privacy must be managed carefully.
  4. Server failures can affect application availability.
  5. Data synchronization can become complicated.

16.15 Important Factors When Choosing a Storage Method

Developers should consider the following points before selecting a storage method.

16.15.1 Type of Data

First, identify what needs to be stored. Settings → DataStore. Text files → Internal Storage. Student records → Room Database. Images → File or media storage.

16.15.2 Amount of Data

Small settings do not need a full database. However, thousands of student records are better managed using a database.

16.15.3 Security

Sensitive information should be protected. For example, passwords and authentication tokens should not be stored as ordinary unencrypted text in SharedPreferences or files. Use appropriate secure storage and authentication practices.

16.15.4 Internet Availability

If the application must work offline, local storage is important. If users need to access the same information from multiple devices, cloud storage may be required.

16.15.5 Performance

The storage method should match the application's requirements. For example, a database is more suitable for searching thousands of student records than manually reading many separate text files.

Sharing Data in Android

Intents, FileProvider, ContentProvider and the Sharesheet

17.1 Introduction

Android applications often need to share information with other applications. For example, imagine you are using a student application and want to:

  • Share your examination result through WhatsApp
  • Send a document through Gmail
  • Share a picture with a friend
  • Send a website link through a messaging application
  • Open a PDF file using another application

Android provides different methods that allow applications to exchange information. This process is called Data Sharing. Android mainly uses a mechanism called Intents to communicate between application components and request actions from other applications.

17.2 Definition of Data Sharing

Data Sharing in Android is the process of transferring or making information available between different applications or components of an application.

In simple words, data sharing allows one application to send information to another application.

Example: suppose you have a PDF file in a student application.
  1. You open the PDF.
  2. You tap the Share button.
  3. Android displays a list of available applications.
  4. You select WhatsApp.
  5. The PDF is shared through WhatsApp.
This is an example of data sharing between Android applications.

17.3 Why Is Data Sharing Important?

Data sharing makes Android applications more useful because users can work with information across different applications.

17.3.1 Easy Communication

Users can send information through messaging and email applications. For example, a student can share examination results with a teacher through WhatsApp.

17.3.2 Sharing Files

Applications can share different types of files: PDF documents, images, videos, audio files and text files.

17.3.3 Better User Experience

Users do not need to manually copy and paste information into another application. They can use the Android sharing interface to select the application they want.

17.3.4 Application Integration

Different applications can work together. A Gallery application can share pictures with WhatsApp, a browser can share website links through Gmail, and a file manager can open documents using a PDF reader.

17.3.5 Reuse of Existing Applications

Developers do not need to create every feature themselves. For example, instead of building an email system inside a student application, they can send information to an existing email application.

17.4 What Is an Intent in Android?

An Intent is a messaging object used to request an action from another Android application component.

In simple words, an Intent tells Android what action should be performed. For example: open another Activity, open a web page, share text, send an email, open a picture or share a document. An Intent can also carry information from one component to another.

Example: suppose a student application wants to share the message "My examination result is available." The application creates an Intent containing the action (share information), the data (the examination result message) and the type (plain text). Android then provides suitable applications that can receive the information.

17.5 Types of Intents

Android mainly has two types of Intents: Explicit Intent and Implicit Intent. Let's understand both.

17.5.1 Explicit Intent

An Explicit Intent specifies exactly which application component should receive the request. It is commonly used when moving from one Activity to another Activity inside the same application.

Example: a student application contains two screens, MainActivity and ProfileActivity. When the user clicks the Profile button, the application should open ProfileActivity.

Intent intent = new Intent(
    MainActivity.this,
    ProfileActivity.class
);

startActivity(intent);

Explanation:

  • Intent creates an Intent object.
  • MainActivity.this identifies the current Activity.
  • ProfileActivity.class identifies the Activity to open.
  • startActivity() starts the selected Activity.

The destination is clearly specified. Therefore, this is an Explicit Intent.

Real-life example: opening the Settings screen from the Home screen of the same application.
17.5.2 Implicit Intent

An Implicit Intent describes an action that should be performed without specifying one particular application component. Android finds applications that can perform the requested action.

Example: a user wants to open a website. The application does not need to specify a particular browser. Android can display or select an application capable of opening the website.

Intent intent = new Intent(
    Intent.ACTION_VIEW,
    Uri.parse("https://www.google.com")
);

startActivity(intent);

Explanation:

  • ACTION_VIEW tells Android that the application wants to display something.
  • Uri.parse() converts the website address into a URI.
  • startActivity() sends the request to Android.
  • Android finds an application capable of opening the website.
Real-life example: opening a website link using Chrome or another installed browser.

17.6 Sharing Data Using Intent

Android provides a standard action called ACTION_SEND for sharing information. It allows an application to send data to another application that supports the requested data type. For example, an application can share text, images, documents and other supported files.

17.6.1 Sharing Text

Suppose you want to share a message from your student application.

Intent intent = new Intent(Intent.ACTION_SEND);

intent.setType("text/plain");

intent.putExtra(
    Intent.EXTRA_TEXT,
    "My examination result is available."
);

startActivity(
    Intent.createChooser(intent, "Share using")
);

Explanation: let's understand each line.

Line 1 – creates an Intent that requests Android to send information.

Intent intent = new Intent(Intent.ACTION_SEND);

Line 2 – defines the data type as plain text.

intent.setType("text/plain");

Line 3 – adds the message that should be shared.

intent.putExtra(
    Intent.EXTRA_TEXT,
    "My examination result is available."
);

Line 4 – creates a sharing interface that allows the user to select an application.

Intent.createChooser(intent, "Share using")

Line 5 – displays the sharing interface.

startActivity(...)
17.6.2 What Is Intent.createChooser()?

Intent.createChooser() creates a system-provided selection interface. It allows users to select an application for performing the requested action. For example, when sharing text, Android may show suitable applications such as Gmail, WhatsApp, Messages and other compatible applications.

Why is it useful? Because the developer does not need to create a separate sharing menu or manually list every installed application. Android handles the selection interface.

17.7 Sharing Images

Android applications can also share images with other applications. For example, a photo-editing application may allow users to share edited pictures through messaging applications. To share an image, Android commonly uses:

  • ACTION_SEND
  • An image MIME type such as image/jpeg or image/png
  • EXTRA_STREAM to provide the image URI
  • A content URI that the receiving application can access

Example: sharing an image

Intent intent = new Intent(Intent.ACTION_SEND);

intent.setType("image/jpeg");

intent.putExtra(
    Intent.EXTRA_STREAM,
    imageUri
);

intent.addFlags(
    Intent.FLAG_GRANT_READ_URI_PERMISSION
);

startActivity(
    Intent.createChooser(intent, "Share Image")
);
CodePurpose
ACTION_SENDRequests data sharing
setType("image/jpeg")Identifies the data as a JPEG image
EXTRA_STREAMSupplies the image URI
FLAG_GRANT_READ_URI_PERMISSIONGrants temporary read access
createChooser()Displays compatible sharing applications
Important: imageUri must be a valid content URI that the receiving application can access. For files in an application's private storage, developers commonly use Android's FileProvider rather than sharing a direct file path.

17.8 What Is a URI?

URI stands for Uniform Resource Identifier. A URI is an identifier used to identify a resource.

In Android, URIs are commonly used to identify files, images, documents, and other data. For example:

content://com.example.app.provider/images/photo.jpg

This is an example of a content URI. A content URI identifies a resource that can be accessed through a ContentProvider.

Why are URIs important? Suppose an application wants to share an image with another application. Instead of giving the other application a private file path, Android can provide a content URI. The receiving application can use that URI to access the shared image when permission is granted.

Types of URI schemes

SchemeExamplePurpose
httpshttps://example.comWebsite resource

filefile://...File URI, generally not suitable for sharing files between modern Android apps

For modern Android file sharing, use content URIs and appropriate permissions.

17.9 What Is FileProvider?

FileProvider is an Android component that securely allows an application to share its files with other applications using content URIs.

Imagine that your application stores a PDF file in its private internal storage. Another application cannot normally access that private file directly. FileProvider provides a controlled way to share access to it.

How FileProvider works

  1. Your application stores a file.
  2. FileProvider creates a content URI for that file.
  3. Your application places that URI inside an Intent.
  4. Your application grants temporary read permission.
  5. The receiving application reads the file through the URI.
Application A
Contains a private PDF file
        ↓
FileProvider
Creates a content URI
        ↓
Android Intent
Shares the URI with temporary read permission
        ↓
Application B
Reads the shared PDF file

Example: sharing a PDF file using FileProvider

Step 1: Add FileProvider to AndroidManifest.xml

Inside the application element:

<provider
    android:name="androidx.core.content.FileProvider"
    android:authorities="${applicationId}.provider"
    android:exported="false"
    android:grantUriPermissions="true">

    <meta-data
        android:name="android.support.FILE_PROVIDER_PATHS"
        android:resource="@xml/file_paths" />

</provider>

Explanation:

  • FileProvider provides secure file-sharing access.
  • authorities defines the provider's unique authority.
  • exported="false" prevents other applications from directly accessing the provider.
  • grantUriPermissions="true" allows temporary URI permissions.
  • file_paths defines which directories can be shared.
Step 2: Create file_paths.xml

Create a folder named xml inside the res folder, then create file_paths.xml.

<?xml version="1.0" encoding="utf-8"?>

<paths xmlns:android="http://schemas.android.com/apk/res/android">

    <files-path
        name="shared_files"
        path="." />

</paths>

This configuration allows FileProvider to generate URIs for files stored in the application's internal files directory.

Step 3: Create a Content URI
File file = new File(
    getFilesDir(),
    "result.pdf"
);

Uri uri = FileProvider.getUriForFile(
    this,
    getPackageName() + ".provider",
    file
);

Here:

  • getFilesDir() accesses the internal files directory.
  • File represents the PDF file.
  • getUriForFile() creates a content URI.
  • The authority must match the authority configured in the manifest.
Step 4: Share the PDF
Intent intent = new Intent(Intent.ACTION_SEND);

intent.setType("application/pdf");

intent.putExtra(Intent.EXTRA_STREAM, uri);

intent.addFlags(
    Intent.FLAG_GRANT_READ_URI_PERMISSION
);

startActivity(
    Intent.createChooser(intent, "Share PDF")
);

Now Android can display applications that support receiving PDF files.

Note: the PDF file must already exist at the specified location. The FileProvider path configuration must also include the file's directory.

17.10 Sharing Data Using ACTION_SENDTO

Android also provides ACTION_SENDTO, which is commonly used when directing a message to a particular type of communication application. For example, you can open an email application to compose an email.

Intent intent = new Intent(
    Intent.ACTION_SENDTO
);

intent.setData(
    Uri.parse("mailto:student@example.com")
);

intent.putExtra(
    Intent.EXTRA_SUBJECT,
    "Examination Result"
);

intent.putExtra(
    Intent.EXTRA_TEXT,
    "Please find my examination result."
);

startActivity(intent);

Explanation:

  • ACTION_SENDTO requests an application that handles the specified communication address.
  • mailto: identifies an email destination.
  • EXTRA_SUBJECT provides the email subject.
  • EXTRA_TEXT provides the email body.

This is useful when you want to open an email application rather than show a general sharing interface.

17.11 What Is a ContentProvider?

A ContentProvider is an Android component that manages and provides access to application data.

It allows one application to expose selected information to other applications in a controlled way. For example, the Contacts Provider provides access to contact information, the Media Provider manages media information, and a custom application can create its own ContentProvider.

Why is ContentProvider used? Suppose a contacts application stores names and phone numbers. Another application may need to access those contacts. Instead of directly accessing the contacts application's database, it can request information through the Contacts ContentProvider, subject to the required permissions.

Main operations of ContentProvider

OperationPurpose
QueryRetrieve data
InsertAdd new data
UpdateModify existing data
DeleteRemove data

How ContentProvider works

  1. An application requests information.
  2. The request contains a content URI.
  3. Android directs the request to the appropriate ContentProvider.
  4. The provider checks access permissions.
  5. The provider performs the requested operation.
  6. The result is returned to the requesting application.
Remember: a ContentProvider is useful for structured data sharing, while FileProvider is a specialized implementation used to share files through content URIs.

17.15 Security in Data Sharing

Data sharing must be handled carefully because applications may contain private information. Developers should follow security practices.

17.15.1 Grant Only Required Permissions

When sharing a file, give the receiving application only the permissions it needs. For example, if the other application only needs to read a PDF, grant read permission instead of unnecessary write access.

17.15.2 Use Content URIs

Do not expose private file paths directly. Use FileProvider to create secure content URIs for sharing application files.

17.15.3 Validate Shared Data

Applications should check incoming data before using it. For example, an application receiving a file should verify that the file type and content are acceptable.

17.15.4 Avoid Sharing Sensitive Information

Do not share passwords, authentication tokens, or confidential information unnecessarily.

17.15.5 Use Appropriate Permissions

Some data sources, such as contacts and media, require specific access permissions. Applications should request only the permissions they actually need.

17.17 Advantages and 17.18 Disadvantages of Data Sharing

Advantages
  1. Easy communication: users can send information through other applications.
  2. Application integration: different applications can work together.
  3. Saves development time: developers can reuse existing applications.
  4. Better user experience: users can share information through a standard interface.
  5. Supports different data types: text, images, videos and documents can be shared.
  6. Controlled access: content URIs and permissions help protect private files.
Disadvantages and challenges
  1. The receiving application may not support the shared data type.
  2. Sharing private information can create security risks.
  3. Different applications may handle the same data differently.
  4. File-sharing permissions must be configured correctly.
  5. Some sharing operations depend on applications being installed on the device.
