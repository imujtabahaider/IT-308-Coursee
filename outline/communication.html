Calling Built-in Applications Using Intents

Understanding how Android applications use Intents to open and communicate with existing applications.

1.1 Introduction

Android provides many built-in applications that help users perform everyday tasks.

Examples include:

  • Phone application for making calls.
  • Messaging application for sending SMS.
  • Camera application for taking pictures.
  • Browser application for opening websites.
  • Email application for sending emails.
  • Maps application for finding locations.
  • Contacts application for viewing contacts.
Practical Example

Suppose you are developing a Student Management Application.

You want to add a button called Call Teacher.

When the student taps this button, you want Android to open the phone application with the teacher's number already entered.

Do you need to develop your own phone application?

No. Android allows your application to request another installed application to perform an action.

This is done using Intents.

1.2 Definition of Calling Built-in Applications Using Intents

Definition: Calling Built-in Applications Using Intents is the process of requesting Android to open an existing application and perform a specific action on behalf of another application.

In simple words, your application can use an Intent to open another application instead of developing that functionality itself.

For example:

  • Open the Phone application to dial a number.
  • Open the Camera application to take a picture.
  • Open a browser to visit a website.
  • Open an email application to compose an email.
  • Open Maps to display a location.

1.3 What Are Built-in Applications?

Definition: Built-in applications are applications provided by the Android device manufacturer, Android ecosystem, or installed by the user.

Examples include:

Application Purpose
PhoneMaking telephone calls
MessagesSending SMS messages
CameraTaking pictures
BrowserOpening websites
EmailSending and receiving emails
MapsFinding locations
ContactsManaging contact information
SettingsManaging device settings

The exact applications available depend on the device and the applications installed by the user.

Important:

Android does not require every device to have the same default application. For example, a device may have different browser or email applications installed.

1.4 How Do Intents Call Built-in Applications?

An Intent tells Android what action your application wants to perform.

Android examines the Intent and looks for an application capable of handling that action.

Basic Working Process
Step 1: Your Android Application

The user interacts with your application.

Step 2: User Taps a Button

The user requests an action, such as opening a website.

Step 3: Intent Is Created

Your application creates an Intent that defines the required action.

Step 4: Android System

Android searches for a suitable application that can handle the request.

Step 5: Built-in or Installed Application

The selected application opens and performs the requested action.

Example: Opening a Website

When your application requests a website to be opened:

  1. Your application creates an Intent.
  2. The Intent specifies ACTION_VIEW.
  3. The Intent contains the website address.
  4. Android searches for an application that can open the website.
  5. A suitable browser opens the website.

1.6 Opening the Phone Application

Suppose you are developing a university application.

You want to provide a button that allows students to contact the university office.

When the student clicks the button, the phone dialer should open with the university's number already entered.

Android provides ACTION_DIAL for this purpose.

Java Example
Intent intent = new Intent(Intent.ACTION_DIAL);

intent.setData(
    Uri.parse("tel:03001234567")
);

startActivity(intent);
Explanation
Step 1: Create an Intent 
Intent intent = new Intent(Intent.ACTION_DIAL);

This tells Android that your application wants to open the phone dialer.

Step 2: Set the Telephone Number 
intent.setData(
    Uri.parse("tel:03001234567")
);
  • setData() provides the information associated with the Intent.
  • Uri.parse() creates a URI.
  • tel: identifies the information as a telephone number.
Step 3: Start the Application 
startActivity(intent);

This sends the request to Android and opens a suitable phone application.

What Happens?

The phone dialer opens with the number:

03001234567

The user can review the number and press the call button.

Important:

ACTION_DIAL does not directly make a phone call. It opens the dialer and allows the user to decide whether to call.

1.7 Directly Making a Phone Call

Sometimes an application may need to initiate a call directly.

Android provides ACTION_CALL for this purpose.

Java Example
Intent intent = new Intent(Intent.ACTION_CALL);

intent.setData(
    Uri.parse("tel:03001234567")
);

startActivity(intent);

However, this action requires the CALL_PHONE permission.

Step 1: Add Permission

Open AndroidManifest.xml and add:

<uses-permission
    android:name="android.permission.CALL_PHONE" />
Step 2: Check Runtime Permission

On modern Android versions, declaring the permission in the manifest is not enough.

The application must also request the permission from the user at runtime.

For example, using the Activity Result API:

private final ActivityResultLauncher<String> callPermission =
    registerForActivityResult(
        new ActivityResultContracts.RequestPermission(),
        granted -> {

            if (granted) {
                makeCall();
            }
        }
    );

Then define the call method:

private void makeCall() {

    Intent intent = new Intent(Intent.ACTION_CALL);

    intent.setData(
        Uri.parse("tel:03001234567")
    );

    startActivity(intent);
}

Request the permission when needed:

callPermission.launch(
    Manifest.permission.CALL_PHONE
);

Use ACTION_DIAL when the user should review the number before making a call.

1.9 Opening the Camera Application

Suppose you are developing a student profile application.

You want to allow students to take a profile picture.

Instead of developing a complete camera system, you can request an existing camera application to capture an image.

Android provides:

MediaStore.ACTION_IMAGE_CAPTURE
Java Example
Intent intent = new Intent(
    MediaStore.ACTION_IMAGE_CAPTURE
);

if (intent.resolveActivity(getPackageManager()) != null) {

    startActivityForResult(intent, 100);
}
Explanation
  • ACTION_IMAGE_CAPTURE requests an image capture.
  • resolveActivity() checks whether a suitable camera application is available.
  • getPackageManager() provides information about installed applications.
  • startActivityForResult() launches the camera and requests a result.
Important Modern Android Note:

startActivityForResult() is an older approach. Modern applications should generally use the Activity Result API.

Modern Approach: Activity Result API
private final ActivityResultLauncher<Void> cameraLauncher =
    registerForActivityResult(
        new ActivityResultContracts.TakePicturePreview(),
        bitmap -> {

            if (bitmap != null) {
                imageView.setImageBitmap(bitmap);
            }
        }
    );

Launch the camera:

cameraLauncher.launch(null);

This approach requests a camera application to capture a preview image and returns a Bitmap.

For capturing a full-resolution image, developers commonly use ActivityResultContracts.TakePicture() with a destination content URI.

Android can open a compatible Maps application.

Remember:

You do not need to develop a complete Maps application to open a location. You can request an existing Maps application through an Intent.

1.14 Handling Situations Where an Application Is Not Available

What happens if the user's device does not contain an application that can perform the requested action?

For example, a device might not have a suitable browser installed.

If your application blindly starts an Intent, Android may throw an ActivityNotFoundException.

Developers should check whether an application can handle the request.

Java Example
Intent intent = new Intent(
    Intent.ACTION_VIEW,
    Uri.parse("https://www.google.com")
);

if (intent.resolveActivity(getPackageManager()) != null) {

    startActivity(intent);

} else {

    Toast.makeText(
        this,
        "No suitable application found",
        Toast.LENGTH_SHORT
    ).show();
}
Explanation
  • resolveActivity() checks whether a suitable application exists.
  • If it exists, the Intent is started.
  • Otherwise, an error message is displayed.

This makes the application more reliable.

Modern Android Note:

Android's package visibility restrictions can affect which installed applications your app can discover. For many standard implicit Intents, Android can still resolve the action, but some package queries may require appropriate manifest declarations.

1.16 Advantages of Calling Built-in Applications Using Intents

1. Saves Development Time

Developers do not need to create separate applications for calling, browsing, emailing, or taking pictures.

2. Reduces Development Cost

Using existing applications reduces the amount of code and resources required.

3. Better User Experience

Users can work with familiar applications. For example, users already understand how to use their phone dialer and camera.

4. Application Integration

Different applications can work together. For example, a shopping application can open Maps to show a delivery location.

5. Flexible

An application can request different actions using different Intent types.

1.17 Disadvantages and Limitations

  1. The required application may not be installed.
  2. Different devices may use different applications for the same action.
  3. Some actions require special permissions.
  4. Developers have limited control over the appearance and behavior of another application's interface.
  5. Some operations depend on user confirmation.
  6. The receiving application may not support the requested data or action.

Sending SMS in Android

Preparing messages with intents and sending SMS through Android services.

18.1 Introduction

SMS stands for Short Message Service. It is a technology that allows users to send and receive short text messages through a mobile network.

Android applications can provide SMS functionality in two main ways:

  1. Open the built-in messaging application with a message already prepared.
  2. Send an SMS directly using Android's SMS services.

For example, imagine that you are developing a university application.

You want to add a feature that allows students to:

  • Send a message to their teacher.
  • Receive examination notifications.
  • Send an admission inquiry.
  • Receive an OTP (One-Time Password).
  • Get information about their examination schedule.

Android provides different methods and classes that developers can use to implement SMS-related functionality.

18.2 Definition of SMS in Android

Sending SMS in Android is the process of sending text messages from an Android application to a mobile phone number using the device's messaging functionality or SMS service.

In simple words, an Android application can prepare or send a text message to another person's mobile number.

Example:

A student application can send this message:

Your examination will start on Monday at 9:00 AM.

The message can be sent to the student's registered mobile number.

18.3 Why Is SMS Used in Android Applications?

SMS is useful because it allows applications to communicate with users through mobile phone numbers.

18.3.1 Notifications

Applications can send important information to users.

Example:

A university application sends a message about examination dates.

18.3.2 OTP Verification

Many applications use OTP messages to verify a user's mobile number.

Example:

A user enters their mobile number and receives a verification code.

Your verification code is 482951.

The user enters this code to verify their account.

18.3.3 Reminders

Applications can send reminders about important activities.

Examples:

  • Payment reminders.
  • Examination reminders.
  • Appointment reminders.
  • Meeting reminders.
18.3.4 Emergency Communication

Some applications can send emergency information to selected contacts.

Example:

A safety application may help a user contact an emergency number.

18.3.5 Business Communication

Businesses can use SMS to communicate with customers.

Examples:

  • Order confirmation.
  • Delivery updates.
  • Booking confirmation.
  • Account notifications.
Important: In real applications, automated SMS notifications are often sent through a backend service and an SMS gateway rather than directly from the user's phone.

18.4 Two Methods of Sending SMS in Android

Android provides two common approaches.

Method 1: Using an Intent

This method opens the messaging application with the recipient's number and message already entered.

The user reviews the message and presses Send.

Method 2: Using SmsManager

This method sends the SMS directly through Android's SMS service.

The application uses the SmsManager class and requires the appropriate SMS permission.

Let's understand both methods in detail.

18.5 Method 1: Sending SMS Using an Intent

This is a simple method for allowing users to send messages through an existing messaging application.

Android provides:

Intent.ACTION_SENDTO

It is commonly used with the sms: URI scheme.

Example Situation

Suppose you are developing a Student Management Application.

You want to add a button called Contact Teacher.

When the student clicks this button:

  1. The messaging application opens.
  2. The teacher's number appears in the recipient field.
  3. The message is automatically entered.
  4. The student reviews the message.
  5. The student presses Send.
Java Code
Intent intent = new Intent(
    Intent.ACTION_SENDTO
);

intent.setData(
    Uri.parse("smsto:03001234567")
);

intent.putExtra(
    "sms_body",
    "Hello Teacher, I need some information."
);

startActivity(intent);
Explanation of Each Line

Step 1: Create an Intent

Intent intent = new Intent(
    Intent.ACTION_SENDTO
);

This creates an Intent that requests a messaging application to handle the message.

Step 2: Set the recipient's number

intent.setData(
    Uri.parse("smsto:03001234567")
);
  • setData() provides the recipient information.
  • Uri.parse() converts the address into a URI.
  • smsto: identifies the destination as an SMS recipient.

Step 3: Add the message

intent.putExtra(
    "sms_body",
    "Hello Teacher, I need some information."
);

This adds the text that should appear in the message field.

Step 4: Open the messaging application

startActivity(intent);

This sends the request to Android and opens a suitable messaging application.

Important Points
  • The user controls the final sending operation.
  • Your application does not directly send the SMS.
  • You generally do not need the SEND_SMS permission for this approach.
  • The device must have a suitable application that can handle the SMS request.

This method is generally preferable when the user should review and send the message themselves.

18.6 Method 2: Sending SMS Using SmsManager

Android provides a class called SmsManager for sending SMS messages directly through the device's SMS service.

Definition:

SmsManager is an Android class used to manage and send SMS messages from an application.

Unlike the Intent method, this method can send the message without opening the messaging application's compose screen.

How Does SmsManager Work?
  1. The application obtains an SmsManager object.
  2. It provides the recipient's phone number.
  3. It provides the message text.
  4. It calls the SMS sending method.
  5. Android attempts to send the message through the available mobile network.

18.7 Permission Required for Sending SMS

To send SMS directly using SmsManager, the application needs the SEND_SMS permission.

Android protects SMS functionality because sending messages can create costs and may be misused.

Step 1: Add Permission in AndroidManifest.xml

Open your AndroidManifest.xml file.

Add the following permission outside the <application> element:

<uses-permission
    android:name="android.permission.SEND_SMS" />

Example:

<manifest
    xmlns:android="http://schemas.android.com/apk/res/android">

    <uses-permission
        android:name="android.permission.SEND_SMS" />

    <application
        android:label="Student Application">

        <!-- Activities go here -->

    </application>

</manifest>

Explanation:

SEND_SMS tells Android that the application wants permission to send SMS messages.

However, declaring the permission in the manifest is not enough on modern Android versions.

The application must also request permission from the user at runtime.

18.8 Runtime Permission for Sending SMS

Android 6.0 (API level 23) introduced runtime permission requests for dangerous permissions.

SEND_SMS is a dangerous permission.

This means the application must ask the user for permission while running.

Why Is Runtime Permission Necessary?

Imagine that an application sends messages without the user's knowledge.

It could:

  • Send unwanted messages.
  • Create SMS charges.
  • Misuse the user's phone number.
  • Send messages to unknown contacts.

Runtime permissions give users control over sensitive operations.

Java Example: Requesting SMS Permission

Using the modern Activity Result API:

private final ActivityResultLauncher<String> smsPermission =
    registerForActivityResult(
        new ActivityResultContracts.RequestPermission(),
        granted -> {

            if (granted) {

                sendSMS();

            } else {

                Toast.makeText(
                    this,
                    "SMS permission denied",
                    Toast.LENGTH_SHORT
                ).show();
            }
        }
    );

To request permission:

smsPermission.launch(
    Manifest.permission.SEND_SMS
);
Explanation
  • ActivityResultLauncher launches a permission request.
  • RequestPermission() handles one permission.
  • granted tells us whether the user accepted the permission.
  • If permission is granted, sendSMS() is called.
  • Otherwise, the application displays a message.

The permission must also be declared in AndroidManifest.xml.

18.9 Sending an SMS Using SmsManager

Now let's write the actual SMS sending code.

Java Example
private void sendSMS() {

    String phoneNumber = "03001234567";

    String message = "Your examination will start on Monday.";

    SmsManager smsManager =
        SmsManager.getDefault();

    smsManager.sendTextMessage(
        phoneNumber,
        null,
        message,
        null,
        null
    );
}
Explanation of Each Line

Step 1: Store the phone number

String phoneNumber = "03001234567";

This stores the recipient's mobile number.

Step 2: Store the message

String message = "Your examination will start on Monday.";

This contains the message that will be sent.

Step 3: Get the SmsManager object

SmsManager smsManager =
    SmsManager.getDefault();

This obtains the SMS manager used to send messages.

Step 4: Send the message

smsManager.sendTextMessage(
    phoneNumber,
    null,
    message,
    null,
    null
);

This method accepts five parameters.

Parameter Meaning
destinationAddress Recipient's phone number
scAddress SMS service center address; null uses the default
text Message content
sentIntent Optional notification about sending result
deliveryIntent Optional notification about delivery report
Important

Calling sendTextMessage() does not guarantee that the receiver has received the SMS.

To check the sending result and delivery report, developers can use PendingIntent with appropriate broadcast receivers.

Also, modern Android applications may use a subscription-specific SmsManager when working with dual-SIM devices.

18.10 Sending Long SMS Messages

An ordinary SMS message can contain up to 160 characters when using the standard GSM 7-bit alphabet.

However, some characters and languages use different encoding rules, which can reduce the number of characters available in one SMS segment.

What happens if the message is longer?

Android can divide it into multiple SMS parts.

For this purpose, SmsManager provides:

divideMessage()
Example
String message =
    "This is a long message containing more text than one SMS can normally hold.";

SmsManager smsManager =
    SmsManager.getDefault();

ArrayList<String> parts =
    smsManager.divideMessage(message);

smsManager.sendMultipartTextMessage(

18.12 Handling SMS Sending Results

A developer should not assume that an SMS was successfully sent just because the sending method was called.

There are two important results:

18.12.1 Sent Status

The sent status tells the application whether the SMS was successfully submitted through the sending process.

18.12.2 Delivery Status

The delivery status provides information about whether the SMS reached the recipient's device, when the network and device support delivery reports.

These are different things.

For example:

  • A message may be successfully submitted but not delivered.
  • A receiver's phone may be switched off.
  • The network may be unavailable.
  • The phone number may be incorrect.

Developers can use PendingIntent and BroadcastReceiver to receive sending and delivery results.

import androidx.activity.result.contract.ActivityResultContracts;

public class MainActivity extends AppCompatActivity {

    EditText phoneNumber;
    EditText message;
    Button sendButton;

    private final ActivityResultLauncher<String> smsPermission =
        registerForActivityResult(
            new ActivityResultContracts.RequestPermission(),
            granted -> {

                if (granted) {
                    sendSMS();
                } else {
                    Toast.makeText(
                        this,
                        "SMS permission denied",

    private void sendSMS() {

        String number = phoneNumber.getText().toString().trim();

        String text = message.getText().toString().trim();

        if (number.isEmpty() || text.isEmpty()) {

            Toast.makeText(
                this,
                "Enter phone number and message",
                Toast.LENGTH_SHORT
            ).show();

            return;

        try {

            smsManager.sendTextMessage(
                number,
                null,
                text,
                null,
                null
            );

            Toast.makeText(
                this,
                "SMS sending requested",
                Toast.LENGTH_SHORT
            ).show();

        } catch (Exception e) {

            Toast.makeText(
                this,
                "Unable to send SMS",
                Toast.LENGTH_SHORT
            ).show();
        }

18.14 Important Security and Google Play Considerations

SMS permission is sensitive because it allows an application to send messages that may cost the user money.

Developers should:

  1. Request permission only when the feature is needed.

An application generally needs to qualify for an approved permitted use or an applicable exception to distribute with these permissions. For many commercial applications, a backend SMS gateway is a more suitable solution for automated notifications and OTP delivery.

20.6 Difference Between ACTION_SENDTO and ACTION_SEND

Android provides different Intent actions for sharing and sending information.

Two important actions are ACTION_SENDTO and ACTION_SEND.

ACTION_SENDTO

ACTION_SENDTO is commonly used when you want to open a specific type of communication application.

For email, it is used with the mailto: URI.

Example:

Intent intent = new Intent(Intent.ACTION_SENDTO);

intent.setData(Uri.parse("mailto:"));

This approach is suitable when you want to open an email application without attaching files.

ACTION_SEND

ACTION_SEND is used to share information with another application.

It can be used for sharing:

  • Text
  • Images
  • Documents
  • PDF files
  • Other supported content

Example:

Intent intent = new Intent(Intent.ACTION_SEND);

        "Hello, this is a shared message.");

startActivity(intent);

This example opens compatible sharing applications. It is not restricted to email applications.

    if (ActivityCompat.checkSelfPermission(
            this,
            Manifest.permission.ACCESS_FINE_LOCATION

        ActivityCompat.checkSelfPermission(
            this,

This code checks whether the application has an appropriate location permission before enabling the My Location Layer.

Consuming Web Services Using HTTP

Learn how Android applications communicate with web servers, send HTTP requests, receive data, and process JSON responses.

21.1 Introduction

Modern mobile applications rarely work alone. Most applications communicate with servers to send information, receive information, and access online services.

For example:

  • A weather application gets current weather information from a server.
  • A shopping application retrieves product details from an online database.
  • A social media application loads posts and messages from a server.
  • A banking application communicates with a server to retrieve account information.
  • A news application downloads the latest news articles.

Android applications commonly use HTTP (Hypertext Transfer Protocol) to communicate with web servers.

When an Android application requests information from a server, the server processes the request and sends a response.

This process allows mobile applications to use online data without storing everything directly on the device.

21.2 What Are Web Services?

Definition:

A web service is a software system that allows two applications to communicate and exchange information over a network, usually through the internet.

In simple words, a web service allows one application to request information or functionality from another system.

For example, imagine that we are developing a weather application.

The application needs to display the current temperature of Islamabad.

However, the application does not have the latest weather information stored inside it.

Instead, it communicates with a weather service.

The weather service returns information such as:

  • City name
  • Temperature
  • Weather condition
  • Humidity
  • Wind speed

The Android application displays this information to the user.

Example of Web Services in Real Applications
Application Web service usage
Weather application Retrieves weather information
Shopping application Retrieves products and prices
Banking application Retrieves account information
Social media application Loads posts and messages
Food delivery application Retrieves restaurants and orders
News application Retrieves the latest news

21.3 What Does Consuming a Web Service Mean?

Definition:

Consuming a web service means using a web service provided by another system to request information or perform an operation.

For example, suppose a developer creates a weather web service.

Another developer creates an Android weather application.

The Android application uses the weather service to retrieve information.

This means the Android application is consuming the web service.

Understanding the Process

The process works as follows:

  1. The user opens the Android application.
  2. The application sends a request to a web service.
  3. The server receives the request.
  4. The server processes the request.
  5. The server sends a response.
  6. The Android application receives the response.
  7. The application displays the information.

21.4 What Is HTTP?

Definition:

HTTP stands for Hypertext Transfer Protocol. It is a communication protocol used to transfer information between clients and servers over a network.

In simple words, HTTP defines how an application sends requests to a server and how the server sends responses back.

For example, when an Android application requests a list of products, HTTP helps transfer that information between the application and the server.

How HTTP Works

HTTP follows a request-response communication model.

Request

The client asks the server to perform an operation or provide information.

Response

The server returns the result of that request.

Example:

Client: Please give me the product list.

Server: Here is the product list.

In a real application, these messages contain structured information, headers, and sometimes a request or response body.

HTTP and HTTPS

There are two important versions to understand.

HTTP HTTPS
Hypertext Transfer Protocol Hypertext Transfer Protocol Secure
Communication is not encrypted by TLS Communication is protected using TLS
Data can be exposed during transmission Helps protect data during transmission
Not suitable for sensitive data over untrusted networks Recommended for modern applications
Important:

Android applications should use HTTPS for normal communication with web services, especially when sending passwords, personal information, or financial data.

21.5 Important Parts of an HTTP Request

An HTTP request contains different parts that tell the server what the application wants.

The important parts are:

  1. URL
  2. HTTP method
  3. Headers
  4. Request body
21.5.1 URL (Uniform Resource Locator)
Definition:

A URL is the address of a resource on the internet.

Example:

https://api.example.com/products

Let's understand its parts:

Part Meaning
https Communication protocol
api.example.com Server address
/products Resource or endpoint

An endpoint is a specific URL through which an application accesses a particular resource or operation.

For example:

https://api.example.com/products
https://api.example.com/users
https://api.example.com/orders

These endpoints may provide product, user, and order information.

21.5.2 HTTP Method

An HTTP method tells the server what type of operation the client wants to perform.

For example:

  • GET: Retrieve information.
  • POST: Send information to create a resource or perform an operation.
  • PUT: Replace or update a resource.
  • DELETE: Delete a resource.

We will explain these methods in detail below.

21.5.3 HTTP Headers

Headers provide additional information about the request or response.

For example, a header can tell the server that the application wants JSON data.

Content-Type: application/json
Accept: application/json

Content-Type describes the format of the data being sent.

Accept tells the server which response formats the client can handle.

Another common header is:

Authorization: Bearer YOUR_ACCESS_TOKEN

This can be used to send an authentication token when accessing a protected service.

21.5.4 Request Body

The request body contains information sent to the server.

For example, when a user registers an account, the application may send:

{
  "name": "Ali",
  "email": "ali@example.com",
  "password": "example-password"
}

This is an example of JSON data.

A GET request usually does not need a request body. POST and PUT requests commonly include one.

21.9 What Is JSON Parsing?

Definition:

JSON parsing is the process of reading JSON data and converting it into a structure that an application can understand and use.

When an Android application receives JSON data from a server, it needs to extract the required information.

For example, the server returns:

{
  "id": 101,
  "name": "Ali",
  "course": "BS IT"
}

The Android application may need only the student's name and course.

Java provides classes such as JSONObject and JSONArray to work with JSON data.

21.9.1 JSONObject

JSONObject is used to read and work with JSON objects.

Example:

String jsonData =
    "{\"id\":101,\"name\":\"Ali\",\"course\":\"BS IT\"}";

JSONObject object = new JSONObject(jsonData);

String name = object.getString("name");

String course = object.getString("course");

int id = object.getInt("id");

Explanation:

  • JSONObject: Creates an object from JSON text.
  • getString("name"): Extracts the student's name.
  • getString("course"): Extracts the course name.
  • getInt("id"): Extracts the student ID as an integer.

The extracted information can now be displayed in the application.

21.9.2 JSONArray

JSONArray is used when the server returns multiple objects in an array.

Example:

[
  {
    "id": 1,
    "name": "Ali"
  },
  {
    "id": 2,
    "name": "Ahmed"
  },
  {
    "id": 3,
    "name": "Sara"
  }
]

Java example:

JSONArray students = new JSONArray(jsonData);

for (int i = 0; i < students.length(); i++) {

    JSONObject student = students.getJSONObject(i);

    String name = student.getString("name");

    int id = student.getInt("id");
}

Explanation:

  1. JSONArray reads the list of students.
  2. length() tells us how many objects are in the array.
  3. The for loop visits each student.
  4. getJSONObject(i) retrieves the current student.
  5. getString() and getInt() extract the student's information.

This is useful when an Android application receives lists of products, students, customers, or other records.

21.10 Making HTTP Requests in Android

Now we will understand how an Android application communicates with a web server using Java.

Android provides different networking approaches, including:

  • HttpURLConnection
  • OkHttp
  • Retrofit

21.10.1 Add Internet Permission

First, open AndroidManifest.xml.

<uses-permission

This permission allows the application to open network connections.

21.10.2 Important Rule: Network Requests Must Not Run on the Main Thread

Android applications have a main thread, also called the UI thread.

The main thread handles:

  • Displaying the interface.
  • Responding to button clicks.
  • Updating TextViews.
  • Handling user interactions.

Network requests may take time because they depend on the internet and server response.

If we perform a network request directly on the main thread, the application may become unresponsive or crash with an NetworkOnMainThreadException.

Therefore, we perform network operations on a background thread.

After receiving the response, we return to the main thread to update the user interface.

How Android handles an HTTP request
  1. Main Thread

    User clicks the Load Data button.

  2. Background Thread

    Sends HTTP request and waits for the server.

  3. Server

    Processes request and returns data.

  4. Main Thread

    Displays the received information.

import android.os.Handler;
import android.os.Looper;
import android.widget.Button;
import android.widget.TextView;

import androidx.appcompat.app.AppCompatActivity;

import org.json.JSONObject;

import java.io.BufferedReader;
import java.io.InputStream;
import java.io.InputStreamReader;
import java.net.HttpURLConnection;
import java.net.URL;
import java.util.concurrent.ExecutorService;
import java.util.concurrent.Executors;

public class MainActivity extends AppCompatActivity {

    Button btnLoad;
    TextView txtResult;

    ExecutorService executor =
            Executors.newSingleThreadExecutor();

    Handler mainHandler =
            new Handler(Looper.getMainLooper());

    @Override
    protected void onCreate(Bundle savedInstanceState) {
        super.onCreate(savedInstanceState);

        setContentView(R.layout.activity_main);

        btnLoad = findViewById(R.id.btnLoad);
        txtResult = findViewById(R.id.txtResult);

        btnLoad.setOnClickListener(v -> {

            txtResult.setText("Loading...");

            executor.execute(() -> {

                String result = getData();

                mainHandler.post(() -> {
                    txtResult.setText(result);
                });

            });

        });
    }

    private String getData() {

        HttpURLConnection connection = null;

        try {

            URL url = new URL(
                "https://jsonplaceholder.typicode.com/posts/1"
            );

            connection =
                (HttpURLConnection) url.openConnection();

            connection.setRequestMethod("GET");

            connection.setConnectTimeout(10000);

            connection.setReadTimeout(10000);

            int responseCode =
                connection.getResponseCode();

            if (responseCode == 200) {

                InputStream inputStream =
                    connection.getInputStream();

                BufferedReader reader =
                    new BufferedReader(
                        new InputStreamReader(inputStream)
                    );

                StringBuilder response =
                    new StringBuilder();

                String line;

                while ((line = reader.readLine()) != null) {
                    response.append(line);
                }

                reader.close();

                JSONObject object =
                    new JSONObject(response.toString());

                String title =
                    object.getString("title");

                String body =
                    object.getString("body");

                return "Title: " + title
                    + "\n\nBody: " + body;

            } else {

                return "Server error: " + responseCode;
            }

        } catch (Exception e) {

            return "Error: " + e.getMessage();

        } finally {

            if (connection != null) {
                connection.disconnect();
            }
        }
    }

    @Override
    protected void onDestroy() {
        super.onDestroy();
        executor.shutdown();
    }
}

private void sendData() {

            System.out.println(

            );
        }

    } catch (Exception e) {

        e.printStackTrace();

    } finally {

        if (connection != null) {
            connection.disconnect();
        }
    }
}

21.16 Best Practices When Consuming Web Services

When developing a real Android application, we should follow these practices.

Never perform long-running network operations on the main UI thread.

Handle network failures, invalid responses, and server errors properly.

Set connection and read timeouts so the application does not wait indefinitely.

Check status codes and validate received information before using it.

7. Avoid Unnecessary Requests

Do not repeatedly request the same information when it can be reused safely.

8. Respect User Privacy

Send only the information required by the web service and protect sensitive user data.

9. Use Suitable Libraries

For larger applications, libraries such as OkHttp and Retrofit can make networking code easier to maintain.

23.2 What Is a Web Service?

Definition:

A web service is a software system that allows different applications to communicate and exchange information over a network using standard communication technologies.

In simple words, a web service acts as a communication bridge between different applications.

For example:

  1. An Android application requests student information.
  2. A web service receives the request.
  3. The web service retrieves the information from a database.
  4. The web service sends the information back to the Android application.

The Android application does not need to know how the server internally stores or manages the information.

Real-Life Example

Usually, the information is stored in a database on a server.

The Android application sends a request to a web service.

The web service retrieves product information and returns it to the application.

The application then displays the products.

23.5 Types of Web Services

There are different approaches to developing web services.

Two important types are:

  1. SOAP Web Services.
  2. RESTful Web Services.
23.5.1 SOAP Web Services
Definition:

SOAP stands for Simple Object Access Protocol. It is a protocol used for exchanging structured information between applications.

SOAP commonly uses XML to represent messages.

Example of a SOAP message:

<soap:Envelope>
    <soap:Body>
        <getStudent>
            <studentId>101</studentId>
        </getStudent>
    </soap:Body>
</soap:Envelope>

Explanation:

  • Envelope: Represents the outer structure of a SOAP message.
  • Body: Contains the actual request or response information.
  • getStudent: Represents the requested operation.
  • studentId: Identifies the student.

SOAP is commonly used in systems that require formal message structures and established enterprise standards.

23.5.2 RESTful Web Services
Definition:

REST stands for Representational State Transfer. It is an architectural style used to design network-based services.

RESTful services commonly use HTTP methods such as GET, POST, PUT, and DELETE to work with resources.

They often exchange information using JSON.

Example:

GET /api/students/101

The server may return:

{
  "id": 101,
  "name": "Ali",
  "course": "BS IT"
}

Explanation:

The request asks the server to retrieve student number 101.

The server returns the student's information in JSON format.

SOAP vs REST

Remember:

SOAP and REST are not the same thing. SOAP is a protocol, while REST is an architectural style.

23.17 Important Principles of RESTful Web Services

When creating REST APIs, developers should follow certain principles.

23.17.1 Client-Server Architecture

The client and server have separate responsibilities.

  • Client: Displays information and sends requests.
  • Server: Processes requests and manages data.

This separation makes applications easier to develop and maintain.

23.17.2 Statelessness

Each request should contain the information required to process it.

The server should not depend on the previous request to understand the current request.

For example, a protected API request can include an authentication token.

23.17.3 Resource-Based URLs

REST APIs use URLs to identify resources.

Examples:

/api/students
/api/products
/api/orders

These URLs identify different resources.

23.17.4 Use of HTTP Methods

REST APIs use HTTP methods to perform operations on resources.

  • GET — Retrieve.
  • POST — Create or submit.
  • PUT — Replace or update.
  • DELETE — Remove.
23.17.5 Consistent Responses

A well-designed API should return predictable responses, including appropriate HTTP status codes and structured data.

For example:

{
  "message": "Student created successfully",
  "id": 5
}

23.18 Security in Web Services

Security is extremely important when creating and accessing web services.

A web service may contain private information, such as student records, account details, and personal information.

Developers should follow these practices.

  1. Use HTTPS

    HTTPS protects information while it travels between the Android application and the server.

  2. Authentication

    Authentication verifies the identity of a user.

    For example, users may log in using an email address and password.

  3. Authorization

    Authorization determines what an authenticated user is allowed to access.

    For example, a student may view their own results, while an administrator may manage all student records.

  4. Input Validation

    The server should check information received from clients before processing it.

  5. SQL Injection Protection

    Use prepared SQL statements instead of building database queries by directly joining user input into SQL strings.

  6. Protect API Credentials

    Do not store database passwords or private server credentials inside an Android application.

  7. Control Access

    Sensitive API endpoints should require appropriate authentication and authorization.

Threading in Android

Understand threads, multithreading, background tasks, the main UI thread, Handler, Looper, ExecutorService, and modern Android background work.

24.1 Introduction to Threading

An Android application performs many tasks when a user interacts with it.

For example, imagine a student management application. When a student opens the app, it may need to:

  • Display the home screen.
  • Load student records from an online server.
  • Download student profile pictures.
  • Save information into a database.
  • Calculate student results.
  • Respond when the user clicks a button.

Some tasks are quick, while others may take several seconds.

The important question is: How can an Android application perform time-consuming tasks without freezing its screen?

The answer is threading.

Threading allows an application to perform multiple tasks without forcing every task to run one after another on the same execution path.

For example, the app can display its screen while another thread downloads student records from a server.

24.2 What Is a Thread?

Definition: A thread is the smallest unit of execution within a process. It represents an independent path through which a program's instructions are executed.

In simple words, a thread is a path that performs a particular task inside an application.

For example, an Android application may use:

  • One thread to display the user interface.
  • Another thread to download data.
  • Another thread to process images.
  • Another thread to perform calculations.

Each thread can execute its own instructions.

Real-life example

Imagine a restaurant:

  • One worker takes customer orders.
  • Another worker prepares food.
  • Another worker delivers food.

All workers are part of the same restaurant, but each performs a different task.

Similarly, an application can use different threads to perform different tasks.

Why are threads important?

Threads are important because they help applications:

  1. Perform multiple tasks efficiently.
  2. Keep the user interface responsive.
  3. Handle network operations.
  4. Process large amounts of data.
  5. Perform background calculations.
  6. Improve the overall user experience.

24.3 Difference Between a Process and a Thread

A process and a thread are related, but they are not the same.

Process

A process is a running instance of a program.

When an Android application starts, Android normally creates a process for that application. The process has resources such as memory and other operating-system-managed resources.

Thread

A thread is an execution path inside a process.

A process can contain multiple threads. These threads normally share the process's memory and other resources.

Example

Suppose you open a music player application.

  • The entire running music player application is a process.
  • One thread may handle the user interface.
  • Another thread may process audio.
  • Another thread may download music information.
Process Thread
A running instance of a program. An execution path inside a process.
Has its own process resources. Shares many resources with other threads in the same process.
Can contain multiple threads. Belongs to a process.
Generally has a larger resource-management cost. Generally has a smaller resource-management cost.

Important: A process is the environment in which threads operate, while threads perform the actual execution of tasks.

24.4 What Is Multithreading?

Definition: Multithreading is the technique of using multiple threads within a single process to perform different tasks.

It allows an application to work on multiple activities without making the user wait for every task to finish.

Example

Suppose a user opens a news application.

The application needs to:

  1. Display the home screen.
  2. Download news articles.
  3. Load article images.
  4. Process notifications.

Without proper threading, a long operation could stop the application from responding.

With multithreading:

  • The main thread handles the screen and user interactions.
  • A background thread downloads news articles.
  • Another worker thread can process images.

The application remains responsive while background work continues.

Advantages of multithreading
  1. Better responsiveness: The application can respond to user actions while other work continues.
  2. Efficient task handling: Different tasks can be handled by different threads.
  3. Better resource utilization: Multiple CPU cores may execute different threads in parallel.
  4. Improved user experience: Users do not have to wait for every background operation.
  5. Background processing: Long-running work can be moved away from the user interface thread.

Remember: Multiple threads do not always mean that tasks execute at exactly the same time. On a multi-core processor, threads may run in parallel. On a single-core processor, the operating system can switch between threads rapidly.

24.5 Main Thread (UI Thread) in Android

Definition: The main thread, also called the UI thread, is the primary thread responsible for managing an Android application's user interface.

When an Android application starts, Android creates its main thread.

This thread handles activities such as:

  • Displaying text, buttons, images, and other views.
  • Drawing and updating the screen.
  • Responding to button clicks.
  • Handling touch events.
  • Processing user interactions.
  • Updating the user interface.
Example

Suppose an application has a button:

Button btn = findViewById(R.id.btnSubmit);

btn.setOnClickListener(v -> {
    Toast.makeText(this, "Button Clicked", Toast.LENGTH_SHORT).show();
});

When the user clicks the button, the main thread handles the click event and displays the message.

Why is the main thread important?

The main thread must remain available to respond to the user.

Imagine that a user clicks a button to load information from an online server. If the main thread performs the entire network operation, it may have to wait several seconds for the server.

During that time:

  • The screen may stop responding.
  • Buttons may not work.
  • Animations may freeze.
  • The user may think the application has stopped working.

Therefore, Android developers should avoid performing long-running operations on the main thread.

24.6 Background Thread (Worker Thread)

Definition: A background thread is a thread used to perform tasks that should not block the main user interface thread.

It allows time-consuming operations to run separately while the main thread continues handling the screen.

Common tasks performed by background threads
  1. Network operations: Downloading information from a web service or sending data to a server.
  2. Database operations: Reading or saving large amounts of information.
  3. File operations: Reading, writing, uploading, or downloading files.
  4. Image processing: Resizing, compressing, or processing images.
  5. Calculations: Performing complex mathematical operations.
  6. Data processing: Sorting, filtering, or processing large datasets.
Example

Suppose a student opens a result-checking application.

The application needs to retrieve the student's result from a server.

The process can work like this:

  1. The main thread displays the result screen.
  2. The user clicks the Check Result button.
  3. A background thread sends a request to the server.
  4. The server returns the student's result.
  5. The application sends the result back to the main thread.
  6. The main thread displays the result on the screen.

Important rule: Background threads should not directly update Android Views.

For example, a background thread should not directly change a TextView, Button, or other UI component.

Instead, it should send the result to the main thread, which then updates the user interface.

We will learn how to do this later in this topic.

24.8 What Is ANR (Application Not Responding)?

Definition: ANR stands for Application Not Responding.

It is an Android system warning that appears when an application cannot respond to user input within the expected time.

In simple words, ANR occurs when an application becomes unresponsive for too long.

Why does ANR happen?

One common reason is that the main thread is busy performing a long-running operation.

For example:

Suppose an application downloads a large file directly on the main thread.

The process may look like this:

  1. The user clicks the Download button.
  2. The main thread starts downloading the file.
  3. The download takes several seconds.
  4. The main thread cannot respond properly to other user interactions.
  5. Android detects that the application is not responding and may display an ANR warning.
How can developers prevent ANR?

Developers should:

  1. Perform network operations on background threads.
  2. Avoid long calculations on the main thread.
  3. Move large file operations to worker threads.
  4. Keep UI operations short.
  5. Use suitable background-work tools.
  6. Avoid blocking the main thread with operations that wait for a long time.

Important: ANR is not a separate type of thread. It is an application responsiveness problem that Android can detect.

24.9 Thread Lifecycle and States

A thread does not remain in the same condition throughout its life.

Java provides different thread states to describe what a thread is currently doing.

The main thread states are:

  1. NEW
  2. RUNNABLE
  3. BLOCKED
  4. WAITING
  5. TIMED_WAITING
  6. TERMINATED
24.9.1 NEW State

A thread is in the NEW state when its object has been created but it has not started running.

Example:

Thread myThread = new Thread(() -> {
    System.out.println("Thread is running");
});

Here, the thread object has been created, but start() has not been called.

Therefore, its state is NEW.

24.9.2 RUNNABLE State

A thread enters the RUNNABLE state after its start() method is called.

It is ready to run or may currently be running.

Example:

myThread.start();

Java combines the ready-to-run and currently-running conditions under the RUNNABLE state.

24.9.3 BLOCKED State

A thread enters the BLOCKED state when it is waiting to obtain a monitor lock so that it can enter a synchronized section of code.

For example, another thread may already hold a lock that the current thread needs.

24.9.4 WAITING State

A thread enters the WAITING state when it waits indefinitely for another thread to perform a particular action.

For example:

myThread.join();

The thread calling join() waits until myThread finishes.

24.9.5 TIMED_WAITING State

A thread enters the TIMED_WAITING state when it waits for a specific amount of time.

Example:

Thread.sleep(2000);

This pauses the current thread for approximately two seconds.

24.9.6 TERMINATED State

A thread enters the TERMINATED state when its execution has finished or stopped because of an uncaught exception.

Example:

Thread myThread = new Thread(() -> {
    System.out.println("Task completed");
});

myThread.start();

After the task finishes, the thread becomes TERMINATED.

Important: A terminated thread cannot be started again. You must create a new thread object to perform another execution.

Two basic approaches are:

  1. Using the Thread class.
  2. Using the Runnable interface.
24.10.1 Using the Thread Class

The Thread class represents a thread of execution.

We can create a thread and provide the task that it should perform.

Example:

Thread myThread = new Thread(() -> {

    System.out.println("Background task is running");

});

myThread.start();
Explanation

Step 1: Create a thread

Thread myThread = new Thread(() -> {

This creates a new thread object.

Step 2: Define the task

System.out.println("Background task is running");

This is the work that the new thread will perform.

Step 3: Start the thread

myThread.start();

The start() method asks Java to start a new thread. The new thread then executes the task.

24.10.2 Using the Runnable Interface

Runnable is a Java interface used to represent a task that can be executed by a thread.

It contains a method called:

run()

We provide the code that should execute inside this method.

Example:

Runnable task = new Runnable() {

    @Override
    public void run() {

        System.out.println("Task is running");

  • Runnable task creates a task.
  • run() contains the instructions to perform.
  • new Thread(task) creates a thread and gives it the task.
  • start() starts a new thread to execute the task.

A class extending Thread cannot extend another class. A class implementing Runnable can still extend another class.
Which approach is better?

Using Runnable is often more flexible because it separates the task from the thread that executes it.

24.10.4 Difference Between start() and run()

This is a very important concept.

Consider:

Thread myThread = new Thread(() -> {

    System.out.println("Hello");

});

There are two possible calls.

Using start():

myThread.start();

This starts a new thread, and that thread executes the run() method.

Using run():

myThread.run();

This simply calls the run() method like an ordinary method on the current thread.

It does not create a new thread.

24.11 Updating the User Interface from a Background Thread

As explained earlier, Android Views must be accessed and updated on the main thread.

Suppose a background thread downloads a student's result. After receiving the result, the application needs to display it inside a TextView.

The background thread cannot safely update that TextView directly.

Android provides ways to send work back to the main thread.

Two common methods are:

  1. runOnUiThread()
  2. Handler with Looper.getMainLooper()
24.11.1 Using runOnUiThread()

Definition: runOnUiThread() is an Activity method that allows code to execute on the main UI thread.

It is useful when a background task needs to update the screen.

Example:

public class MainActivity extends AppCompatActivity {

    TextView txtResult;
    Button btnLoad;

        setContentView(R.layout.activity_main);

        btnLoad.setOnClickListener(v -> {

            new Thread(() -> {

                // Background task

                // Return to the main thread
                runOnUiThread(() -> {

                    txtResult.setText(result);

                });

            }).start();

        });
    }
}

Step 1: Find the UI components

txtResult = findViewById(R.id.txtResult);
btnLoad = findViewById(R.id.btnLoad);

The application connects the Java variables with the TextView and Button defined in XML.

Step 2: Handle the button click

btnLoad.setOnClickListener(v -> {

This code runs when the user clicks the button.

Step 3: Create a background thread

new Thread(() -> {

This creates a new thread to perform the background task.

Step 4: Perform the background work

String result = "Student Result: 85 Marks";

Here, the thread prepares the result. In a real application, this could involve downloading data from a server or reading a database.

Step 5: Return to the main thread

runOnUiThread(() -> {
    txtResult.setText(result);
});

This schedules the UI update on the main thread.

The TextView can now safely display the result.

  1. User clicks the button.
  2. A background thread starts.
  3. The background task performs its work.
  4. The result is passed to runOnUiThread().
  5. The main thread updates the TextView.

Android also provides two important classes:

  • Handler
  • Looper

They are commonly used to communicate with a thread through its message queue.

Handler: A Handler allows you to send messages or post tasks to a thread's message queue.

Looper: A Looper manages a thread's message queue. It continuously processes queued messages and tasks while the thread is running.

How do they work together?

Imagine that a background thread completes a task and wants the main thread to display the result.

The background thread sends a task through a Handler.

The Handler places the task in the main thread's message queue.

The main thread's Looper processes that task, and the UI is updated.

Practical Java example
public class MainActivity extends AppCompatActivity {

    TextView txtResult;
    Button btnStart;

    Handler mainHandler =
            new Handler(Looper.getMainLooper());

    @Override
    protected void onCreate(Bundle savedInstanceState) {
        super.onCreate(savedInstanceState);
        setContentView(R.layout.activity_main);

        txtResult = findViewById(R.id.txtResult);
        btnStart = findViewById(R.id.btnStart);

        btnStart.setOnClickListener(v -> {

            new Thread(() -> {

                String result = "Background task completed";

                mainHandler.post(() -> {

                    txtResult.setText(result);

                });

            }).start();

        });
    }
}
Understanding the important lines

1. Create a Handler for the main thread

Handler mainHandler =
        new Handler(Looper.getMainLooper());
  • Looper.getMainLooper() gets the Looper associated with the main thread.
  • new Handler(...) creates a Handler that can post tasks to that thread.

2. Start the background thread

new Thread(() -> {

This creates a separate thread.

3. Perform the background task

String result = "Background task completed";

The background thread prepares the result.

4. Post a task to the main thread

mainHandler.post(() -> {
    txtResult.setText(result);
});

The Handler places the UI update task in the main thread's message queue.

The main thread's Looper processes it.

Difference between Handler and Looper
Handler Looper
Sends or posts tasks and messages. Processes a thread's message queue.
Works with a particular Looper. Manages the message-processing loop.
Can schedule work on the associated thread. Keeps processing queued work while active.

Important: A Handler does not itself create a new thread. It sends work to the thread associated with its Looper.

24.12 ExecutorService in Android

Creating a new thread manually is useful for understanding threading, but creating many individual threads can become difficult to manage.

For example, imagine that a user clicks a button ten times and the application creates ten new threads.

This can waste system resources and make task management more complicated.

Java provides the ExecutorService framework to manage and execute background tasks more efficiently.

Definition

ExecutorService is a Java interface that manages task execution using a pool of threads.

Instead of manually creating and managing a thread for every task, we submit tasks to an executor.

The executor decides which available worker thread will perform each task.

What is a thread pool?

Definition: A thread pool is a collection of reusable worker threads.

Instead of continuously creating and destroying threads, an application can reuse threads to execute different tasks.

Advantages of ExecutorService
  1. Reuses worker threads.
  2. Reduces unnecessary thread creation.
  3. Makes task management easier.
  4. Supports executing multiple tasks.
  5. Can control how many tasks run simultaneously.
24.12.1 Creating a Single-Thread Executor

A single-thread executor uses one worker thread to execute submitted tasks one at a time.

Example:

ExecutorService executor =
        Executors.newSingleThreadExecutor();

executor.execute(() -> {

    System.out.println("Background task is running");

});

executor.shutdown();
Explanation

Step 1: Create the executor

ExecutorService executor =
        Executors.newSingleThreadExecutor();

This creates an executor that uses one worker thread.

Step 2: Submit a task

executor.execute(() -> {
    System.out.println("Background task is running");
});

The execute() method submits the task for background execution.

Step 3: Shut down the executor

executor.shutdown();

This tells the executor not to accept new tasks. Tasks already submitted are allowed to finish.

24.12.2 Creating a Fixed Thread Pool

A fixed thread pool uses a specified number of worker threads.

For example:

ExecutorService executor =
        Executors.newFixedThreadPool(3);

This creates an executor with three worker threads.

You can submit multiple tasks:

executor.execute(() -> {
    System.out.println("Task 1");
});

executor.execute(() -> {
    System.out.println("Task 2");
});

executor.execute(() -> {
    System.out.println("Task 3");
});

The executor can run up to three tasks simultaneously, subject to available CPU resources and scheduling.

After submitting the tasks:

executor.shutdown();
Single-thread executor vs fixed thread pool
Single-thread executor Fixed thread pool
Uses one worker thread. Uses a specified number of worker threads.
Executes submitted tasks one at a time. Can execute multiple tasks at the same time.
Useful for sequential background work. Useful for independent tasks that can run concurrently.
24.12.3 ExecutorService in a Real Android Activity

Consider an application that loads student information when the user clicks a button.

Java code:

public class MainActivity extends AppCompatActivity {

    TextView txtResult;
    Button btnLoad;

    ExecutorService executor =
            Executors.newSingleThreadExecutor();

    Handler mainHandler =
            new Handler(Looper.getMainLooper());

    @Override
    protected void onCreate(Bundle savedInstanceState) {
        super.onCreate(savedInstanceState);
        setContentView(R.layout.activity_main);

        txtResult = findViewById(R.id.txtResult);
        btnLoad = findViewById(R.id.btnLoad);

        btnLoad.setOnClickListener(v -> {

            executor.execute(() -> {

                // Background operation
                String result = "Student Name: Ali";

                // Update UI on main thread
                mainHandler.post(() -> {

                    txtResult.setText(result);

                });

            });

        });
    }

    @Override
    protected void onDestroy() {
        super.onDestroy();

        executor.shutdown();
    }
}
How does this example work?
  1. The Activity creates an ExecutorService.
  2. The user clicks the Load button.
  3. executor.execute() submits the task.
  4. The executor runs the task on its worker thread.
  5. The background task prepares the student information.
  6. mainHandler.post() sends the UI update to the main thread.
  7. The TextView displays the information.
  8. When the Activity is destroyed, the executor is shut down.

Important: This is a basic teaching example. In a production application, the task's lifetime should be managed carefully. An Activity can be destroyed while a task is still running. For longer-lived work, lifecycle-aware components or WorkManager may be more appropriate. Also, shutting down an executor does not automatically cancel every task that has already started.

24.14 Modern Background Work in Android

24.14.1 WorkManager

Definition: WorkManager is an Android library used to schedule background work that should continue even if the application is closed or the device restarts, subject to Android's scheduling rules.

For example:

  • Uploading pending user information.
  • Synchronizing application data.
  • Sending reports to a server.
  • Periodically checking for updates.

WorkManager is especially useful for work that must eventually be completed, even if it cannot run immediately.

They allow developers to write background operations in a simpler, more readable style.

For example, an application can:

  3. Process the response.
  4. Display the result.

Coroutines are widely used in modern Android development, particularly in Kotlin projects.

24.15 Advantages of Threading

Threading provides several advantages in Android application development.

1. Improved responsiveness

The application can continue responding to users while background operations are running.

2. Better performance

Different tasks can execute independently, and multi-core processors can run multiple threads in parallel.

3. Background processing

Time-consuming operations can run without blocking the main UI thread.

4. Better user experience

Users can continue interacting with an application instead of waiting for every operation to finish.

5. Efficient task management

Thread pools and executors make it easier to organize and manage multiple background tasks.

6. Better resource utilization

Threads can make better use of available processor resources when tasks can run concurrently.

24.16 Limitations and Problems of Threading

Although threading is useful, it also introduces some challenges.

1. More complex programming

Managing multiple threads is more complicated than executing all instructions in a single thread.

2. Race conditions

A race condition occurs when multiple threads access shared data and the final result depends on the timing or order of their execution.

For example, two threads may try to update the same bank balance simultaneously.

3. Deadlock

A deadlock occurs when two or more threads wait indefinitely for resources held by one another.

As a result, none of the affected threads can continue.

4. Difficult debugging

Thread-related problems may occur only under particular timing conditions, making them difficult to reproduce and fix.

5. Resource consumption

Creating too many threads can consume memory and CPU resources and may reduce application performance.

6. UI update restrictions

Android Views should be accessed from the main thread. Developers must correctly transfer results from background threads to the UI thread.

24.17 Best Practices for Threading in Android

Developers should follow these practices:

  1. Never perform long-running network operations on the main thread.
  2. Use background threads for time-consuming operations.
  3. Update Android Views only from the main thread.
  4. Use ExecutorService or another appropriate task-management tool instead of creating unlimited threads.
  5. Handle exceptions in background tasks.
  6. Avoid unnecessary thread creation.
  7. Consider cancellation when a task is no longer needed.
  8. Manage background tasks according to the Activity or other component's lifecycle.
  9. Use WorkManager for suitable persistent, deferrable tasks.
  10. Avoid sharing mutable data between threads without proper synchronization.
