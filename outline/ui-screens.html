User interface and screens

Fragments in Android

Reusable parts of an Android screen

7.1 Introduction to Fragments

A Fragment is a reusable part of an Android application's user interface (UI). It represents a portion of an Activity's screen and has its own layout and lifecycle.

In simple words, a Fragment is a small section of an application screen that can be added, removed, or replaced without creating a completely new Activity.

Example: imagine a shopping application with one screen containing product categories on the left and product details on the right. Each section can be designed as a separate Fragment.

7.2 What is an Activity?

Before understanding Fragments, you should understand Activities.

An Activity is an Android application component that provides a screen with which users can interact.

For example, a shopping application may have Login, Home, Product and Profile activities. An Activity acts as a container for the user interface. A Fragment can be placed inside an Activity to divide its screen into smaller reusable sections.

Relationship between Activity and Fragment

  • An Activity can contain one Fragment.
  • An Activity can contain multiple Fragments.
  • A Fragment cannot exist independently; it must be hosted by an Activity.
  • Multiple Activities can reuse the same Fragment.
Example: in a student management application, the main Activity can contain three Fragments: Student Information, Attendance and Result. When a user selects Attendance, the application can replace the Student Information Fragment with the Attendance Fragment while keeping the same Activity.

7.3 Why Do We Use Fragments?

Fragments make Android applications more organized, flexible, and reusable.

1. Reusability

A Fragment can be used in different Activities. For example, a Profile Fragment can be used in both a Home Activity and a Settings Activity.

2. Flexible User Interface

Fragments divide one screen into multiple sections. A phone may display one section at a time, while a tablet may display two or more together.

3. Better Code Organization

Instead of one large Activity, divide the application into smaller components: Login Fragment (login UI), Profile Fragment (profile UI), Settings Fragment (settings UI).

4. Dynamic Screen Changes

Fragments can be added, removed, and replaced while an Activity is running. For example, clicking the Profile button can display the Profile Fragment without opening another Activity.

5. Support for Different Screen Sizes

Fragments help developers create flexible layouts for mobile phones and tablets.

7.4 Lifecycle of a Fragment

A Fragment has its own lifecycle. The Fragment lifecycle describes the stages a Fragment passes through from creation to destruction. Understanding it is important because developers need to know when to create the interface, initialize components, save data, and release resources.

Important Fragment lifecycle methods

1. onAttach()

Called when the Fragment becomes attached to its hosting Activity. It establishes the connection between the Fragment and the Activity.

2. onCreate()

Called when the Fragment is being created. Generally used to initialize data and other non-UI components.

3. onCreateView()

Responsible for creating the Fragment's user interface. For example, it loads an XML layout file containing buttons, text fields, and images.

4. onViewCreated()

Called after the Fragment's view has been created. Used to initialize UI components and set click listeners.

5. onStart()

The Fragment becomes visible to the user.

6. onResume()

The Fragment becomes active and the user can interact with it.

7. onPause()

The Fragment is losing its active state, for example because another screen is coming in front of it.

8. onStop()

The Fragment is no longer visible to the user.

9. onDestroyView()

The Fragment's view is destroyed, but the Fragment object itself may still exist. The view can be destroyed while the Fragment remains in memory.

10. onDestroy()

The Fragment itself is being destroyed.

11. onDetach()

The Fragment is disconnected from its hosting Activity.

7.5 Types of Fragments

Fragments are not limited to one specific type. Developers can create different Fragments according to the application's requirements.

1. Static Fragment

Declared directly inside an Activity's XML layout. Suitable when a Fragment should remain in a fixed position and does not need to be dynamically replaced.

2. Dynamic Fragment

Added, removed, or replaced programmatically while the application is running. Useful when the interface needs to change according to user actions.

Example: clicking the Settings button replaces the Home Fragment with the Settings Fragment.

3. Dialog Fragment

A DialogFragment is designed to display a dialog window.

  • Confirmation dialog
  • Delete warning
  • Date picker
  • Information message
4. List Fragment

A ListFragment is an older Android framework class designed to display a list of items. Modern applications commonly use a regular Fragment with a RecyclerView instead.

7.6 How to Create a Fragment in Android

Suppose we are developing a student application and want to display student information inside a Fragment. We will use Java and XML.

Step 1: Create an XML layout

Create a file named fragment_student.xml. This file defines the Fragment's user interface.

<?xml version="1.0" encoding="utf-8"?>

<LinearLayout
    xmlns:android="http://schemas.android.com/apk/res/android"
    android:layout_width="match_parent"
    android:layout_height="match_parent"
    android:orientation="vertical"
    android:padding="20dp">

    <TextView
        android:id="@+id/studentName"
        android:layout_width="wrap_content"
        android:layout_height="wrap_content"
        android:text="Muhammad"
        android:textSize="24sp" />

    <TextView
        android:layout_width="wrap_content"
        android:layout_height="wrap_content"
        android:text="BS Information Technology"
        android:textSize="18sp" />

</LinearLayout>

Understanding the code:

  • LinearLayout: organizes UI elements vertically.
  • TextView: displays text.
  • layout_width: defines the width of an element.
  • layout_height: defines the height of an element.
  • orientation: determines the direction of elements.
  • textSize: controls the text size.
Step 2: Create the Fragment Java class

Create a Java class named StudentFragment.java.

import android.os.Bundle;
import android.view.LayoutInflater;
import android.view.View;
import android.view.ViewGroup;

import androidx.annotation.NonNull;
import androidx.annotation.Nullable;
import androidx.fragment.app.Fragment;

public class StudentFragment extends Fragment {

    public StudentFragment() {
        // Required empty public constructor
    }

    @Nullable
    @Override
    public View onCreateView(
            @NonNull LayoutInflater inflater,
            @Nullable ViewGroup container,
            @Nullable Bundle savedInstanceState) {

        return inflater.inflate(
            R.layout.fragment_student,
            container,
            false
        );
    }
}

Understanding the important parts:

  • StudentFragment: defines our Fragment class.
  • extends Fragment: makes this class an Android Fragment.
  • onCreateView(): creates the Fragment's interface.
  • LayoutInflater: converts the XML layout into actual View objects.
  • R.layout.fragment_student: identifies the XML layout.
  • container: the parent ViewGroup where the Fragment's view will be placed.
  • false: prevents the layout from being attached to the container immediately. The FragmentManager handles attachment.
Step 3: Add a Fragment container to the Activity

Open your Activity's XML layout and add a FragmentContainerView.

<androidx.fragment.app.FragmentContainerView
    xmlns:android="http://schemas.android.com/apk/res/android"
    android:id="@+id/fragmentContainer"
    android:layout_width="match_parent"
    android:layout_height="match_parent" />

This container provides an area where Fragments can be displayed.

Step 4: Add the Fragment to the Activity

Inside MainActivity.java, use FragmentManager to display the Fragment.

import android.os.Bundle;

import androidx.appcompat.app.AppCompatActivity;
import androidx.fragment.app.Fragment;

public class MainActivity extends AppCompatActivity {

    @Override
    protected void onCreate(Bundle savedInstanceState) {
        super.onCreate(savedInstanceState);

        setContentView(R.layout.activity_main);

        if (savedInstanceState == null) {

            getSupportFragmentManager()
                .beginTransaction()
                .replace(
                    R.id.fragmentContainer,
                    new StudentFragment()
                )
                .commit();
        }
    }
}

Understanding the process:

  1. getSupportFragmentManager() gets the FragmentManager.
  2. beginTransaction() starts a Fragment transaction.
  3. replace() places the StudentFragment inside the container.
  4. commit() applies the transaction.

The savedInstanceState == null condition prevents unnecessarily adding the same initial Fragment again after an Activity recreation.

Result: the Activity will display the Student Fragment containing the student's name and degree.

7.7 Fragment Transactions

A Fragment Transaction is a process used to perform changes to Fragments inside an Activity. Developers use FragmentManager to manage these transactions.

Important transaction methods

MethodPurpose
add()Adds a Fragment
replace()Replaces an existing Fragment
remove()Removes a Fragment
hide()Hides a Fragment's view
show()Shows a hidden Fragment
addToBackStack()Allows a transaction to be reversed using Back navigation
commit()Submits the transaction

Example: replacing Home Fragment with Profile Fragment

getSupportFragmentManager()
    .beginTransaction()
    .replace(R.id.fragmentContainer, new ProfileFragment())
    .addToBackStack(null)
    .commit();

Here, addToBackStack(null) allows the user to return to the previous Fragment using the Back button.

7.9 Advantages and 7.10 Disadvantages of Fragments

Advantages
  1. Reusability: the same Fragment can be used in different Activities.
  2. Flexibility: change screen content dynamically.
  3. Better Organization: application code becomes easier to manage.
  4. Multiple Screen Support: helps create interfaces for phones and tablets.
  5. Independent Lifecycle: lifecycle callbacks for managing its operations.
  6. Easy Navigation: Fragments can be replaced to move between sections.
Disadvantages
  1. Complex Lifecycle: managing Fragment and view lifecycles can be difficult for beginners.
  2. Communication Challenges: sharing data between Activities and Fragments requires proper communication methods.
  3. Management Complexity: multiple Fragments can make navigation and back-stack management complicated.
  4. Debugging Difficulty: lifecycle-related errors can be difficult to identify.

7.11 Real-Life Example

Consider a student management application containing a Home Fragment, Profile Fragment, Attendance Fragment and Result Fragment.

When the user clicks the Attendance button:

  1. The application receives the click event.
  2. The current Fragment is replaced with the Attendance Fragment.
  3. The Attendance Fragment displays attendance records.
  4. The Activity remains the host of the Fragment.

This is how Fragments help organize an application into reusable sections.

Components of a Screen in Android

Activities, layouts, views and common UI widgets

8.1 Introduction

Every Android application has a user interface (UI) through which users interact with the application. For example, when you open a WhatsApp-like application, you see:

A screen titleA list of contactsProfile picturesButtonsText messagesText input fieldsNavigation icons

All these elements work together to create the application's screen.

Definition: Components of a screen are the different elements used to create and organize the user interface of an Android application. These components allow users to view information and interact with the application.

8.2 What Is an Android Screen?

An Android screen is the visible area of an application where users see information and perform different actions. In Android development, an Activity commonly provides the window for a screen.

For example, a student management application might have a Login Screen, Home Screen, Student Profile Screen, Attendance Screen and Result Screen. Each screen can contain different UI components according to its purpose.

Example: Login Screen. Imagine that you open a student application. You see the application name at the top, an email field, a password field, a login button and a Forgot Password link. All these elements are components of the Login Screen.

8.3 Main Components of an Android Screen

An Android screen is made up of several important components. Let's understand them individually.

8.3.1 Activity

An Activity is an Android application component that provides a window for the user interface. It acts as a main container for the screen. For example, when a user opens the Login Screen, the Login Activity manages that screen.

What does an Activity do?

  • Creates and displays the screen
  • Manages user interaction
  • Connects the screen with application logic
  • Handles lifecycle events
  • Can host Fragments
public class MainActivity extends AppCompatActivity {

    @Override
    protected void onCreate(Bundle savedInstanceState) {

        super.onCreate(savedInstanceState);

        setContentView(R.layout.activity_main);
    }
}

Let's understand the important lines:

  • MainActivity: name of the Activity.
  • extends AppCompatActivity: makes this class an Activity using AndroidX compatibility support.
  • onCreate(): called when the Activity is created.
  • setContentView(): sets the XML layout that will appear on the screen.
  • R.layout.activity_main: refers to the activity_main.xml layout file.
In simple words, the Activity provides the screen, and the layout defines what appears on that screen.
8.3.2 Layouts

A Layout is a container that controls how UI components are arranged on the screen. For example, on a login screen with an email field, a password field and a login button, the layout decides where these elements appear and how they are arranged. Android provides different types of layouts.

A. LinearLayout

LinearLayout arranges components in one direction: vertically (top to bottom) or horizontally (left to right).

<LinearLayout
    xmlns:android="http://schemas.android.com/apk/res/android"
    android:layout_width="match_parent"
    android:layout_height="match_parent"
    android:orientation="vertical">

    <TextView
        android:layout_width="wrap_content"
        android:layout_height="wrap_content"
        android:text="Welcome" />

    <Button
        android:layout_width="wrap_content"
        android:layout_height="wrap_content"
        android:text="Login" />

</LinearLayout>

Here, the TextView appears first, the Button appears below it, and orientation="vertical" arranges them from top to bottom.

B. RelativeLayout

RelativeLayout arranges components in relation to other components or the parent container. For example, you can place a button below a TextView.

<RelativeLayout
    xmlns:android="http://schemas.android.com/apk/res/android"
    android:layout_width="match_parent"
    android:layout_height="match_parent">

    <TextView
        android:id="@+id/title"
        android:layout_width="wrap_content"
        android:layout_height="wrap_content"
        android:text="Login" />

    <Button
        android:layout_width="wrap_content"
        android:layout_height="wrap_content"
        android:text="Submit"
        android:layout_below="@id/title" />

</RelativeLayout>

Here, the button is placed below the TextView.

C. ConstraintLayout

ConstraintLayout allows developers to position UI components using relationships called constraints. For example, you can:

  • Center a button on the screen
  • Place a text field below a heading
  • Align two buttons
  • Control spacing between components

It is commonly used in modern Android interface design because it can create complex layouts while keeping the view hierarchy relatively flat.

Important: LinearLayout, RelativeLayout, and ConstraintLayout are different ways to organize UI components. They are not buttons or text fields themselves.
8.3.3 Views

A View is the basic building block of an Android user interface. Almost every visible UI element is a View or is built using Views.

TextViewButtonEditTextImageViewCheckBoxRadioButton

Think of Views as individual objects placed inside a screen. For example, a login screen might contain three Views: the email input field, the password input field and the login button.

We will study Views in detail in Topic 7: Views.

8.3.4 TextView

TextView is used to display text on the screen, for example welcome messages, application titles, student names, product prices and instructions.

<TextView
    android:layout_width="wrap_content"
    android:layout_height="wrap_content"
    android:text="Welcome to My App"
    android:textSize="24sp" />

Understanding:

  • TextView: creates a text display component.
  • layout_width: defines its width.
  • layout_height: defines its height.
  • text: specifies the displayed text.
  • textSize: controls the text size.
Remember: TextView displays text; it is not primarily used for entering text.
8.3.5 EditText

EditText allows users to enter information into an application, for example an email address, password, username, phone number or search text.

<EditText
    android:id="@+id/email"
    android:layout_width="match_parent"
    android:layout_height="wrap_content"
    android:hint="Enter your email"
    android:inputType="textEmailAddress" />

Understanding:

  • EditText: creates an input field.
  • id: gives the component a unique identifier.
  • hint: displays temporary guidance inside the empty field.
  • inputType: specifies what kind of input is expected.

For example, textEmailAddress tells Android that the field is intended for an email address.

8.3.6 Button

A Button is a UI component that allows users to perform an action by tapping it, for example Login, Register, Submit, Save and Delete.

<Button
    android:id="@+id/loginButton"
    android:layout_width="wrap_content"
    android:layout_height="wrap_content"
    android:text="Login" />

We can connect a click action to this button using Java:

Button loginButton = findViewById(R.id.loginButton);

loginButton.setOnClickListener(v -> {

    System.out.println("Login button clicked");

});

When the user taps the button, the click listener executes the code inside it.

8.3.7 ImageView

ImageView is used to display images inside an Android application, for example profile pictures, product images, application logos, background illustrations and icons.

<ImageView
    android:layout_width="100dp"
    android:layout_height="100dp"
    android:src="@drawable/profile"
    android:contentDescription="Profile picture" />
  • ImageView: displays an image.
  • src: specifies the image resource.
  • @drawable/profile: refers to an image stored in the drawable resources.
  • contentDescription: provides a description useful for accessibility.
8.3.8 CheckBox

A CheckBox allows users to select or deselect an option. It is useful when users can choose multiple options.

Example: a registration form might ask users to select their interests: Programming, Networking, Database, Web Development. A user can select more than one checkbox.

<CheckBox
    android:layout_width="wrap_content"
    android:layout_height="wrap_content"
    android:text="Programming" />
8.3.9 RadioButton

A RadioButton allows users to select one option from a group of choices, for example Male, Female, Other. When RadioButtons are placed inside a RadioGroup, the user can select only one option in that group at a time.

<RadioGroup
    android:layout_width="wrap_content"
    android:layout_height="wrap_content">

    <RadioButton
        android:layout_width="wrap_content"
        android:layout_height="wrap_content"
        android:text="Option 1" />

    <RadioButton
        android:layout_width="wrap_content"
        android:layout_height="wrap_content"
        android:text="Option 2" />

</RadioGroup>
8.3.10 ProgressBar

A ProgressBar shows the progress of an operation, for example uploading a file, downloading a document, loading application data or processing information.

It helps users understand that the application is working instead of appearing frozen.

8.5 View and ViewGroup: What Is the Difference?

This is an important concept in Android screen design.

View

An individual UI component that displays information or accepts user input.

Examples: Button, TextView, EditText, ImageView.

ViewGroup

A special type of View that acts as a container for other Views and ViewGroups.

Examples: LinearLayout, RelativeLayout, ConstraintLayout, FrameLayout.

Example: imagine a box containing a book, a pen and a notebook. The box represents the ViewGroup, while the individual objects represent Views. In Android, LinearLayout is the container, and TextView, Button and ImageView are its children. This arrangement is called a View Hierarchy.

8.6 XML Layout and Java Code: How Do They Work Together?

Android developers commonly use XML to design the screen and Java or Kotlin to control its behavior. Let's understand this with a login screen.

Step 1: Design the screen using XML

Create activity_main.xml.

<LinearLayout
    xmlns:android="http://schemas.android.com/apk/res/android"
    android:layout_width="match_parent"
    android:layout_height="match_parent"
    android:orientation="vertical"
    android:padding="20dp">

    <TextView
        android:layout_width="wrap_content"
        android:layout_height="wrap_content"
        android:text="Student Login"
        android:textSize="25sp" />

    <EditText
        android:id="@+id/email"
        android:layout_width="match_parent"
        android:layout_height="wrap_content"
        android:hint="Enter email"
        android:inputType="textEmailAddress" />

    <Button
        android:id="@+id/loginButton"
        android:layout_width="match_parent"
        android:layout_height="wrap_content"
        android:text="Login" />

</LinearLayout>

This XML creates three components: the TextView displays the heading, the EditText accepts the email, and the Button allows the user to perform an action.

Step 2: Control the screen using Java

Create or open MainActivity.java.

import android.os.Bundle;
import android.widget.Button;
import android.widget.EditText;
import android.widget.Toast;

import androidx.appcompat.app.AppCompatActivity;

public class MainActivity extends AppCompatActivity {

    @Override
    protected void onCreate(Bundle savedInstanceState) {

        super.onCreate(savedInstanceState);

        setContentView(R.layout.activity_main);

        EditText email = findViewById(R.id.email);

        Button loginButton = findViewById(R.id.loginButton);

        loginButton.setOnClickListener(v -> {

            String userEmail = email.getText().toString();

            Toast.makeText(
                this,
                "Welcome " + userEmail,
                Toast.LENGTH_SHORT
            ).show();

        });
    }
}
Step 3: Understand how everything works

When the application starts:

  1. Android opens MainActivity.
  2. setContentView() loads the XML layout.
  3. The TextView, EditText, and Button appear on the screen.
  4. findViewById() finds the email field and button using their IDs.
  5. setOnClickListener() waits for the user to click Login.
  6. When the user clicks, the program reads the email.
  7. A Toast message displays the entered email.
Important concept: XML defines how the screen looks, while Java/Kotlin defines how the screen behaves. This separation makes application development easier to organize.

Adapting to Display Orientation in Android

Portrait, landscape and layouts that fit both

9.1 Introduction

Android applications run on devices with different screen sizes and orientations. For example, when you hold your mobile phone normally, the screen is usually vertical. When you rotate your phone sideways, the screen becomes horizontal.

An Android application should adjust its user interface according to the screen orientation so that users can easily view and use the application.

Definition: Adapting to Display Orientation is the process of adjusting an application's user interface according to the direction in which a device is held, such as portrait or landscape mode.

9.2 What Is Screen Orientation?

Screen orientation refers to the direction in which the content of a device's screen is displayed. Android mainly supports two commonly used orientations: portrait and landscape.

9.2.1 Portrait Orientation

The device is held vertically.

  • The screen is taller than it is wide
  • Content is arranged mainly from top to bottom
  • Commonly used for reading, messaging, browsing, and social media applications

Example: WhatsApp on a phone held normally usually displays its interface in portrait orientation.

9.2.2 Landscape Orientation

The device is held horizontally.

  • The screen is wider than it is tall
  • Content can be arranged from left to right
  • It provides more horizontal space
  • Commonly useful for videos, games, presentations, and maps

Example: when you rotate your phone while watching a video, the video may expand to use the wider screen.

9.3 Why Is Adapting to Screen Orientation Important?

Imagine that you create a student management application. In portrait mode, the application displays the student name at the top, the student picture below the name, attendance information and result information. Now imagine the user rotates the phone into landscape mode. If the application does not adjust its layout, some content may become difficult to see or may require excessive scrolling. Adapting the interface solves this problem.

Main reasons

1. Better User Experience

Users can use the application comfortably in both orientations.

2. Better Use of Screen Space

Android devices use sensors, particularly the accelerometer, to detect changes in device position. The accelerometer measures acceleration along different directions. Managing Changes to Screen Orientation in Android

What happens when the phone rotates, and how to keep user data

10.1 Introduction

In the previous topic, we learned about screen orientation and how Android applications adjust their layouts between Portrait and Landscape modes. Now we will learn what happens internally when a user rotates a mobile phone and how Android manages these changes.

Imagine that you are using a student management application and you enter this information:

  • Student name: Muhammad
  • Email: muhammad@example.com
  • Phone number: 03001234567

Suddenly, you rotate your phone from portrait to landscape mode. The screen changes its orientation. But what happens to the information you entered? Will it remain there, or will it disappear? This is the main problem that developers must understand when managing orientation changes.

Definition: Managing Changes to Screen Orientation is the process of handling changes in an Android device's display direction while maintaining the application's functionality and preserving user data.

10.2 What Happens When We Rotate a Phone?

When a user rotates a phone, Android detects a configuration change. By default, an Activity is usually destroyed and recreated to adjust to the new configuration. Let's understand this process step by step.

  1. Application is running: the user opens an application in portrait mode. The Activity is running, and the user is interacting with the screen.
  2. User rotates the phone: the device is rotated from portrait to landscape mode. Android detects that the device configuration has changed.
  3. Old Activity is destroyed: in the normal configuration-change process, Android destroys the current Activity instance. Its lifecycle methods are called, including onPause(), onStop() and onDestroy().
  4. New Activity is created: Android creates a new Activity instance. The onCreate() method runs again.
  5. New layout is loaded: Android selects the appropriate layout for the new orientation. Portrait: res/layout/activity_main.xml. Landscape: res/layout-land/activity_main.xml.
  6. Application continues: the Activity displays the new layout. If the developer has properly saved and restored the required information, the user can continue working without losing important data.

10.3 What Is Activity Recreation?

Activity Recreation means destroying an existing Activity instance and creating a new Activity instance.

Android may recreate an Activity when certain device configurations change. Examples include:

  1. Screen orientation changes
  2. Device language changes
  3. Screen size changes
  4. Certain display configuration changes

Why does Android recreate an Activity? Different configurations may require different resources and layouts. For example, a portrait screen may use a vertical layout, while a landscape screen may use a horizontal layout. Recreating the Activity allows Android to initialize the interface using the new configuration.

Important: Activity recreation does not necessarily mean that the entire application is closed. The Activity is recreated while the application process and other components may continue running.

10.4 Problems Caused by Activity Recreation

Activity recreation can create problems if developers do not manage data properly. Three common problems:

10.4.1 Loss of User Input

Suppose a user is filling out a registration form and enters Name: Muhammad, Email: muhammad@example.com, Age: 22. After rotation, the Activity is recreated. If the application does not preserve the entered information, the fields may become empty. This creates a poor user experience.

10.4.2 Loss of Temporary Data

Temporary information may include the current search text, selected tab, current question number, selected item and form progress. If it is not saved, the application may return to its initial state after recreation.

10.4.3 Repeating Operations

If an application is loading information from a server and the developer does not manage the operation correctly, Activity recreation may cause unnecessary repeated work. For example, the application might request the same information again, wasting network resources and processing time.

10.5 How to Manage Orientation Changes

Android provides different techniques for managing Activity recreation and preserving application state. Let's understand the most important methods.

10.5.1 Using onSaveInstanceState()

onSaveInstanceState() is a lifecycle callback that allows developers to save a small amount of temporary UI state before an Activity may be destroyed. For example, we can save entered text, selected options, the current screen position and the current question number.

Example: the user enters a name into an EditText, and we want to save that name before the Activity is recreated.

@Override
protected void onSaveInstanceState(Bundle outState) {

    super.onSaveInstanceState(outState);

    EditText nameField = findViewById(R.id.name);

    String name = nameField.getText().toString();

    outState.putString("student_name", name);
}

Let's understand the code:

  1. onSaveInstanceState(): called when Android is saving the Activity's state.
  2. Bundle outState: a container used to store small amounts of data as key-value pairs.
  3. findViewById(): finds the EditText component using its ID.
  4. getText().toString(): gets the text entered by the user and converts it into a String.
  5. putString(): stores the name inside the Bundle. Key: "student_name"; value: the entered student name.
10.5.2 Using onCreate() to Restore Data

Saving data is not enough. We must also restore it when the Activity is recreated. We can use the Bundle received by onCreate().

@Override
protected void onCreate(Bundle savedInstanceState) {

    super.onCreate(savedInstanceState);

    setContentView(R.layout.activity_main);

    EditText nameField = findViewById(R.id.name);

    if (savedInstanceState != null) {

        String savedName =
            savedInstanceState.getString("student_name");

        nameField.setText(savedName);
    }
}

Let's understand this code:

  1. savedInstanceState: contains the previously saved state when one is available.
  2. if (savedInstanceState != null): checks whether saved information exists.
  3. getString(): retrieves the saved student name using its key.
  4. setText(): places the saved name back into the EditText field.

Result: when the user rotates the phone, the Activity saves the entered name, Android recreates the Activity, the new Activity retrieves the saved name and the EditText displays the previous name. The user does not need to enter the name again.

10.6 Understanding Bundle in Android

A Bundle is an Android class used to store and transfer small amounts of data using key-value pairs.

Think of it like a small storage box. You put information inside using a key, and later retrieve that information using the same key.

Bundle data = new Bundle();

data.putString("name", "Muhammad");

data.putInt("age", 22);

data.putBoolean("isStudent", true);

Here we store three values:

KeyValueData type
nameMuhammadString
age22Integer
isStudenttrueBoolean

To retrieve the information:

String name = data.getString("name");

int age = data.getInt("age");

boolean student = data.getBoolean("isStudent");
Remember: Bundle is suitable for small, temporary state information. It is not intended to store large files or permanent application data.

10.7 Using ViewModel to Preserve Data

Another important Android technique is using a ViewModel. A ViewModel is a component that stores and manages UI-related data. One of its important benefits is that it survives Activity recreation caused by configuration changes, such as screen rotation.

Example: a user is completing a long registration form, and the application stores the entered information in a ViewModel. When the phone rotates:

  1. The Activity is recreated.
  2. The old Activity instance is destroyed.
  3. The ViewModel remains available.
  4. The new Activity obtains the existing ViewModel.
  5. The application displays the previously stored information.

Simple Java example

public class StudentViewModel extends ViewModel {

    private String studentName = "";

    public void setStudentName(String name) {

        studentName = name;
    }

    public String getStudentName() {

        return studentName;
    }
}

The Activity can obtain the ViewModel:

StudentViewModel model =
    new ViewModelProvider(this)
        .get(StudentViewModel.class);

The Activity can save a name, and retrieve it later:

model.setStudentName("Muhammad");

String name = model.getStudentName();

When the Activity is recreated due to a configuration change, the same ViewModel instance is retained.

Important distinction: onSaveInstanceState() saves small pieces of temporary state in a Bundle. ViewModel manages UI-related data across configuration changes. Neither one alone guarantees permanent data storage if the application process is killed. For important permanent information, developers can use databases or other persistent storage solutions.

10.8 Using onConfigurationChanged()

Android also provides a method called onConfigurationChanged(). It is used when an application wants to handle certain configuration changes itself instead of allowing Android to recreate the Activity for those changes.

@Override
public void onConfigurationChanged(Configuration newConfig) {

    super.onConfigurationChanged(newConfig);

    if (newConfig.orientation ==
            Configuration.ORIENTATION_LANDSCAPE) {

        // Handle landscape mode

    } else if (newConfig.orientation ==
            Configuration.ORIENTATION_PORTRAIT) {

        // Handle portrait mode
    }
}

This method checks whether the device is in portrait or landscape orientation. However, simply overriding this method does not stop Activity recreation. Developers must also declare the relevant configuration changes in the Activity's manifest.

<activity
    android:name=".MainActivity"
    android:configChanges="orientation|screenSize" />

Now the Activity can receive these declared configuration changes through onConfigurationChanged() rather than being automatically recreated for them.

Important: this approach should be used carefully. Developers become responsible for updating the interface and handling the affected resources correctly. For most applications, allowing Android to recreate the Activity and using ViewModel and saved state is the preferred approach.

        savedInstanceState.getString("student_name");

}

It is called after onStart() when there is saved instance state to restore. You can restore state in either onCreate() or onRestoreInstanceState(), depending on your application design.

11.2 Definition of User Interface

User Interface (UI) is the visual part of an application through which users interact with the system.

In simple words, UI is everything that a user can see and use on the screen, such as buttons, text, images, menus, and input fields.

11.3.5 Attractive Appearance

Displaying Notifications in Android

Channels, notification types and how to create them in Java

13.1 Introduction

Notifications are an important feature of Android applications. They allow an application to send information or alerts to users even when the application is not currently open on the screen. For example:

  • WhatsApp displays a notification when someone sends you a message.
  • YouTube displays a notification when a new video is available.
  • Banking applications notify users about transactions.
  • Shopping applications notify users about orders and deliveries.
  • Calendar applications remind users about upcoming events.

You do not need to open an application every time to check for new information. Notifications bring important information directly to the user's device.

13.2 Definition of Notification

A Notification is a message or alert displayed by an Android application outside its normal application screen to inform the user about an event, update, reminder, or other important information.

In simple words, a notification is a message that an application sends to inform the user about something.

Example: suppose you are using another application and someone sends you a WhatsApp message. WhatsApp can display a notification such as: WhatsApp · Now · New message — You have received a new message. You can see this notification without opening WhatsApp.

13.3 Why Are Notifications Important?

Notifications help applications communicate with users.

Provide Important Information

Applications can inform users about important events. For example, a banking application can notify a user when money is deposited or withdrawn.

Save Time

Users do not need to open an application repeatedly to check for updates. For example, a student can receive an assignment reminder directly on their mobile phone.

Provide Reminders

Applications can remind users about important activities:

  • Class schedules
  • Meetings
  • Exams
  • Medicine reminders
  • Payment deadlines
Improve Communication

Messaging applications use notifications to inform users about incoming messages and calls.

Provide Real-Time Updates

Applications can send information about events as they happen. For example, a food delivery application can notify a customer when an order is confirmed, prepared, or out for delivery.

13.4 Where Do Android Notifications Appear?

Android notifications can appear in different places depending on the device, Android version, notification settings, and application configuration.

Notification Drawer

The area where users can see their received notifications. Users normally open it by swiping down from the top of the screen. It can display notifications from WhatsApp, Gmail, YouTube, Facebook, banking applications and more.

Status Bar Notification Icon

When an application generates a notification, Android may display a small icon in the status bar. For example, a messaging application may display its notification icon at the top of the screen. The user can pull down the notification drawer to read more information.

Heads-Up Notification

A temporary notification that appears over the current screen. For example, while playing a game, a new message notification may appear at the top of the screen. It allows users to notice important information without leaving their current application. However, heads-up notifications depend on notification importance, device settings, and Android behavior.

Lock Screen Notification

Notifications can also appear on the device's lock screen. Users can control whether notification content is visible, hidden, or completely disabled on the lock screen.

13.7 Notification Channels

Notification Channels are an important feature introduced in Android 8.0 (API level 26).

A Notification Channel is a category used to organize notifications from an application. It allows users to control different types of notifications separately.
Example: imagine a university application that sends different notifications. It may create these channels: Exam Notifications, Assignment Notifications, General Announcements and Fee Reminders. A user may want to receive exam notifications but disable general announcements. Notification Channels allow this type of control.

Why are Notification Channels needed? Before Notification Channels, users had fewer options to manage different notification categories separately. Notification Channels provide:

  • Better notification organization
  • User control over notification categories
  • Separate notification settings
  • Different importance levels
  • Better management of unwanted notifications

Importance levels of Notification Channels. When creating a channel, developers specify its importance. Some commonly used importance levels are:

ImportanceMeaning
IMPORTANCE_HIGHImportant notifications that may appear as heads-up alerts
IMPORTANCE_DEFAULTNormal notification importance
IMPORTANCE_LOWLower-priority notifications
IMPORTANCE_MINVery low-priority notifications

There is also IMPORTANCE_NONE, which represents a channel with no notification importance.

Important: after a channel is created, its importance is generally controlled by the user. An application cannot freely change the channel's importance whenever it wants.

13.8 How to Create and Display a Notification in Android

Now let's understand how developers create notifications using Java. There are several steps involved.

Step 1: Create a Notification Channel

For Android 8.0 and later, an application must create a Notification Channel before sending notifications through it.

private void createNotificationChannel() {

    if (Build.VERSION.SDK_INT >= Build.VERSION_CODES.O) {

        CharSequence name = "Student Notifications";

        String description = "Notifications about student activities";

        int importance = NotificationManager.IMPORTANCE_DEFAULT;

        NotificationChannel channel =
            new NotificationChannel(
                "student_channel",
                name,
                importance
            );

        channel.setDescription(description);

        NotificationManager manager =
            getSystemService(NotificationManager.class);

        manager.createNotificationChannel(channel);
    }
}

Understand each part:

Check Android version – this checks whether the device is running Android 8.0 or a newer version. Notification Channels are required for Android 8.0 and later.

if (Build.VERSION.SDK_INT >= Build.VERSION_CODES.O)

Channel name – the name users can see in notification settings.

CharSequence name = "Student Notifications";

Channel description – explains the purpose of the channel.

String description = "Notifications about student activities";

Importance – sets the channel's initial importance.

int importance = NotificationManager.IMPORTANCE_DEFAULT;

Create channel – creates the channel with a unique channel ID, a channel name and an importance level.

NotificationChannel channel =
    new NotificationChannel(
        "student_channel",
        name,
        importance
    );

Register the channel – registers the channel with Android.

manager.createNotificationChannel(channel);
Step 2: Create a Notification

After creating the channel, developers can build a notification. Android provides NotificationCompat.Builder through the AndroidX Core library.

NotificationCompat.Builder builder =
    new NotificationCompat.Builder(this, "student_channel")
        .setSmallIcon(R.drawable.ic_notification)
        .setContentTitle("Assignment Reminder")
        .setContentText("Submit your assignment tomorrow.")
        .setPriority(NotificationCompat.PRIORITY_DEFAULT)
        .setAutoCancel(true);

Let's understand its methods.

MethodPurpose
NotificationCompat.Builder()Starts creating a notification
setSmallIcon()Sets the notification icon
setContentTitle()Sets the notification title
setContentText()Sets the notification message
setPriority()Sets the priority for older Android versions
setAutoCancel(true)Dismisses the notification when the user taps it
Notice that setPriority() is mainly relevant to older Android versions. On Android 8.0 and later, the channel's importance controls notification behavior.
Step 3: Display the Notification

After creating the notification, we need to send it to Android's notification system.

NotificationManagerCompat manager =
    NotificationManagerCompat.from(this);

manager.notify(1, builder.build());

Explanation:

  • NotificationManagerCompat.from(this) gets access to the notification manager.
  • notify() sends the notification.
  • 1 is the notification ID.
  • builder.build() creates the final notification object.

The notification ID helps identify a notification. Reusing the same ID can update an existing notification instead of creating a separate one.

public class MainActivity extends AppCompatActivity {

    private static final String CHANNEL_ID = "student_channel";

    @Override
    protected void onCreate(Bundle savedInstanceState) {

        super.onCreate(savedInstanceState);

        setContentView(R.layout.activity_main);

        createNotificationChannel();

        Button button = findViewById(R.id.btnNotify);

        button.setOnClickListener(v -> {

            showNotification();

        });
    }

    private void createNotificationChannel() {

        if (Build.VERSION.SDK_INT >= Build.VERSION_CODES.O) {

            NotificationChannel channel =
                new NotificationChannel(

                    NotificationManager.IMPORTANCE_DEFAULT
                );

                getSystemService(NotificationManager.class);

            manager.createNotificationChannel(channel);
        }
    }

    private void showNotification() {

        NotificationCompat.Builder builder =
            new NotificationCompat.Builder(this, CHANNEL_ID)
                .setSmallIcon(R.drawable.ic_notification)
                .setContentTitle("Assignment Reminder")
                .setContentText("Submit your assignment tomorrow.")
                .setPriority(NotificationCompat.PRIORITY_DEFAULT)
                .setAutoCancel(true);

        NotificationManagerCompat manager =
            NotificationManagerCompat.from(this);

        if (Build.VERSION.SDK_INT < 33 ||
            checkSelfPermission(
                android.Manifest.permission.POST_NOTIFICATIONS
            ) == android.content.pm.PackageManager.PERMISSION_GRANTED) {

            manager.notify(1, builder.build());
        }
    }
}

What happens when this application runs?

  1. The application opens.
  2. The onCreate() method runs.
  3. The notification channel is created.
  4. The user sees the Show Notification button.
  5. The user taps the button.
  6. The showNotification() method runs.
  7. Android receives the notification.
  8. The user can see the notification in the notification drawer.
Important requirements for this example:
  • Add the AndroidX Core dependency to the project if it is not already included.
  • Add a valid small notification icon named ic_notification to the drawable resources.
  • For Android 13 (API 33) and later, declare and request notification permission before displaying notifications.

13.10 Notification Permission in Android

Android 13 introduced a runtime notification permission called POST_NOTIFICATIONS. This means applications targeting Android 13 or later must request permission from the user before sending ordinary notifications.

Add this permission to AndroidManifest.xml:

<uses-permission
    android:name="android.permission.POST_NOTIFICATIONS" />

Then request permission in Java:

if (Build.VERSION.SDK_INT >= 33) {

    requestPermissions(
        new String[]{
            android.Manifest.permission.POST_NOTIFICATIONS
        },
        100
    );
}

The user can choose whether to allow notifications. Understand the difference:

  • Manifest permission declares that the application needs notification permission.
  • Runtime permission request asks the user to grant that permission.
  • Notification Channel organizes the notifications after the application has permission.
These are three separate concepts.

13.11 Notification Actions

Notifications can also contain buttons that allow users to perform actions. For example, a messaging notification may contain a Reply button. A user can tap Reply and respond without opening the complete application. Android uses components such as PendingIntent, NotificationCompat.Action and RemoteInput.

What is PendingIntent? A PendingIntent is a special object that allows Android or another application component to perform an action on behalf of your application at a later time. For example, it can open an Activity when a notification is tapped, start a Service, or perform a broadcast action.

Example: when a user taps a notification, the application can open its MainActivity.

Intent intent = new Intent(this, MainActivity.class);

PendingIntent pendingIntent =
    PendingIntent.getActivity(
        this,
        0,
        intent,
        PendingIntent.FLAG_UPDATE_CURRENT |
        PendingIntent.FLAG_IMMUTABLE
    );

Then attach it to the notification:

builder.setContentIntent(pendingIntent);

Now tapping the notification can open MainActivity.

Listening for UI Notifications in Android

Handling user interface events with event listeners

14.1 Introduction

In Android application development, users interact with an application by performing different actions. For example:

  • Tapping a button
  • Typing text into an input field
  • Selecting a checkbox
  • Moving a slider
  • Touching or swiping the screen
  • Selecting an item from a list

When a user performs one of these actions, Android generates an event. An application can listen for these events and perform an appropriate operation. This process is called Listening for UI Events or Handling User Interface Events.

For example, imagine a student login application. When a student enters a username and taps the Login button, the application listens for that click and checks the entered information. Without event listening, the application would not know when the user wants to perform an action.

14.2 Definition of Listening for UI Events

Listening for UI Events is the process of detecting user actions on interface elements and responding to those actions by executing specific code.

In simple words, it means that an application waits for the user to perform an action and then responds to it.

Example: suppose an application contains a button called Submit.
  1. The application displays the button.
  2. The user taps the button.
  3. Android detects the click event.
  4. The application's event listener receives the event.
  5. The application executes the required code.
  6. A message appears on the screen.
This is how event listening works.

14.3 What Is an Event?

An Event is an action or occurrence detected by an application. Events can be generated by users or by the system.

Examples of user events

EventMeaning
ClickUser taps a button
Long ClickUser presses and holds an element
TouchUser touches the screen
Text ChangeUser enters or removes text
Focus ChangeAn element gains or loses focus
Selection ChangeUser selects or changes an option
ScrollUser moves through scrollable content

Examples of system events

  • Screen orientation changes
  • Network connection changes
  • Battery level changes
  • Application receives certain system callbacks

This topic mainly focuses on events generated through Android user interface elements.

14.4 What Is an Event Listener?

An Event Listener is an object or mechanism that waits for a particular event and executes code when that event occurs.

For example, a Button can have a click listener. When the user clicks the button, the listener runs the code written inside it. Android provides different event listener interfaces for different types of user interactions. The general working process is:

  1. User performs an action: for example, taps a button.
  2. Android detects an event: the click event occurs.
  3. Event Listener receives the event: the click listener runs.
  4. Application executes code: displays a message or performs an operation.

14.5 Types of Event Listeners in Android

Android provides different listeners to handle different user actions. Let's understand each one.

14.5.1 OnClickListener

OnClickListener is used to detect when a user taps or clicks a View. It is commonly used with Buttons, ImageViews, TextViews and other clickable Views. For example, suppose we have a button called Click Me.

XML:

<Button
    android:id="@+id/btnClick"
    android:layout_width="wrap_content"
    android:layout_height="wrap_content"
    android:text="Click Me" />

Java:

Button button = findViewById(R.id.btnClick);

button.setOnClickListener(v -> {

    Toast.makeText(
        this,
        "Button Clicked",
        Toast.LENGTH_SHORT
    ).show();

});

Explanation:

  1. findViewById() finds the button.
  2. setOnClickListener() attaches a click listener to it.
  3. When the user taps the button, the listener executes.
  4. Toast displays the message.
Real-life example: a Login button listens for a click and starts the login process.
14.5.2 OnLongClickListener

OnLongClickListener detects when a user presses and holds a View for a period of time. It is commonly used for showing additional options, selecting items, displaying context menus, and deleting or managing items.

Button button = findViewById(R.id.btnClick);

button.setOnLongClickListener(v -> {

    Toast.makeText(
        this,
        "Button Pressed for a Long Time",
        Toast.LENGTH_SHORT
    ).show();

    return true;
});

Explanation:

  • setOnLongClickListener() registers a long-click listener.
  • The code runs when the user presses and holds the button.
  • return true means the event has been handled.
Click

User taps an element.

Long Click

User presses and holds an element.

14.5.3 OnTouchListener

OnTouchListener detects touch actions performed on a View. It is useful when developers need more control over touch interaction, for example detecting finger movement, dragging an object, detecting touch-down and touch-up actions, and creating drawing applications.

View view = findViewById(R.id.myView);

view.setOnTouchListener((v, event) -> {

    if (event.getAction() == MotionEvent.ACTION_DOWN) {

        Toast.makeText(
            this,
            "Screen Touched",
            Toast.LENGTH_SHORT
        ).show();
    }

    return true;
});

setOnTouchListener() listens for touch events. Android provides different touch actions:

ActionMeaning
ACTION_DOWNFinger touches the screen
ACTION_MOVEFinger moves on the screen
ACTION_UPFinger is lifted from the screen
ACTION_CANCELCurrent touch operation is cancelled
Example in real life: a drawing application uses touch events to detect where the user moves their finger.
14.5.4 OnFocusChangeListener

OnFocusChangeListener detects when a View gains or loses focus. Focus means that a View is currently selected to receive keyboard input or interaction. It is commonly used with EditText.

EditText editText = findViewById(R.id.edtName);

editText.setOnFocusChangeListener((v, hasFocus) -> {

    if (hasFocus) {

        Toast.makeText(
            this,
            "Name Field Selected",
            Toast.LENGTH_SHORT
        ).show();

    } else {

        Toast.makeText(
            this,
            "Name Field Unselected",
            Toast.LENGTH_SHORT
        ).show();
    }
});

Explanation:

  • If hasFocus is true, the field has gained focus.
  • If hasFocus is false, the field has lost focus.
Real-life example: a registration form can check a field when the user moves away from it.
14.5.5 TextWatcher

TextWatcher listens for changes in the text entered into an EditText. It is useful when an application needs to respond immediately as a user types, for example search suggestions, password validation, character counting, and checking whether an input field is empty.

EditText editText = findViewById(R.id.edtName);

editText.addTextChangedListener(new TextWatcher() {

    @Override
    public void beforeTextChanged(
        CharSequence s,
        int start,
        int count,
        int after
    ) {
    }

    @Override
    public void onTextChanged(
        CharSequence s,
        int start,
        int before,
        int count
    ) {

        Toast.makeText(
            MainActivity.this,
            "Text Changed",
            Toast.LENGTH_SHORT
        ).show();
    }

    @Override
    public void afterTextChanged(Editable s) {
    }
});

Understand its three methods:

MethodPurpose
beforeTextChanged()Called before the text changes
onTextChanged()Called when the text changes
afterTextChanged()Called after the text has changed

For example, if a user types Muhammad, these methods are called as the text is entered.

14.5.6 OnCheckedChangeListener

This listener detects when a CheckBox or Switch changes its checked state. For example, a user can turn notifications ON or OFF.

CheckBox checkBox = findViewById(R.id.chkTerms);

checkBox.setOnCheckedChangeListener(
    (buttonView, isChecked) -> {

        if (isChecked) {

            Toast.makeText(
                this,
                "Terms Accepted",
                Toast.LENGTH_SHORT
            ).show();

        } else {

            Toast.makeText(
                this,
                "Terms Not Accepted",
                Toast.LENGTH_SHORT
            ).show();
        }
    }
);

Explanation:

  • setOnCheckedChangeListener() listens for selection changes.
  • isChecked tells us whether the CheckBox is selected.
  • If true, the CheckBox is selected. If false, the CheckBox is unselected.
14.5.7 OnItemSelectedListener

This listener detects when a user selects an item from a Spinner or another suitable selection-based component. For example, a university application contains a semester selection list: Semester 1, Semester 2, Semester 3 and Semester 4. When the user selects Semester 4, the application can display the selected semester.

Spinner spinner = findViewById(R.id.spinnerSemester);

spinner.setOnItemSelectedListener(
    new AdapterView.OnItemSelectedListener() {

        @Override
        public void onItemSelected(
            AdapterView<?> parent,
            View view,
            int position,
            long id
        ) {

            String selected =
                parent.getItemAtPosition(position).toString();

            Toast.makeText(
                MainActivity.this,
                selected,
                Toast.LENGTH_SHORT
            ).show();
        }

        @Override
        public void onNothingSelected(AdapterView<?> parent) {
        }
    }
);

Explanation:

  • onItemSelected() runs when an item is selected.
  • position tells us the item's position in the list.
  • getItemAtPosition() gets the selected item.
  • onNothingSelected() handles the situation where no item is selected.
Note that a Spinner can also trigger an initial selection callback when it is first populated, so developers should account for that when necessary.

14.6 Difference Between Event and Event Listener

These two terms are related, but they are not the same.

14.8 Practical Example: Student Registration Form

Let's create a simple example that uses multiple event listeners together. Imagine a registration form containing a name field, a terms and conditions checkbox and a Submit button. The application should:

  1. Listen when the user enters a name.
  2. Detect whether the user accepts the terms.
  3. Listen when the user clicks Submit.
  4. Display an appropriate message.
Step 1: XML Layout

Create activity_main.xml.

<?xml version="1.0" encoding="utf-8"?>

<LinearLayout
    xmlns:android="http://schemas.android.com/apk/res/android"
    android:layout_width="match_parent"
    android:layout_height="match_parent"
    android:orientation="vertical"
    android:padding="20dp">

    <EditText
        android:id="@+id/edtName"
        android:layout_width="match_parent"
        android:layout_height="wrap_content"
        android:hint="Enter your name" />

    <CheckBox
        android:id="@+id/chkTerms"
        android:layout_width="wrap_content"
        android:layout_height="wrap_content"
        android:text="I accept the terms" />

    <Button
        android:id="@+id/btnSubmit"
        android:layout_width="match_parent"
        android:layout_height="wrap_content"
        android:text="Submit" />

</LinearLayout>
Step 2: Java Code

Create the event listeners inside MainActivity.java.

package com.example.studentapp;

import android.os.Bundle;
import android.widget.Button;
import android.widget.CheckBox;
import android.widget.EditText;
import android.widget.Toast;

import androidx.appcompat.app.AppCompatActivity;

public class MainActivity extends AppCompatActivity {

    EditText name;
    CheckBox terms;
    Button submit;

    @Override
    protected void onCreate(Bundle savedInstanceState) {

        super.onCreate(savedInstanceState);

        setContentView(R.layout.activity_main);

        name = findViewById(R.id.edtName);
        terms = findViewById(R.id.chkTerms);
        submit = findViewById(R.id.btnSubmit);

        submit.setOnClickListener(v -> {

            String studentName =
                name.getText().toString().trim();

            if (studentName.isEmpty()) {

                Toast.makeText(
                    this,
                    "Please enter your name",
                    Toast.LENGTH_SHORT
                ).show();

            } else if (!terms.isChecked()) {

                Toast.makeText(
                    this,
                    "Please accept the terms",
                    Toast.LENGTH_SHORT
                ).show();

            } else {

                Toast.makeText(
                    this,
                    "Registration Successful",
                    Toast.LENGTH_SHORT
                ).show();
            }
        });
    }
}
Step 3: Understand the Working
  1. Android displays the registration form.
  2. The user enters their name.
  3. The user selects the CheckBox.
  4. The user clicks Submit.
  5. The click listener checks the entered information.

ConditionResult
Name is emptyPlease enter your name
Terms are not acceptedPlease accept the terms
Both conditions are satisfiedRegistration Successful
