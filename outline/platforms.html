Platforms and architecture

Mobile Application Development Platform

Tools, components, types and examples

1.1 Introduction to Mobile Application Development

Before understanding a Mobile Application Development Platform, we first need to understand what mobile application development means.

Mobile Application Development is the process of creating software applications that run on mobile devices such as smartphones and tablets.

These applications help users perform different tasks, such as:

  • Sending messages
  • Making phone calls
  • Watching videos
  • Shopping online
  • Using banking services
  • Playing games
  • Learning through educational applications
  • Booking tickets and ordering food

Examples of mobile applications:

WhatsAppFacebookInstagramYouTubeGoogle MapsDarazSnapchat

In simple words, mobile application development means designing, developing, testing, and maintaining applications for mobile devices.

1.2 What is a Mobile Application Development Platform?

Definition: A Mobile Application Development Platform (MADP) is a collection of software tools, technologies, frameworks, libraries, and services that developers use to create, test, deploy, and maintain mobile applications.

In simple words, it is an environment that provides developers with the necessary tools to build mobile applications without creating everything from the beginning.

Example: Suppose you want to develop a mobile application like WhatsApp. You need:
  1. A programming language to write the application.
  2. A development environment to write and manage code.
  3. A framework to build the user interface.
  4. Tools to connect the application with a server.
  5. Tools to test the application.
  6. Tools to publish the application.
A MADP provides many of these tools and services in one development environment.

1.3 Why Do We Need Mobile Application Development Platforms?

Developing a mobile application is not just about writing code. Developers need to manage designing, programming, testing, security, and deployment. These platforms make these activities easier.

1. Easy Application Development

Ready-made tools, libraries and frameworks mean developers do not write every feature from scratch.

Example: a login screen can use ready-made text fields, password fields, buttons and checkboxes.

2. Faster Development

Reusable components and tools reduce development time.

Example: use an existing camera library instead of writing all camera code.

3. Cross-Platform Development

Some platforms let developers build for several operating systems using a shared codebase (Android and iOS), for example with Flutter or React Native.

4. Easy Testing and Debugging

Testing checks whether the application works correctly. Debugging means finding and fixing errors.

Example: if a login button does not work, debugging tools help find the problem.

5. Better User Interface Design

Ready-made elements: buttons, menus, navigation bars, images, forms, dialog boxes.

6. Application Deployment

Deployment means making an application available for users.

  • Android apps: Google Play Store
  • iOS apps: Apple App Store
7. Application Maintenance

After publishing, developers fix bugs, improve performance, add features and provide security updates.

1.4 Main Components of a MADP

1. Integrated Development Environment (IDE)

Software that provides tools to write, edit, manage, and debug program code.

Examples: Android Studio, Eclipse, Xcode, Visual Studio.

Main functions:

  • Writing program code
  • Finding programming errors
  • Managing project files
  • Running applications
  • Debugging applications
2. Software Development Kit (SDK)

A collection of tools, libraries, documentation, and other resources used to develop applications for a particular platform.

Example: the Android SDK includes:

  • Development tools
  • Android APIs
  • Debugging tools
  • Emulator support
  • Platform libraries
3. Framework

A collection of pre-written code, tools, and rules that provides a structure for developing applications.

Examples: Flutter, React Native, .NET MAUI, Ionic.

Example: React Native provides components for building mobile interfaces.

4. Application Programming Interface (API)

Allows different software components to communicate and exchange information. It works like a bridge between two software systems.

Example: a weather app sends a request to a weather API, which returns temperature, weather conditions, humidity and wind speed. The app then displays them.

5. Testing Tools

Check whether an application works correctly before release.

  • Functional testing
  • Performance testing
  • Security testing
  • Compatibility testing
  • User interface testing
6. Emulator and Simulator

Let developers test apps without always using a physical device.

Emulator: reproduces the hardware and software behavior of a target device.

Simulator: imitates the behavior of a device or environment, generally without reproducing all its hardware.

Example: Android Emulator runs Android apps on a computer.

1.5 Types of Mobile Application Development Platforms

1. Native Application Development

Creating applications specifically for one operating system. Android apps use Kotlin or Java; iOS apps use Swift or Objective-C.

Advantages
  • High performance
  • Better access to device hardware
  • Better integration with the operating system
  • Smooth user experience
Disadvantages
  • Separate development for Android and iOS
  • Can take more time
  • Maintenance may be more expensive
2. Cross-Platform Application Development

Creating applications that run on multiple operating systems using a shared codebase, for example with Flutter or React Native.

Advantages
  • Code can be reused
  • Less development time
  • Reduced development cost
  • Easier maintenance of shared features
Disadvantages
  • Some platform-specific features need additional code
  • Performance may vary by framework and app
  • Native integration can be more complicated
3. Hybrid Application Development

Combines web technologies (HTML, CSS, JavaScript) with mobile application packaging. The interface runs inside a native container or WebView.

Advantages
  • Uses common web technologies
  • Code can be reused
  • Development can be less expensive
  • Easier for web developers to learn
Disadvantages
  • Lower performance for graphics-intensive apps
  • Some device features require plugins
  • User experience may differ from fully native apps

1.6 Examples of Popular Platforms

Android Studio

Google's official IDE for Android application development. Supports Kotlin and Java.

Xcode

Apple's IDE used to develop applications for iOS and other Apple platforms.

Flutter

Google's UI framework used to build applications for multiple platforms.

React Native

A framework for developing mobile applications using JavaScript or TypeScript and React.

Eclipse

An IDE historically used for Android development with the Android Development Tools (ADT) plugin.

1.7 Advantages and 1.8 Disadvantages

Advantages
  1. Reduced Development Time: ready-made tools and components.
  2. Cost Reduction: reusable code and resources.
  3. Easy Development: tools simplify the process.
  4. Code Reusability: reuse code and components.
  5. Easy Testing: testing and debugging tools.
  6. Better User Experience: components for attractive interfaces.
  7. Easy Maintenance: update, fix bugs, add features.
  8. Multiple Platform Support: Android, iOS and others.
Disadvantages
  1. Learning Complexity: different languages and tools.
  2. Platform Limitations: may not support every device feature directly.
  3. Performance Issues: cross-platform and hybrid apps may be slower than optimized native apps.
  4. Dependency on Tools: third-party frameworks, libraries and updates.
  5. Compatibility Problems: apps may behave differently on different devices and OS versions.
  6. Security Risks: poorly configured libraries and tools can add vulnerabilities.

1.9 Complete Example: Developing a Mobile Application

Suppose a developer wants to create a simple student attendance application. Teachers can log in, view student lists, mark attendance, save attendance records and view attendance reports.

  1. Planning: decide what features the attendance application will provide.
  2. UI/UX Design: design login screens, student lists, buttons, and attendance pages.
  3. Development: use an IDE, programming language, SDK, and framework to write the code.
  4. Database and API Integration: connect the application to a database to save student and attendance records.
  5. Testing: check login, attendance marking, data saving, and other features.
  6. Deployment: prepare and publish the application for users.
  7. Maintenance: fix errors, improve performance, and introduce new features.

HTML5 for Mobiles

Features, PWAs and mobile web development

2.1 Introduction to HTML5

Before understanding HTML5 for mobile devices, we need to understand HTML.

HTML stands for HyperText Markup Language. It is a markup language used to create the structure of web pages. It tells a web browser how to display elements such as headings, paragraphs, images, videos, links, buttons, and forms.

HTML5 is the fifth major version of HTML. It introduced new elements, features, and APIs that make it easier to develop modern websites and mobile-friendly web applications.

In simple words: HTML5 allows developers to create websites and web applications that can work on computers, tablets, and smartphones.

Examples of HTML5-based mobile applications:

Online shopping websitesMobile banking websitesEducational web applicationsSocial media websitesOnline video platforms

2.2 What is HTML5 for Mobiles?

Definition: HTML5 for mobiles refers to the use of HTML5 technologies to develop mobile-friendly websites and web applications that can run on smartphones and tablets through mobile web browsers.

In simple words, HTML5 allows developers to create applications that users can access through a mobile browser without necessarily installing a separate application from an app store.

Example: You create an online shopping website using HTML5, CSS, and JavaScript. A user can open it on Android smartphones, iPhones, tablets and desktop computers. The website automatically adjusts its layout to the screen size when it is designed responsively.

2.3 Why is HTML5 Used for Mobile Development?

HTML5 provides features that help developers create interactive, responsive, and user-friendly web applications.

1. Cross-Platform Compatibility

HTML5 applications run on different operating systems through compatible browsers. The same website can work on Android, iOS, Windows and macOS, so developers do not need a completely separate website for every operating system.

2. Responsive Web Design

Creating websites that automatically adjust their layout according to the screen size and device.

Example: a website may display three product columns on a computer, but only one column on a mobile phone.

Technologies used: HTML5, CSS3, CSS Media Queries, flexible layouts, Flexbox and Grid.

3. Multimedia Support

HTML5 provides built-in support for audio and video. Previously, developers often needed external plugins. HTML5 introduced <audio> (adds audio) and <video> (adds video).

<video controls width="300">
    <source src="video.mp4" type="video/mp4">
</video>

This code displays a video player on a web page.

4. Offline Storage

HTML5 introduced technologies that let web applications store certain information on a user's device. For example, a shopping application can temporarily save some information so it remains available even when the internet connection is lost.

  • Local Storage: stores data in the browser with no automatic expiration.
  • Session Storage: stores data for the duration of a browser page session.
  • IndexedDB: stores larger amounts of structured data in the browser.
Note: HTML5's old Web SQL and Application Cache technologies are obsolete; modern applications generally use IndexedDB and service workers.
5. Touchscreen Support

Mobile devices mainly use touchscreens instead of a mouse and keyboard. HTML5 works with JavaScript and browser events to handle: touching buttons, tapping links, scrolling pages, selecting options, and filling forms.

6. Geolocation Support

The Geolocation API allows a website to request the user's geographical location. For example, a food delivery website can use it to help identify the user's delivery area.

navigator.geolocation.getCurrentPosition(
    function(position) {
        console.log(position.coords.latitude);
        console.log(position.coords.longitude);
    }
);

The browser normally asks the user for permission before sharing location information.

7. Better Form Support

HTML5 introduced new input types that make forms easier to use, especially on mobile devices.

<form>
    <input type="email" placeholder="Enter email">
    <input type="tel" placeholder="Phone number">
    <input type="date">
    <input type="number" placeholder="Age">
    <button type="submit">Submit</button>
</form>

These input types can display suitable mobile keyboards and built-in validation.

2.4 Important HTML5 Features for Mobile Applications

1. Semantic Elements

Semantic elements clearly describe the meaning and purpose of different parts of a web page.

ElementPurpose

    <a href="#">About</a>

    <section>
        <h2>Welcome</h2>
        <p>This is my website.</p>
    </section>
</main>

<footer>

</footer>

These elements make the structure of a website clearer and easier to maintain.

2. Canvas Element

The Canvas element provides an area where developers can draw graphics using JavaScript. It can be used for games, charts, animations, drawing applications and data visualization.

<canvas id="myCanvas" width="300" height="150"></canvas>

<script>
const canvas = document.getElementById("myCanvas");
const ctx = canvas.getContext("2d");

ctx.fillStyle = "blue";
ctx.fillRect(20, 20, 150, 80);
</script>

This code draws a blue rectangle inside the canvas.

3. Audio and Video Elements

HTML5 provides audio and video elements for playing multimedia content without external browser plugins.

<audio controls>
    <source src="music.mp3" type="audio/mpeg">
</audio>

<video controls width="300">
    <source src="movie.mp4" type="video/mp4">
</video>

The controls attribute displays playback controls such as play, pause, and volume.

4. Local Storage

Local Storage allows developers to save small amounts of data in the user's browser.

localStorage.setItem("username", "Ali");

let user = localStorage.getItem("username");

console.log(user);   // Output: Ali

Even after closing and reopening the browser, the stored value normally remains available until it is removed or cleared.

Mobile application example: a mobile shopping website can remember a user's preferred theme or certain settings using Local Storage.
5. Web Workers

Web Workers allow JavaScript to perform certain tasks in the background without blocking the main user interface thread.

For example, if a mobile application processes a large amount of data on the main thread, the interface may become slow or unresponsive. A Web Worker can handle suitable background calculations separately.

Benefits:

  • Keeps the interface responsive
  • Performs background processing
  • Helps handle computationally intensive tasks
6. Geolocation API

Allows a web application to request the geographical position of a user.

It can provide: latitude, longitude, accuracy, altitude (when available), speed (when available).

Example applications:

Google MapsFood delivery servicesLocation-based servicesNavigation applications
7. Drag and Drop

The Drag and Drop API allows users to move elements or files from one location to another. For example, a user can drag a file into an upload area.

Used in: file upload applications, image editors, task management applications, online design tools.

2.5 Mobile Web Applications vs Native Mobile Applications

HTML5 is commonly used to develop mobile web applications. However, mobile web applications and native applications are not exactly the same.

Mobile Web Application

Runs inside a mobile web browser. Generally developed using HTML5, CSS and JavaScript. Examples: mobile-friendly online shopping and banking websites.

Native Mobile Application

Developed specifically for a particular operating system (Android: Kotlin or Java; iOS: Swift or Objective-C). Normally installed through an app store or another supported distribution method.

Main Differences

Runs in a web browserRuns as an installed application
Uses HTML, CSS and JavaScriptUses platform-specific technologies
Usually accessed through a URLUsually installed on the device
Works across compatible browsersDeveloped for a particular platform
Device access may be limited by browser APIsCan access many native device features
Updates are usually made on the serverUpdates may require app releases

2.6 Progressive Web Applications (PWA)

A Progressive Web Application (PWA) is a web application that uses modern browser technologies to provide an experience similar to an installed mobile application. PWAs combine the accessibility of websites with several useful application-like features.

Main Features of PWA

  1. Installability: users can install supported PWAs on their devices.
  2. Offline Support: service workers can cache resources and support selected offline functionality.
  3. Responsive Design: PWAs adjust to different screen sizes.
  4. Push Notifications: supported browsers and operating systems can deliver notifications with user permission.
  5. Fast Loading: caching can improve loading speed.
  6. App-Like Experience: a PWA can open in a standalone window without the usual browser interface when installed and configured appropriately.

Main Technologies Used in PWA

  • HTML: creates the structure.
  • CSS: designs the interface.
  • JavaScript: adds functionality.
  • Service Worker: handles background tasks and caching.
  • Web App Manifest: provides application information such as name and icons.

2.7 Advantages and 2.8 Disadvantages of HTML5 for Mobile Development

Advantages
  1. Cross-Platform Compatibility: works on different operating systems through compatible browsers.
  2. Reduced Development Cost: same web technologies for different devices.
  3. Easy Maintenance: changes are deployed on the server without users installing a new native version.
  4. Multimedia Support: audio and video integrate directly into web pages.
  5. Responsive Design: adjusts to different screen sizes.
  6. Offline Capabilities: modern browser technologies allow selected offline features.
  7. Easy Learning: common web technologies, widely taught and documented.
  8. No Mandatory App Store Installation: users access ordinary mobile web apps directly through a browser.
Disadvantages
  1. Performance Limitations: demanding apps, especially graphics-intensive games, may perform better natively.
  2. Browser Dependency: depends on the browser's capabilities and compatibility.
  3. Limited Device Access: some hardware and OS features may not be available through standard web APIs.
  4. Internet Dependency: many web apps need an internet connection, although offline functionality can be implemented.
  5. Different Browser Behavior: features may behave differently across browsers and operating systems.
  6. User Experience: some web apps may not feel as smooth or integrated as native apps.
  7. Security Concerns: developers must protect stored information, validate user input, and use secure connections.

Android OS: Architecture, Framework and Application Development

Layers, system services and how Android apps are built

3.1 Introduction to Android

Android is an open-source, Linux-based operating system mainly designed for smartphones, tablets, smart TVs, smartwatches, and other electronic devices.

It is developed and maintained by Google and the Android Open Source Project (AOSP). Android provides an environment in which users can run applications and developers can create applications using programming languages and development tools.

Examples of Android devices:

Samsung smartphonesGoogle Pixel smartphonesXiaomi smartphonesOppo smartphonesVivo smartphonesAndroid tablets

Main Features of Android

1. Open Source

The core platform is available through AOSP, allowing developers and manufacturers to modify and customize it.

2. User-Friendly Interface

Easy-to-use interface with icons, menus, buttons, and touch interactions.

3. Multitasking

Users can switch between applications; background tasks are supported.

4. Connectivity

Supports Wi-Fi, Bluetooth, mobile networks, NFC, and other communication technologies.

5. Application Support

A large number of educational, business, entertainment, and social media applications.

6. Multimedia Support

Images, audio, videos, and other multimedia formats.

7. Security

Application sandboxing, permissions, encryption, and other security mechanisms.

8. Customization

Users and manufacturers can customize home screens, themes, widgets, and other interface elements.

Part 1: Android Architecture

3.2 What is Android Architecture?

Definition: Android Architecture is the layered structure of the Android operating system that explains how different software components work together to manage hardware, system services, applications, and user interactions.

In simple words, it explains how Android is organized internally and how its layers communicate with each other. Each layer has its own responsibilities and provides services to the layer above it.

3.3 Layers of Android Architecture

Android architecture is commonly represented through five major layers:

  1. Linux Kernel
  2. Hardware Abstraction Layer (HAL)
  3. Native Libraries and Android Runtime
  4. Application Framework
  5. Applications
1. Linux Kernel

The lowest layer of Android Architecture. It acts as a bridge between the hardware and the software of the device, helping Android communicate with and control the physical components of a smartphone.

Main responsibilities:

A. Memory Management

Controlling and distributing the device's RAM among applications and system processes.

Example: WhatsApp and YouTube both need memory; the kernel helps manage it.

B. Process Management

A process is a program that is currently running. The kernel manages running processes and helps allocate CPU time.

Example: opening a browser creates processes whose execution the kernel helps manage.

C. Device Drivers

Software components that allow the OS to communicate with hardware.

  • Camera drivers
  • Audio drivers
  • Display drivers
  • USB drivers
  • Wi-Fi drivers
D. Security

Process isolation and access controls prevent applications from accessing resources they are not authorized to use.

E. Power Management

Helps manage power consumption, for example by controlling hardware activity to reduce battery usage.

F. Networking

Provides networking functionality for communicating over networks.

  • Wi-Fi communication
  • Internet connections
  • Network data transmission
In short: the Linux Kernel manages hardware resources, processes, memory, security, and power.
2. Hardware Abstraction Layer (HAL)
Definition: HAL is a layer that provides standard interfaces between Android's higher-level software and the device hardware. In simple words, it works like a communication bridge between Android software and different hardware components.

Why is HAL needed? Different manufacturers use different hardware. For example, Samsung, Xiaomi and Google Pixel may each use a different camera sensor. Android applications should not need to understand the internal details of every manufacturer's hardware, so HAL provides standard interfaces for different hardware implementations.

Main components of HAL:

  1. Camera HAL: interface for camera hardware.
  2. Audio HAL: interface for audio hardware.
  3. Bluetooth HAL: interface for Bluetooth hardware.
  4. Wi-Fi HAL: interface for Wi-Fi hardware.
  5. GPS/GNSS HAL: interface for location-related hardware.
Example: opening the camera application
  1. The application requests access to the camera.
  2. Android's camera services communicate with the camera HAL.
  3. The HAL implementation communicates with the camera hardware.
  4. The camera captures an image.
  5. The captured image is made available to the application through Android's camera system.
In short: HAL hides hardware-specific details and provides standard interfaces for Android software.
3. Native Libraries

Pre-written software libraries that provide important functions to Android. Many are written in C or C++.

Definition: Native Libraries are collections of pre-written code that provide services such as graphics processing, database management, multimedia playback, and security.
A. SQLite

A lightweight database engine used to store and manage structured data.

Example: a notes app saves note titles, descriptions and creation dates.

B. OpenGL ES

A graphics API used for rendering 2D and 3D graphics.

Example: mobile games display objects, animations, and visual effects.

C. Media Framework

Handles audio and video.

Example: a video application plays video files.

D. SSL/TLS Libraries

Security functionality for encrypted network communication.

Example: with HTTPS, encryption helps protect the transmitted information.

E. Web Rendering Engine

Chromium-based WebView technology displays web content inside applications.

Example: a shopping app shows a web page without opening a separate browser.

In short: Native Libraries provide ready-made functions for graphics, multimedia, databases, and other system operations.
4. Android Runtime (ART)
Definition: Android Runtime is the execution environment responsible for running Android application code.

Android apps are commonly developed using Kotlin or Java. Their compiled code is packaged into DEX (Dalvik Executable) bytecode, which Android Runtime executes.

Main responsibilities of ART:

  1. Application Execution: provides the environment required to run Android applications.
  2. Memory Management: helps manage memory used by applications.
  3. Garbage Collection: automatically reclaims memory occupied by objects that are no longer needed.
  4. Code Optimization: uses compilation techniques to improve performance.
  5. Runtime Support: provides essential services required while applications are running.
Example: when you open WhatsApp, ART provides the runtime environment needed to execute its application code.
Historical point: earlier Android versions used the Dalvik Virtual Machine (DVM). ART replaced Dalvik as the default runtime beginning with Android 5.0 Lollipop.
5. Application Framework

Provides high-level services and APIs that developers use to build Android applications. It is studied separately in Part 2.

6. Applications

The topmost layer of Android Architecture. It contains the applications that users interact with directly.

PhoneMessagesCameraSettingsContactsWhatsAppYouTubeGoogle Maps
Example: the Camera application uses services provided by the Application Framework, which communicates with lower Android layers to access the camera hardware.

3.4 How Android Architecture Works: Real-Life Example

Suppose you open the Camera application and capture a photograph. Different layers work together:

  1. Application Layer: you open the Camera application and press the capture button.
  2. Application Framework: Android's camera services manage the camera request and provide the required APIs.
  3. HAL: the camera HAL communicates with the specific camera hardware implementation.
  4. Linux Kernel: device drivers and hardware-management facilities support communication with the camera device.
  5. Native Libraries: graphics and image-processing components help process and handle image data.
  6. Android Runtime: provides the execution environment for the application's code throughout the process.
  7. Result: the photograph is captured and saved on the device.
Notice that these layers do not work independently. They cooperate to complete the task.

Part 2: Android Framework

3.5 What is Android Framework?

Definition: Android Framework is a collection of APIs and system services that provides developers with the necessary tools and functionality to build Android applications.

In simple words, it provides ready-made services that developers can use instead of writing everything from the beginning.

Example: to send notifications you do not need to create a complete notification system yourself. Android provides a Notification Manager that helps your application display notifications.

3.6 Main Components of Android Framework

1. Activity Manager

Manages the lifecycle and execution of activities. An Activity generally represents a single screen.

Example: a shopping app may have Login, Home, Product Details and Payment activities.

2. Window Manager

Manages application windows and their display on the screen: position, size, arrangement and other display operations.

Example: when you open an app, it helps manage how the window appears.

3. Content Providers

Allow applications to share and access structured data through controlled interfaces.

Example: a messaging app requests permission to access contacts; the Contacts Content Provider gives access to the permitted information.

4. Resource Manager

Manages non-code resources: images, icons, strings, colors, layout files, animations.

Example: an app logo stored as an image resource can be used on different screens.

5. Notification Manager

Allows applications to display notifications.

Example: WhatsApp message, email, banking transaction and reminder notifications.

6. Location Manager

Provides access to location-related services through supported location providers, subject to permissions.

Example: a navigation app determines the user's position.

7. Package Manager

Manages information about installed applications and their packages. It helps Android:

  • Identify installed applications
  • Retrieve package information
  • Manage installation-related information
  • Check application permissions
8. Telephony Manager

Provides information about telephony services and the device's cellular network capabilities.

Example: an app may use supported telephony APIs to get certain mobile network information, subject to permission and privacy restrictions.

These two terms are related, but they do not mean the same thing.

Part 1: iOS Architecture

4.4 What is iOS Architecture?

Definition: iOS Architecture is the layered structure of the iOS operating system that explains how hardware, system services, frameworks, and applications work together.

In simple words, it explains how an iPhone works internally and how different software layers communicate with each other. iOS uses four major architectural layers, and each layer provides specific services to the layer above it:

  1. Cocoa Touch Layer
  2. Media Layer
  3. Core Services Layer
  4. Core OS Layer
1. Cocoa Touch Layer

The highest layer of iOS Architecture. It provides the frameworks and technologies required to develop the user interface and handle user interactions. This layer helps developers create screens, buttons, menus, and other interactive elements.

Main responsibilities:

A. User Interface Management

Tools for creating application interfaces: buttons, text fields, navigation bars, tables, images, menus.

B. Touch Event Handling

Handles user interactions with the touchscreen: tapping, swiping, scrolling, pinching, touching buttons.

C. Application Lifecycle Management

Manages the states of an application: launching, becoming active, moving into the background, termination.

D. Notifications

Facilities for managing application notifications and user interactions with them.

Important frameworks: UIKit, SwiftUI, UserNotifications.

Example: when you open Instagram, the interface you see, including buttons, menus, and navigation elements, uses technologies provided by the higher-level iOS frameworks.
2. Media Layer

Provides technologies for handling graphics, animations, audio, and video. It helps applications display visual content and play multimedia.

  • A. Graphics: displaying images, shapes, and other visual elements.
  • B. Animation: smooth animations and visual transitions.
  • C. Audio: recording and playing audio.
  • D. Video: playing, recording, and processing video.

Important frameworks: Core Graphics, Core Animation, AVFoundation, Core Audio, Metal.

Example: when you play a video on an iPhone, the Media Layer provides technologies that help process and display it.
3. Core Services Layer

Provides essential system services used by applications: important background functionality that applications need to operate.

  • A. Data Management: storing and managing application information.
  • B. Networking: allows applications to communicate over the internet.
  • C. Location Services: geographical location information, subject to user permission.
  • D. Database Support: store and retrieve data.
  • E. Cloud Services: communicating with cloud-based services.

Important frameworks: Core Data, Core Location, Core Foundation, Foundation, CloudKit.

Example: when you use Apple Maps, Core Services technologies help the application work with location information and network data.
4. Core OS Layer

The lowest layer of iOS Architecture. It provides low-level operating system functionality and communicates with the device hardware. It handles important internal operations that allow the iPhone to function.

  • A. Memory Management: memory used by the operating system and applications.
  • B. File System Management: storing and accessing files.
  • C. Security: low-level security mechanisms, including encryption and system protection.
  • D. Process Management: execution and management of system processes.
  • E. Device Communication: low-level interfaces and drivers for hardware.
  • F. Networking: low-level networking functionality.

Important technologies: Darwin kernel, BSD components, Security, File System, Networking, Device drivers.

Example: when you save a photograph, lower-level operating system services help manage the storage and file operations.

4.5 How iOS Architecture Works: Real-Life Example

Suppose you open the Camera application on your iPhone and capture a photograph. All four layers work together:

  1. Cocoa Touch Layer: handles your interaction when you open the camera and press the capture button.
  2. Media Layer: provides image-processing and graphics-related technologies.
  3. Core Services Layer: provides supporting services such as data management.
  4. Core OS Layer: supports low-level hardware communication, device drivers, and file storage.

Result: the photograph is captured and saved on your iPhone.

The important point is that all four layers cooperate to perform a single task.

Part 2: iOS Framework

4.6 What is an iOS Framework?

Definition: An iOS Framework is a collection of pre-written code, APIs, libraries, and services that developers use to build applications for Apple devices.

Frameworks provide ready-made functionality so developers do not have to create every feature from the beginning.

Example: to use the iPhone camera you do not write all the camera hardware management code yourself. Apple provides the AVFoundation framework, which offers APIs for camera and media functionality.

4.7 Important iOS Frameworks

1. UIKit Framework
UIKit stands for User Interface Kit. It is a framework used to create and manage the user interface of iOS applications, with ready-made components for building application screens.

Main functions: creating buttons, creating text fields, displaying images, managing navigation, handling touch interactions, managing view controllers.

Example: a login application needs an email text field, a password text field, a login button and a registration link. UIKit provides components to create these elements.
2. SwiftUI Framework
SwiftUI is Apple's modern declarative framework for building user interfaces across Apple platforms. Developers describe what the interface should look like, and SwiftUI manages much of the process of updating it when data changes.

Main functions: creating application interfaces, designing buttons and forms, building navigation, creating animations, updating interfaces when data changes.

Example: a button created with SwiftUI:

import SwiftUI

struct ContentView: View {
    var body: some View {
        Button("Click Me") {
            print("Button clicked")
        }
    }
}

This code creates a button with the text "Click Me".

3. Foundation Framework

Provides essential programming features used by iOS applications.

Main functions: managing strings, working with dates and times, handling collections, managing URLs, working with files, supporting networking-related operations.

Example: a student application stores the student name, registration date, email address and course information. Foundation provides basic data types and utilities to manage this information.
4. Core Data Framework

Used to manage an application's model data. It helps developers store, retrieve, and manage structured information.

Main functions: saving application data, retrieving records, updating information, deleting records, managing relationships between data objects.

Example: a notes application can use Core Data to store note titles, descriptions, creation dates and categories.
5. Core Location Framework

Provides services for obtaining geographical location information.

Main functions: accessing location information, getting latitude and longitude, monitoring location changes, supporting location-based features.

Example: a food delivery application can use Core Location to help identify the user's delivery location. Location access requires appropriate authorization from the user.
6. AVFoundation Framework

AVFoundation stands for Audio Video Foundation. It provides technologies for working with audio and video.

Main functions: recording audio, playing audio, capturing video, playing video, accessing camera functionality, processing audiovisual media.

Example: a video recording application can use AVFoundation to access the camera and record videos.
7. Core Graphics Framework

A graphics framework used for creating and rendering two-dimensional graphics.

Main functions: drawing shapes, creating paths, rendering images, drawing text, working with colors.

Example: a drawing application can use Core Graphics to draw lines, circles, rectangles, and other shapes.
8. CloudKit Framework

Allows applications to store and synchronize data using Apple's iCloud infrastructure.

Main functions: storing data in iCloud, synchronizing supported information, managing cloud records, supporting data sharing.

Example: a notes application can use CloudKit to synchronize notes across supported Apple devices.

In the traditional Model-View-Controller (MVC) pattern, the Controller coordinates interactions between the Model and the View.

Example: when a user presses a login button, the controller processes the input and communicates with the model or authentication service.

5.4 Windows Mobile Architecture

Definition: Windows Mobile Architecture is the internal structure of the Windows Mobile operating system that explains how hardware, system services, application frameworks, and applications work together.

In simple words, it explains how different software components communicate with mobile device hardware and execute applications. Windows Mobile was built on Windows CE technology and used a layered software architecture.

1. Hardware Layer

Contains the physical components of a mobile device, which provide the physical resources needed by the operating system.

ProcessorRAMInternal storageTouchscreenCameraSpeakerMicrophoneNetwork components
2. Kernel and Hardware Abstraction

The kernel is the core part of the operating system. It manages the device's hardware resources and provides essential operating system functions.

  • A. Memory Management: manages available memory and allocates it to running applications.
  • B. Process Management: helps manage running programs and their execution.
  • C. Device Management: supports communication between software and hardware through device drivers.
  • D. Security: basic operating system protection mechanisms.
  • E. Power Management: helps control device power consumption.
Windows CE provided the underlying kernel and operating system services for Windows Mobile.
3. Operating System Services

Provides important system services required by applications, so applications can perform operations without directly controlling all hardware components.

File managementNetworkingCommunicationInput and outputGraphicsMultimedia
4. Application Framework and Libraries

Provides programming interfaces and reusable libraries that developers use to create applications.

.NET Compact FrameworkWindows Mobile APIsUser interface librariesDatabase-related libraries
5. Application Layer

The topmost layer. It contains the applications that users interact with.

CalendarContactsMessagingEmailOffice applicationsWeb browsers

5.5 How Windows Mobile Architecture Works

Suppose a user opens a contact management application and saves a new contact. The architectural components work together:

  1. Application Layer: the user opens the Contacts application and enters a name and phone number.
  2. Application Framework: the application uses available APIs and libraries to process the information.
  3. Operating System Services: system services help manage the data and file operations.
  4. Kernel: manages the necessary memory and hardware operations.
  5. Hardware Layer: the device's storage hardware stores the required information.

Result: the contact is saved and can be accessed later.

6.1 Introduction to Eclipse

Eclipse is an Integrated Development Environment (IDE) used by programmers to write, edit, compile, run, test, and debug computer programs.

It provides a complete environment where developers can manage their programming projects and write code in different programming languages. Eclipse is especially known for Java development, but it can also support other languages through plugins.

Simple definition: Eclipse is an open-source IDE that provides tools for developing, testing, debugging, and managing software applications.

6.2 What is an IDE?

IDE stands for Integrated Development Environment. It is software that combines different programming tools in one application.

Instead of using separate programs for writing code, compiling, running, and debugging, an IDE provides these facilities together.

Main components of an IDE

1. Code Editor

Allows programmers to write and edit source code.

Example: writing Java code inside Eclipse.

2. Compiler

Translates source code into a form that the computer can execute. For Java, Eclipse works with the Java compiler to compile Java source files.

3. Debugger

Helps programmers find and correct errors.

Example: if a calculator produces the wrong answer, the programmer can use debugging tools to examine the program step by step.

4. Project Explorer

Displays the files and folders of a programming project.

5. Run Tools

Allow programmers to execute their applications and see the output.

6.3 History of Eclipse

  1. Eclipse was originally developed by IBM.
  2. It was released as an open-source project in 2001.
  3. It became popular for Java application development.
  4. The Eclipse Foundation was established in 2004 to support the Eclipse ecosystem.
  5. Later, Eclipse expanded to support many programming languages and development tools.

Today, Eclipse is commonly used for Java and other software development tasks.

6.4 Main Features of Eclipse

1. Open-Source Software

Developers can use it without purchasing a commercial license and can contribute to its development.

2. Code Editor

An advanced code editor with:

  • Syntax highlighting
  • Automatic indentation
  • Code completion
  • Error highlighting
  • Code formatting

Example: in Java code, Eclipse highlights keywords such as class, public, and static in different colors.

3. Code Completion

Suggests keywords, methods, and variables while the programmer is writing code. This saves time and reduces typing mistakes.

Example: after typing System.out. Eclipse can suggest methods such as println().

4. Debugging

Tools to find errors in programs:

  • Breakpoints
  • Step Into
  • Step Over
  • Step Return
  • Variable inspection

A breakpoint temporarily pauses program execution at a selected line so the programmer can examine what is happening.

5. Plugin Support

Plugins are additional software components that extend Eclipse's functionality:

  • Java development tools
  • C/C++ development tools
  • Git integration
  • Database development tools

Developers can add tools according to their requirements.

6. Project Management

Organizes code into projects. Each project can contain:

  • Source code files
  • Libraries
  • Resources
  • Configuration files
  • Other project-related files
7. Multiple Programming Languages

Through suitable tools and plugins, for example Java, C, C++, Python, PHP. Support depends on the Eclipse package and installed plugins.

6.5 Architecture of Eclipse

Eclipse uses a modular architecture. This means its functionality is divided into separate components that work together.

Main components

1. Eclipse Platform

Provides the basic environment required to run Eclipse. It manages the user interface, workbench, workspace, and plugins.

2. Workbench

The graphical user interface of Eclipse, containing the areas where programmers work:

  • Code editor
  • Project Explorer
  • Console
  • Debug view
3. Workspace

A directory that stores and manages Eclipse projects and related settings. A programmer can create multiple projects inside one workspace.

4. Plugin System

Allows developers to add new features to Eclipse. For example, a Java Development Tools plugin provides tools for Java programming.

5. Java Development Tools (JDT)

A collection of tools that supports Java development inside Eclipse:

  • Java code editing
  • Code completion
  • Compilation
  • Debugging
  • Java project management

6.6 Eclipse in Mobile Application Development

Eclipse was historically used for Android application development. In earlier versions of Android development, programmers used Eclipse with the Android Development Tools (ADT) plugin.

Important tools

1. Eclipse IDE

Used to write and manage Android application code.

2. Android Development Tools (ADT)

A plugin that added Android development features to Eclipse. It helped developers create Android projects, manage resources, and debug applications.

3. Android SDK

Provides the libraries, APIs, and development tools needed to build Android applications.

4. Android Emulator

Lets developers test Android applications on a virtual Android device without requiring a physical phone.

How Eclipse was used for Android development

  1. Install Eclipse IDE.
  2. Install the Android SDK.
  3. Install the ADT plugin.
  4. Create an Android project.
  5. Write Java code.
  6. Design the application interface.
  7. Run the application using an emulator or physical device.
  8. Debug and fix errors.
  9. Build the application package.
Important modern note: Eclipse is no longer the official Android development IDE. Google replaced the Eclipse-based Android development workflow with Android Studio. The old ADT plugin is deprecated. Modern Android development generally uses Android Studio with Kotlin or Java.

6.7 How to Create a Java Project in Eclipse

A basic example of creating and running a Java program:

  1. Open Eclipse IDE.
  2. Select or create a workspace.
  3. Click File → New → Java Project.
  4. Enter a project name, such as MyFirstProject.
  5. Click Finish.
  6. Create a Java class inside the source folder.
  7. Write the following code:
public class Main {

    public static void main(String[] args) {

        System.out.println("Hello World!");

    }
}
  1. Click the Run button.

Output: Hello World!

This demonstrates how Eclipse helps programmers write and execute Java programs.

6.8 Advantages and 6.9 Disadvantages of Eclipse

Advantages
  1. Free and Open Source: no commercial license needed.
  2. Multiple Languages: different programming languages through plugins.
  3. Code Completion: suggests code while programmers type.
  4. Debugging Tools: identify and correct programming errors.
  5. Plugin Support: add additional functionality.
  6. Project Management: organizes programming files and projects.
  7. Cross-Platform: available for major desktop operating systems.
Disadvantages
  1. Resource Usage: can consume considerable memory and processing resources.
  2. Complex Interface: beginners may find it difficult initially.
  3. Plugin Problems: some plugins may cause compatibility issues.
  4. Configuration: setting up development environments can require additional configuration.
  5. Android Development: its old Android development tools are deprecated and not suitable for modern Android development.
