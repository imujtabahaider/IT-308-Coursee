Windows Mobile

History, architecture and application development

5.1 Introduction to Windows Mobile

Windows Mobile was a mobile operating system developed by Microsoft for smartphones and Pocket PCs. It was designed to bring some of the features of Microsoft Windows computers to mobile devices.

Windows Mobile allowed users to perform different tasks, such as:

  • Making phone calls
  • Sending text messages
  • Sending and receiving emails
  • Browsing the internet
  • Managing contacts
  • Creating and editing documents
  • Running mobile applications
  • Managing calendars and appointments

In simple words, Windows Mobile was Microsoft's operating system for mobile devices that allowed users to perform communication, business, and personal tasks.

Important: Windows Mobile is a discontinued platform. Microsoft later introduced Windows Phone, followed by Windows 10 Mobile. These are related but separate operating system generations.

5.2 History of Windows Mobile

Understanding its history helps us understand how Microsoft introduced and improved mobile operating systems.

1. Windows CE (1996)

A compact operating system developed by Microsoft for embedded devices and small computers. It provided the technological foundation for several early Microsoft mobile operating systems.

2. Pocket PC (2000)

A platform for personal digital assistants (PDAs), with:

  • Contact management
  • Calendar
  • Email
  • Document management
  • Personal information management
3. Windows Mobile 2003

Improved mobile communication and multimedia functionality:

  • Bluetooth
  • Improved wireless connectivity
  • Multimedia applications
  • Better device management
4. Windows Mobile 5.0 (2005)

Improvements in memory management and application functionality, with better support for business users.

5. Windows Mobile 6 (2007)

Improved user interface and productivity features, with better support for:

  • Email
  • Office documents
  • Business applications
  • Internet browsing
6. Windows Mobile 6.5 (2009)

A more touch-friendly interface and an updated Start screen. One of the last major releases under the Windows Mobile name.

7. Windows Phone (2010)

A new mobile operating system with a redesigned interface. It used a different application platform and user experience from Windows Mobile.

5.3 Main Features of Windows Mobile

Windows Mobile provided several features to make smartphones useful for communication, productivity, and business activities.

1. User-Friendly Interface

Menus, icons, buttons, and a Start menu. Users could access different applications and system settings.

2. Microsoft Office Support

Users could work with documents, spreadsheets, and presentations through compatible mobile applications.

  • Word documents
  • Excel spreadsheets
  • PowerPoint presentations
3. Email Support

Users could send emails, receive emails, read messages, and manage email accounts. Particularly useful for business professionals.

4. Internet Browsing

Mobile internet browsing through compatible web browsers, to visit websites and access online information.

5. Contact Management

Save and organize names, phone numbers, email addresses and other contact details.

6. Calendar and Scheduling

Create appointments, schedule meetings, set reminders, and manage daily activities.

7. Multimedia Support

Playing music, watching videos, viewing photographs, recording audio.

8. Wireless Connectivity

Depending on the hardware: Wi-Fi, Bluetooth, cellular networks, USB connections.

9. Application Support

Applications developed for its platform, many using Microsoft technologies such as the .NET Compact Framework.

10. Synchronization

Synchronization with computers and other services: contacts, calendars, emails, files.

5.4 Windows Mobile Architecture

Definition: Windows Mobile Architecture is the internal structure of the Windows Mobile operating system that explains how hardware, system services, application frameworks, and applications work together.

In simple words, it explains how different software components communicate with mobile device hardware and execute applications. Windows Mobile was built on Windows CE technology and used a layered software architecture.

1. Hardware Layer

Contains the physical components of a mobile device, which provide the physical resources needed by the operating system.

ProcessorRAMInternal storageTouchscreenCameraSpeakerMicrophoneNetwork components
2. Kernel and Hardware Abstraction

The kernel is the core part of the operating system. It manages the device's hardware resources and provides essential operating system functions.

  • A. Memory Management: manages available memory and allocates it to running applications.
  • B. Process Management: helps manage running programs and their execution.
  • C. Device Management: supports communication between software and hardware through device drivers.
  • D. Security: basic operating system protection mechanisms.
  • E. Power Management: helps control device power consumption.
Windows CE provided the underlying kernel and operating system services for Windows Mobile.
3. Operating System Services

Provides important system services required by applications, so applications can perform operations without directly controlling all hardware components.

File managementNetworkingCommunicationInput and outputGraphicsMultimedia
4. Application Framework and Libraries

Provides programming interfaces and reusable libraries that developers use to create applications.

.NET Compact FrameworkWindows Mobile APIsUser interface librariesDatabase-related libraries
5. Application Layer

The topmost layer. It contains the applications that users interact with.

CalendarContactsMessagingEmailOffice applicationsWeb browsers

5.5 How Windows Mobile Architecture Works

Suppose a user opens a contact management application and saves a new contact. The architectural components work together:

  1. Application Layer: the user opens the Contacts application and enters a name and phone number.
  2. Application Framework: the application uses available APIs and libraries to process the information.
  3. Operating System Services: system services help manage the data and file operations.
  4. Kernel: manages the necessary memory and hardware operations.
  5. Hardware Layer: the device's storage hardware stores the required information.

Result: the contact is saved and can be accessed later.

5.6 Application Development in Windows Mobile

Definition: Windows Mobile Application Development is the process of designing, programming, testing, and deploying applications that run on devices using the Windows Mobile operating system.

In simple words, it means creating software applications for Windows Mobile smartphones and Pocket PCs.

5.7 Programming Languages Used for Windows Mobile Development

Microsoft provided different programming technologies for Windows Mobile development.

1. C#

An object-oriented programming language developed by Microsoft. It was commonly used for Windows Mobile applications through the .NET Compact Framework.

Features:

  • Object-oriented programming
  • Easy-to-understand syntax
  • Reusable code
  • Integration with Microsoft development tools
using System;

class Program
{
    static void Main()
    {
        string name = "Ali";

        Console.WriteLine("Hello " + name);
    }
}
2. C and C++

Used for developing native applications and system-level components. They provided greater control over memory and device resources.

3. Visual Basic .NET

Another language used for developing applications through Microsoft's .NET technologies. It provided a relatively simple programming syntax.

5.8 Tools Used for Windows Mobile Application Development

1. Microsoft Visual Studio

An IDE developed by Microsoft, used to write, manage, build, and debug Windows Mobile applications.

  • Writing source code
  • Designing user interfaces
  • Debugging errors
  • Building applications
  • Managing project files
2. Windows Mobile SDK

Software Development Kit. Provides development tools, libraries, APIs, and resources required to create applications for Windows Mobile.

3. .NET Compact Framework

A reduced version of the .NET Framework designed for resource-constrained devices. It allowed developers to use languages such as C# and Visual Basic .NET.

4. Windows Mobile Emulator

Allowed developers to test applications on a virtual Windows Mobile device without always requiring a physical smartphone.

5. ActiveSync

Microsoft's technology for synchronizing Windows Mobile devices with computers: contacts, calendars, emails, files.

5.9 Steps Involved in Windows Mobile Application Development

  1. Requirement Analysis: identify the purpose and required features of the application.
  2. User Interface Design: design screens, buttons, menus, and forms.
  3. Environment Setup: install Visual Studio, the appropriate SDK, and development tools.
  4. Programming: write code using C#, C++, or other supported technologies.
  5. Testing: test the application using an emulator or physical device.
  6. Debugging: identify and correct programming errors.
  7. Deployment: package and install the application on compatible Windows Mobile devices.
  8. Maintenance: fix bugs and improve application functionality.

5.10 Advantages and 5.11 Disadvantages of Windows Mobile

Advantages
  1. Microsoft Office Integration: support for productivity applications and Office documents.
  2. Business Support: useful for business communication, scheduling, and document management.
  3. Microsoft Technology Integration: C#, Visual Studio, and .NET Compact Framework.
  4. Email Management: business and personal emails.
  5. Synchronization: contacts, calendars, and other information with computers.
  6. Application Development Tools: development environments and SDKs from Microsoft.
  7. Multitasking: supported, although the exact behavior depended on the device and version.
Disadvantages
  1. Limited Application Ecosystem: fewer applications than Android and iOS.
  2. Declining Market Share: struggled to compete with Android and iOS.
  3. Limited Developer Support: the developer ecosystem became smaller over time.
  4. Outdated Technology: discontinued, with no regular security updates.
  5. Compatibility Issues: applications designed for one version or device may not work on another.
  6. Limited Modern Features: lacks many modern mobile application capabilities and services.
