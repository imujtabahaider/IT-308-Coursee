Android OS: Architecture, Framework and Application Development

Layers, system services and how Android apps are built

3.1 Introduction to Android

Android is an open-source, Linux-based operating system mainly designed for smartphones, tablets, smart TVs, smartwatches, and other electronic devices.

It is developed and maintained by Google and the Android Open Source Project (AOSP). Android provides an environment in which users can run applications and developers can create applications using programming languages and development tools.

Examples of Android devices:

Samsung smartphonesGoogle Pixel smartphonesXiaomi smartphonesOppo smartphonesVivo smartphonesAndroid tablets

Main Features of Android

1. Open Source

The core platform is available through AOSP, allowing developers and manufacturers to modify and customize it.

2. User-Friendly Interface

Easy-to-use interface with icons, menus, buttons, and touch interactions.

3. Multitasking

Users can switch between applications; background tasks are supported.

4. Connectivity

Supports Wi-Fi, Bluetooth, mobile networks, NFC, and other communication technologies.

5. Application Support

A large number of educational, business, entertainment, and social media applications.

6. Multimedia Support

Images, audio, videos, and other multimedia formats.

7. Security

Application sandboxing, permissions, encryption, and other security mechanisms.

8. Customization

Users and manufacturers can customize home screens, themes, widgets, and other interface elements.

Part 1: Android Architecture

3.2 What is Android Architecture?

Definition: Android Architecture is the layered structure of the Android operating system that explains how different software components work together to manage hardware, system services, applications, and user interactions.

In simple words, it explains how Android is organized internally and how its layers communicate with each other. Each layer has its own responsibilities and provides services to the layer above it.

3.3 Layers of Android Architecture

Android architecture is commonly represented through five major layers:

  1. Linux Kernel
  2. Hardware Abstraction Layer (HAL)
  3. Native Libraries and Android Runtime
  4. Application Framework
  5. Applications
1. Linux Kernel

The lowest layer of Android Architecture. It acts as a bridge between the hardware and the software of the device, helping Android communicate with and control the physical components of a smartphone.

Main responsibilities:

A. Memory Management

Controlling and distributing the device's RAM among applications and system processes.

Example: WhatsApp and YouTube both need memory; the kernel helps manage it.

B. Process Management

A process is a program that is currently running. The kernel manages running processes and helps allocate CPU time.

Example: opening a browser creates processes whose execution the kernel helps manage.

C. Device Drivers

Software components that allow the OS to communicate with hardware.

  • Camera drivers
  • Audio drivers
  • Display drivers
  • USB drivers
  • Wi-Fi drivers
D. Security

Process isolation and access controls prevent applications from accessing resources they are not authorized to use.

E. Power Management

Helps manage power consumption, for example by controlling hardware activity to reduce battery usage.

F. Networking

Provides networking functionality for communicating over networks.

  • Wi-Fi communication
  • Internet connections
  • Network data transmission
In short: the Linux Kernel manages hardware resources, processes, memory, security, and power.
2. Hardware Abstraction Layer (HAL)
Definition: HAL is a layer that provides standard interfaces between Android's higher-level software and the device hardware. In simple words, it works like a communication bridge between Android software and different hardware components.

Why is HAL needed? Different manufacturers use different hardware. For example, Samsung, Xiaomi and Google Pixel may each use a different camera sensor. Android applications should not need to understand the internal details of every manufacturer's hardware, so HAL provides standard interfaces for different hardware implementations.

Main components of HAL:

  1. Camera HAL: interface for camera hardware.
  2. Audio HAL: interface for audio hardware.
  3. Bluetooth HAL: interface for Bluetooth hardware.
  4. Wi-Fi HAL: interface for Wi-Fi hardware.
  5. GPS/GNSS HAL: interface for location-related hardware.
Example: opening the camera application
  1. The application requests access to the camera.
  2. Android's camera services communicate with the camera HAL.
  3. The HAL implementation communicates with the camera hardware.
  4. The camera captures an image.
  5. The captured image is made available to the application through Android's camera system.
In short: HAL hides hardware-specific details and provides standard interfaces for Android software.
3. Native Libraries

Pre-written software libraries that provide important functions to Android. Many are written in C or C++.

Definition: Native Libraries are collections of pre-written code that provide services such as graphics processing, database management, multimedia playback, and security.
A. SQLite

A lightweight database engine used to store and manage structured data.

Example: a notes app saves note titles, descriptions and creation dates.

B. OpenGL ES

A graphics API used for rendering 2D and 3D graphics.

Example: mobile games display objects, animations, and visual effects.

C. Media Framework

Handles audio and video.

Example: a video application plays video files.

D. SSL/TLS Libraries

Security functionality for encrypted network communication.

Example: with HTTPS, encryption helps protect the transmitted information.

E. Web Rendering Engine

Chromium-based WebView technology displays web content inside applications.

Example: a shopping app shows a web page without opening a separate browser.

In short: Native Libraries provide ready-made functions for graphics, multimedia, databases, and other system operations.
4. Android Runtime (ART)
Definition: Android Runtime is the execution environment responsible for running Android application code.

Android apps are commonly developed using Kotlin or Java. Their compiled code is packaged into DEX (Dalvik Executable) bytecode, which Android Runtime executes.

Main responsibilities of ART:

  1. Application Execution: provides the environment required to run Android applications.
  2. Memory Management: helps manage memory used by applications.
  3. Garbage Collection: automatically reclaims memory occupied by objects that are no longer needed.
  4. Code Optimization: uses compilation techniques to improve performance.
  5. Runtime Support: provides essential services required while applications are running.
Example: when you open WhatsApp, ART provides the runtime environment needed to execute its application code.
Historical point: earlier Android versions used the Dalvik Virtual Machine (DVM). ART replaced Dalvik as the default runtime beginning with Android 5.0 Lollipop.
5. Application Framework

Provides high-level services and APIs that developers use to build Android applications. It is studied separately in Part 2.

6. Applications

The topmost layer of Android Architecture. It contains the applications that users interact with directly.

PhoneMessagesCameraSettingsContactsWhatsAppYouTubeGoogle Maps
Example: the Camera application uses services provided by the Application Framework, which communicates with lower Android layers to access the camera hardware.

3.4 How Android Architecture Works: Real-Life Example

Suppose you open the Camera application and capture a photograph. Different layers work together:

  1. Application Layer: you open the Camera application and press the capture button.
  2. Application Framework: Android's camera services manage the camera request and provide the required APIs.
  3. HAL: the camera HAL communicates with the specific camera hardware implementation.
  4. Linux Kernel: device drivers and hardware-management facilities support communication with the camera device.
  5. Native Libraries: graphics and image-processing components help process and handle image data.
  6. Android Runtime: provides the execution environment for the application's code throughout the process.
  7. Result: the photograph is captured and saved on the device.
Notice that these layers do not work independently. They cooperate to complete the task.

Part 2: Android Framework

3.5 What is Android Framework?

Definition: Android Framework is a collection of APIs and system services that provides developers with the necessary tools and functionality to build Android applications.

In simple words, it provides ready-made services that developers can use instead of writing everything from the beginning.

Example: to send notifications you do not need to create a complete notification system yourself. Android provides a Notification Manager that helps your application display notifications.

3.6 Main Components of Android Framework

1. Activity Manager

Manages the lifecycle and execution of activities. An Activity generally represents a single screen.

Example: a shopping app may have Login, Home, Product Details and Payment activities.

2. Window Manager

Manages application windows and their display on the screen: position, size, arrangement and other display operations.

Example: when you open an app, it helps manage how the window appears.

3. Content Providers

Allow applications to share and access structured data through controlled interfaces.

Example: a messaging app requests permission to access contacts; the Contacts Content Provider gives access to the permitted information.

4. Resource Manager

Manages non-code resources: images, icons, strings, colors, layout files, animations.

Example: an app logo stored as an image resource can be used on different screens.

5. Notification Manager

Allows applications to display notifications.

Example: WhatsApp message, email, banking transaction and reminder notifications.

6. Location Manager

Provides access to location-related services through supported location providers, subject to permissions.

Example: a navigation app determines the user's position.

7. Package Manager

Manages information about installed applications and their packages. It helps Android:

  • Identify installed applications
  • Retrieve package information
  • Manage installation-related information
  • Check application permissions
8. Telephony Manager

Provides information about telephony services and the device's cellular network capabilities.

Example: an app may use supported telephony APIs to get certain mobile network information, subject to permission and privacy restrictions.

3.7 Difference Between Android Architecture and Android Framework

These two terms are related, but they do not mean the same thing.

Part 3: Android Application Development

3.8 What is Android Application Development?

Definition: Android Application Development is the process of designing, coding, testing, and deploying applications that run on devices powered by the Android operating system.

In simple words, it means creating mobile applications for Android smartphones and tablets.

Calculator applicationsBanking applicationsShopping applicationsEducational applicationsSocial media applications

3.9 Programming Languages Used for Android Development

1. Kotlin

A modern programming language officially recommended by Google for Android development. It works with Java and helps developers write concise and safer code.

2. Java

An object-oriented language widely used for Android development. Many existing Android applications and projects use Java.

3. C and C++

Used for performance-intensive components and native development through the Android NDK.

  • Game engines
  • Audio processing
  • Image processing
  • High-performance libraries

3.10 Tools Required for Android Application Development

1. Android Studio

The official IDE for Android development. It provides tools for:

  • Writing code
  • Designing user interfaces
  • Debugging applications
  • Testing applications
  • Building application packages
2. Android SDK

Provides tools, libraries, APIs, and other resources required to develop Android applications.

3. Android Emulator

Lets developers run and test Android applications on a computer without a physical smartphone.

4. Gradle

A build automation system. It helps:

  • Compile source code
  • Manage dependencies
  • Build application packages
  • Configure different application versions
5. Android Debug Bridge (ADB)

A command-line tool to communicate with Android devices and emulators. It can:

  • Install applications
  • Run shell commands
  • View device logs
  • Debug applications

3.11 Steps Involved in Android Application Development

  1. Requirement Analysis: identify the purpose of the application and the features it should provide. Example: a student attendance application.
  2. UI/UX Design: design the application's screens, buttons, navigation, and layout.
  3. Environment Setup: install Android Studio, SDK, and the required development tools.
  4. Coding: write application code using Kotlin or Java.
  5. Database Integration: connect the application to a database or backend service when required.
  6. Testing and Debugging: test application functionality and correct programming errors.
  7. Building: generate an APK or Android App Bundle (AAB).
  8. Deployment: publish through Google Play or distribute through another supported method.
  9. Maintenance: fix bugs, improve security, and release updates.

3.12 Important Android Application Components

Android applications commonly use four fundamental application components.

1. Activity

Represents a screen with which the user can interact.

Example: a login screen or home screen.

2. Service

A component used for operations that do not require a user interface.

Example: playing music while the user interacts with another application.

Modern Android versions restrict background services, so developers must follow the appropriate background-work rules.

3. Broadcast Receiver

Allows an application to respond to broadcast messages from Android or other applications.

Example: responding to a system broadcast that the device has finished booting.

4. Content Provider

Manages and shares application data through a defined interface.

Example: accessing contacts through the Android Contacts Provider.

3.13 Advantages and 3.14 Disadvantages of Android

Advantages
  1. Open-source platform through AOSP
  2. Large application ecosystem
  3. Supports multiple hardware manufacturers
  4. Flexible customization
  5. Strong development tools
  6. Supports multitasking
  7. Supports many connectivity technologies
  8. Large developer community
Disadvantages
  1. Fragmentation: different manufacturers use different devices and Android versions.
  2. Compatibility Issues: applications may behave differently across devices.
  3. Security Risks: installing applications from untrusted sources can introduce security threats.
  4. Hardware Differences: developers must consider different screen sizes, processors, and device capabilities.
  5. Software Updates: updates may reach devices at different times depending on the manufacturer and model.
