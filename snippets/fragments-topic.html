Fragments in Android

Reusable parts of an Android screen

7.1 Introduction to Fragments

A Fragment is a reusable part of an Android application's user interface (UI). It represents a portion of an Activity's screen and has its own layout and lifecycle.

In simple words, a Fragment is a small section of an application screen that can be added, removed, or replaced without creating a completely new Activity.

Example: imagine a shopping application with one screen containing product categories on the left and product details on the right. Each section can be designed as a separate Fragment.

7.2 What is an Activity?

Before understanding Fragments, you should understand Activities.

An Activity is an Android application component that provides a screen with which users can interact.

For example, a shopping application may have Login, Home, Product and Profile activities. An Activity acts as a container for the user interface. A Fragment can be placed inside an Activity to divide its screen into smaller reusable sections.

Relationship between Activity and Fragment

  • An Activity can contain one Fragment.
  • An Activity can contain multiple Fragments.
  • A Fragment cannot exist independently; it must be hosted by an Activity.
  • Multiple Activities can reuse the same Fragment.
Example: in a student management application, the main Activity can contain three Fragments: Student Information, Attendance and Result. When a user selects Attendance, the application can replace the Student Information Fragment with the Attendance Fragment while keeping the same Activity.

7.3 Why Do We Use Fragments?

Fragments make Android applications more organized, flexible, and reusable.

1. Reusability

A Fragment can be used in different Activities. For example, a Profile Fragment can be used in both a Home Activity and a Settings Activity.

2. Flexible User Interface

Fragments divide one screen into multiple sections. A phone may display one section at a time, while a tablet may display two or more together.

3. Better Code Organization

Instead of one large Activity, divide the application into smaller components: Login Fragment (login UI), Profile Fragment (profile UI), Settings Fragment (settings UI).

4. Dynamic Screen Changes

Fragments can be added, removed, and replaced while an Activity is running. For example, clicking the Profile button can display the Profile Fragment without opening another Activity.

5. Support for Different Screen Sizes

Fragments help developers create flexible layouts for mobile phones and tablets.

7.4 Lifecycle of a Fragment

A Fragment has its own lifecycle. The Fragment lifecycle describes the stages a Fragment passes through from creation to destruction. Understanding it is important because developers need to know when to create the interface, initialize components, save data, and release resources.

Important Fragment lifecycle methods

1. onAttach()

Called when the Fragment becomes attached to its hosting Activity. It establishes the connection between the Fragment and the Activity.

2. onCreate()

Called when the Fragment is being created. Generally used to initialize data and other non-UI components.

3. onCreateView()

Responsible for creating the Fragment's user interface. For example, it loads an XML layout file containing buttons, text fields, and images.

4. onViewCreated()

Called after the Fragment's view has been created. Used to initialize UI components and set click listeners.

5. onStart()

The Fragment becomes visible to the user.

6. onResume()

The Fragment becomes active and the user can interact with it.

7. onPause()

The Fragment is losing its active state, for example because another screen is coming in front of it.

8. onStop()

The Fragment is no longer visible to the user.

9. onDestroyView()

The Fragment's view is destroyed, but the Fragment object itself may still exist. The view can be destroyed while the Fragment remains in memory.

10. onDestroy()

The Fragment itself is being destroyed.

11. onDetach()

The Fragment is disconnected from its hosting Activity.

Lifecycle order (simplified) when a Fragment is created and then completely removed:

onCreate()
    ↓

    ↓
onViewCreated()

Important: not every lifecycle callback is necessarily called in every situation. For example, a Fragment's view can be destroyed while the Fragment itself is retained.

7.5 Types of Fragments

Fragments are not limited to one specific type. Developers can create different Fragments according to the application's requirements.

1. Static Fragment

Declared directly inside an Activity's XML layout. Suitable when a Fragment should remain in a fixed position and does not need to be dynamically replaced.

2. Dynamic Fragment

Added, removed, or replaced programmatically while the application is running. Useful when the interface needs to change according to user actions.

Example: clicking the Settings button replaces the Home Fragment with the Settings Fragment.

3. Dialog Fragment

A DialogFragment is designed to display a dialog window.

  • Confirmation dialog
  • Delete warning
  • Date picker
  • Information message
4. List Fragment

A ListFragment is an older Android framework class designed to display a list of items. Modern applications commonly use a regular Fragment with a RecyclerView instead.

7.6 How to Create a Fragment in Android

Suppose we are developing a student application and want to display student information inside a Fragment. We will use Java and XML.

Step 1: Create an XML layout

Create a file named fragment_student.xml. This file defines the Fragment's user interface.

<?xml version="1.0" encoding="utf-8"?>

<LinearLayout
    xmlns:android="http://schemas.android.com/apk/res/android"
    android:layout_width="match_parent"
    android:layout_height="match_parent"
    android:orientation="vertical"
    android:padding="20dp">

    <TextView
        android:id="@+id/studentName"
        android:layout_width="wrap_content"
        android:layout_height="wrap_content"
        android:text="Muhammad"
        android:textSize="24sp" />

    <TextView
        android:layout_width="wrap_content"
        android:layout_height="wrap_content"
        android:text="BS Information Technology"
        android:textSize="18sp" />

</LinearLayout>

Understanding the code:

  • LinearLayout: organizes UI elements vertically.
  • TextView: displays text.
  • layout_width: defines the width of an element.
  • layout_height: defines the height of an element.
  • orientation: determines the direction of elements.
  • textSize: controls the text size.
Step 2: Create the Fragment Java class

Create a Java class named StudentFragment.java.

import android.os.Bundle;
import android.view.LayoutInflater;
import android.view.View;
import android.view.ViewGroup;

import androidx.annotation.NonNull;
import androidx.annotation.Nullable;
import androidx.fragment.app.Fragment;

public class StudentFragment extends Fragment {

    public StudentFragment() {
        // Required empty public constructor
    }

    @Nullable
    @Override
    public View onCreateView(
            @NonNull LayoutInflater inflater,
            @Nullable ViewGroup container,
            @Nullable Bundle savedInstanceState) {

        return inflater.inflate(
            R.layout.fragment_student,
            container,
            false
        );
    }
}

Understanding the important parts:

  • StudentFragment: defines our Fragment class.
  • extends Fragment: makes this class an Android Fragment.
  • onCreateView(): creates the Fragment's interface.
  • LayoutInflater: converts the XML layout into actual View objects.
  • R.layout.fragment_student: identifies the XML layout.
  • container: the parent ViewGroup where the Fragment's view will be placed.
  • false: prevents the layout from being attached to the container immediately. The FragmentManager handles attachment.
Step 3: Add a Fragment container to the Activity

Open your Activity's XML layout and add a FragmentContainerView.

<androidx.fragment.app.FragmentContainerView
    xmlns:android="http://schemas.android.com/apk/res/android"
    android:id="@+id/fragmentContainer"
    android:layout_width="match_parent"
    android:layout_height="match_parent" />

This container provides an area where Fragments can be displayed.

Step 4: Add the Fragment to the Activity

Inside MainActivity.java, use FragmentManager to display the Fragment.

import android.os.Bundle;

import androidx.appcompat.app.AppCompatActivity;
import androidx.fragment.app.Fragment;

public class MainActivity extends AppCompatActivity {

    @Override
    protected void onCreate(Bundle savedInstanceState) {
        super.onCreate(savedInstanceState);

        setContentView(R.layout.activity_main);

        if (savedInstanceState == null) {

            getSupportFragmentManager()
                .beginTransaction()
                .replace(
                    R.id.fragmentContainer,
                    new StudentFragment()
                )
                .commit();
        }
    }
}

Understanding the process:

  1. getSupportFragmentManager() gets the FragmentManager.
  2. beginTransaction() starts a Fragment transaction.
  3. replace() places the StudentFragment inside the container.
  4. commit() applies the transaction.

The savedInstanceState == null condition prevents unnecessarily adding the same initial Fragment again after an Activity recreation.

Result: the Activity will display the Student Fragment containing the student's name and degree.

7.7 Fragment Transactions

A Fragment Transaction is a process used to perform changes to Fragments inside an Activity. Developers use FragmentManager to manage these transactions.

Important transaction methods

MethodPurpose
add()Adds a Fragment
replace()Replaces an existing Fragment
remove()Removes a Fragment
hide()Hides a Fragment's view
show()Shows a hidden Fragment
addToBackStack()Allows a transaction to be reversed using Back navigation
commit()Submits the transaction

Example: replacing Home Fragment with Profile Fragment

getSupportFragmentManager()
    .beginTransaction()
    .replace(R.id.fragmentContainer, new ProfileFragment())
    .addToBackStack(null)
    .commit();

Here, addToBackStack(null) allows the user to return to the previous Fragment using the Back button.

7.9 Advantages and 7.10 Disadvantages of Fragments

Advantages
  1. Reusability: the same Fragment can be used in different Activities.
  2. Flexibility: change screen content dynamically.
  3. Better Organization: application code becomes easier to manage.
  4. Multiple Screen Support: helps create interfaces for phones and tablets.
  5. Independent Lifecycle: lifecycle callbacks for managing its operations.
  6. Easy Navigation: Fragments can be replaced to move between sections.
Disadvantages
  1. Complex Lifecycle: managing Fragment and view lifecycles can be difficult for beginners.
  2. Communication Challenges: sharing data between Activities and Fragments requires proper communication methods.
  3. Management Complexity: multiple Fragments can make navigation and back-stack management complicated.
  4. Debugging Difficulty: lifecycle-related errors can be difficult to identify.

7.11 Real-Life Example

Consider a student management application containing a Home Fragment, Profile Fragment, Attendance Fragment and Result Fragment.

When the user clicks the Attendance button:

  1. The application receives the click event.
  2. The current Fragment is replaced with the Attendance Fragment.
  3. The Attendance Fragment displays attendance records.
  4. The Activity remains the host of the Fragment.

This is how Fragments help organize an application into reusable sections.
